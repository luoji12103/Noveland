# Branch Policy

## Use `feat/*` for
- new feature slices
- new plugin implementations
- new runtime capabilities

## Use `fix/*` for
- defects
- regressions
- permission or isolation bugs

## Use `docs/*` for
- docs-only changes
- governance updates
- prompt updates

## Use `refactor/*` for
- non-feature restructuring with behavior parity intent

## Forbidden

- long-lived `dev`
- permanent `experimental`
- months-long branch drift
- using a branch as an alternate product line
