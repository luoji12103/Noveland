# v0.4.1 Admin UX Foundation Plan

## Goal

Implement the v0.4 Operator/Admin UX foundation without changing backend behavior. This phase creates shared Web admin patterns for route guards, status states, action feedback, table/detail/action surfaces, and same-origin API client conventions that later v0.4 consoles can reuse.

## Source Of Truth

- OpenSpec change: `openspec/changes/v0-4-operator-admin-ux`
- Capability spec: `openspec/changes/v0-4-operator-admin-ux/specs/admin-ux-foundation/spec.md`
- Phase plan: `openspec/changes/v0-4-operator-admin-ux/phase-plan.md`
- Product context: `PRODUCT.md`

## Scope

- Add a small shared admin UI foundation under `web/features/admin/`.
- Add route guard helpers for server admin pages that keep existing auth behavior.
- Add shared loading, error, empty, notice, table, detail, and action patterns.
- Add admin API client helpers that wrap existing fetch/client conventions without changing backend API behavior.
- Add focused component/helper tests.
- Update OpenSpec task progress and harness docs after implementation.

## Non-goals

- No provider, media, visual, speech, invocation, or diagnostic business console implementation.
- No backend route, schema, migration, or service behavior changes.
- No new public reader/player UI.
- No new provider capability, daemon automation, streaming, or media delivery behavior.

## Guardrails

- Do not expose resolved secrets, storage URIs, filesystem paths, bytes, base64, raw prompts, or raw outputs.
- Do not bypass backend ACLs or validation.
- Do not introduce a parallel admin app or duplicate API layer.
- Do not modify `worlds.py`.
- Preserve existing Next app routes and same-origin proxy patterns.

## Implementation Notes

- Keep the visual direction restrained, dense, and operator-grade.
- Use existing CSS vocabulary and extend it conservatively.
- Shared components must cover default, empty, error, loading, disabled, and action feedback states.
- Prefer semantic HTML tables/details/forms over invented controls.
- Keep Web client helpers small and testable.

## Targeted Validation
