# v0.6.6 Continuity Review v2 Plan

## Goal

Implement an API-first Continuity Review v2 path that checks candidate narrative text or existing narrative artifacts for causality, secret leakage, timeline conflicts, route context gaps, and relationship jumps while preserving worldline and admin-only evidence boundaries.

## Scope

- Add an admin-only narrative quality continuity review API.
- Reuse `LivingWorldGuardrailService.review_narrative_continuity`.
- Reuse existing `NarrativeContinuityReview` records.
- Reuse worldline context, world bible, story hooks, route affinity, relationship edges, and secret visibility checks.
- Return deterministic findings, conflict reports, and repair suggestions.
- Persist the review through the existing guardrail service.
- Keep API responses sanitized.

## Non-goals

- No migration.
- No automatic repair apply.
- No provider calls.
- No Web dashboard or UI.
- No broad `worlds.py` routes.
- No publication gate semantic changes.
- No raw prompt, raw output, storage URI, filesystem path, bytes, base64, or resolved secret exposure.
- No world event writes.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/continuity/review`

Request fields:

- `worldline_id`
- optional `artifact_id`
- `source_kind`
- optional `source_ref`
- optional `reviewed_text`
- optional `metadata`
- optional `context_limit`

Behavior:

- If `artifact_id` is provided and `reviewed_text` is omitted, review the artifact content.
- If both are provided, review `reviewed_text` but validate the artifact belongs to the same world and worldline.
- Require same worldline for v2 artifacts with first-class `worldline_id`.
- Legacy metadata-only artifact worldlines may be accepted only as compatibility evidence, not v2 authority.
- Reject requests containing sensitive keys in metadata.

Response fields:

- `world_id`
- `worldline_id`
- `review_id`
- `artifact_id`
- `source_kind`
- `source_ref`
- `review_status`
- `findings`
- `conflict_reports`
- `repair_suggestions`
- `evidence_refs`
- `diagnostics`

## Diagnostic Rules

- Hidden secret leak from `LivingWorldGuardrailService` becomes an error finding.
- OOC markers, knowledge leak risk, time contradiction risk, and forbidden world-bible changes become findings.
- Unresolved hooks and available canon context remain explainable info findings.
- Relationship jumps are flagged when metadata claims large affection/trust/intimacy/hostility deltas.
- Route conflicts are flagged when reviewed text references a route while no active route state exists in context.
- Repair suggestions are advisory only and do not mutate canonical state.

## Tests

- Review artifact content and persist a review.
- Review explicit text without artifact.
- Detect hidden secret leak.
- Detect time contradiction and knowledge leak risk.
- Detect relationship jump from metadata deltas.
- Detect route reference without active route context.
- Reject cross-worldline artifact.
- Reject sensitive metadata keys.
- API requires world admin ACL and CSRF.
- No raw prompt, raw output, storage URI, filesystem path, bytes, base64, or secrets in response.
- No `world_events` are written.
