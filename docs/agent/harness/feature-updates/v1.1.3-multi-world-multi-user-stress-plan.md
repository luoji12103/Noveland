# v1.1.3 Multi-world / Multi-user Stress Test Plan

Date: 2026-05-21
Branch: `feature/v1.1-3-multi-world-multi-user-stress`
OpenSpec change: `v1-1-normal-use-release-candidate`

## Decision

Phase 3 will add a deterministic, backend-only normal-use stress evidence service under the existing observability boundary. It will not add migrations, Web UI, API routes, provider execution, broad `worlds.py` routes, or a duplicate readiness framework.

## Baseline

- 3 worlds.
- 2 worldlines per world.
- 2 player sessions per world.
- At least 2 fake provider profiles.
- Deterministic 120-turn equivalent coverage by default.
- Fake or mocked provider evidence only in the default local gate.

## Ownership

- Package: `backend/packages/observability/`
- Service ownership: normal-use stress report aggregation over existing world, session, provider, quota, media, memory, feedback, authoring, invocation, and long-run eval records.
- Tests: focused in-memory backend fixture that seeds the accepted baseline with fake providers only.

## Real-provider Profile

Real-provider stress is not enabled by Phase 3. The report will explicitly state that real-provider execution is disabled by default and that any future real-provider stress profile must be opt-in, quota-guarded, and outside the default gate.

## Safe Report Contract

The report may include aggregate counts, latency/cost/failure/quota summaries, and safe evidence references. It must not include storage locations, filesystem paths, object storage paths, credentials, resolved secrets, invite tokens, prompt bodies, provider outputs, bytes, base64, or prompt snapshot internals.

## Tests

- Baseline stress fixture passes with fake providers.
- Cross-world/worldline leakage is detected as a blocker.
- Missing quota policy blocks stress readiness.
- Player sessions remain isolated by world/worldline/player actor.
- Report text does not expose forbidden markers.

## Stop Conditions

- Default stress requires real provider calls or external quota.
- Stress evidence cannot detect world/worldline leakage.
- The fixture needs proprietary or user-provided galgame assets.
- Stress reporting needs unsafe raw payloads or storage locations.
