# v0.3.1.12 Multimodal Evaluation And Diagnostics Phase 12 Plan

Phase 12 adds backend-only quality, cost, safety, and regression diagnostics for the multimodal provider/media/visual/speech pipeline. It must reuse the existing eval/release framework and must not create a parallel release system.

## Scope

- Backend/API only.
- No Web UI, public launch gate changes, provider marketplace, streaming, or automatic memory write from STT.
- Initial implementation should avoid schema migration by storing multimodal eval runs in existing `long_run_eval_runs` with `eval_key="multimodal-smoke"`.
- Diagnostics should be repeatable, deterministic, and safe to run against local/sample worlds.
- API responses must not expose storage URIs, file paths, binary bytes, base64 payloads, raw prompts, or raw outputs.

## Reuse Requirements

Reuse existing records and services:

- `model_invocations`, `prompt_snapshots`
- `provider_integrations`, `provider_capabilities`, `provider_health_checks`
- `media_assets`, `media_objects`, `media_jobs`, `media_references`
- `character_sprite_sets`, `character_sprite_variants`, `scene_background_profiles`
- `conversation_turn_presentations`
- `voice_profiles`, `agent_voice_profile_bindings`, `speech_transcripts`
- `asset_generation_policies`, `asset_generation_runs`, `asset_generation_proposals`
- `long_run_eval_runs`, `beta_checklist_runs`, `living_world_release_profiles`

Do not add `multimodal_eval_runs` unless `long_run_eval_runs` proves insufficient during implementation.

## Package And API

Add a focused multimodal eval package, for example:

- `backend/packages/multimodal_eval/src/noveland/multimodal_eval/contracts.py`
- `backend/packages/multimodal_eval/src/noveland/multimodal_eval/service.py`

Add an independent router and include it from `app.py`:

- `backend/services/api/src/noveland/services/api/multimodal_evals.py`

Routes:

- `GET /worlds/{world_id}/multimodal-evals`
- `POST /worlds/{world_id}/multimodal-evals/run`
- `GET /worlds/{world_id}/multimodal-evals/{run_id}`
- `GET /worlds/{world_id}/diagnostics/multimodal`

## Eval Checks

The `multimodal-smoke` eval should check:

- provider secret boundary and safe auth-ref usage
- provider health/smoke availability summaries
- model invocation ledger completeness for provider-created media jobs/assets
- prompt snapshot redaction and absence of secret-like fields
- media job success/failure counts and succeeded-job output asset linkage
- media object presence and checksum/storage existence health
- missing media object records
- sprite default/neutral variant availability
- scene background availability
- agent default voice binding availability
- TTS media linked to a model invocation when provider-generated
- STT transcripts do not correspond to automatic memory write jobs
- no storage URI, file path, base64, bytes, raw prompt, or raw output leaks in `world_events.payload`
- cost/latency aggregation from `model_invocations`
- sample-world multimodal smoke state can pass with one worldline, agents, media assets, sprite/background, voice binding, TTS asset, transcript, and presentation

## Result Shape

Return a safe diagnostics/eval result with:

- `status`: `passed | warning | failed`
- `metrics_json`: aggregate counts and latency/cost summaries
- `blockers`: actionable blocking findings
- `warnings`: non-blocking findings
- `recommendations`: follow-up actions
- `evidence_refs`: IDs and table names only, never storage URIs or raw prompt/output

Persist eval runs as `LongRunEvalRun`:

- `eval_key="multimodal-smoke"`
- `horizon_days=1`
- `status` mapped from result status
- `metrics`, `blockers`, `recommendations`, and safe metadata/evidence refs populated from diagnostics

## Tests

Targeted tests:

- detect missing media object
- detect missing checksum/storage object
- detect missing default sprite
- detect missing voice binding
- detect leaked `storage_uri` in world event payload fixture
- detect raw prompt leak in world event payload fixture
- pass sample world multimodal smoke scenario
- aggregate model invocation cost/latency
- aggregate media job statuses
- verify STT transcript does not imply memory auto-write
- permission checks
- no duplicate release framework and no migration initially
