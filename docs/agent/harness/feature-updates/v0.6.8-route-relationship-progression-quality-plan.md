# v0.6.8 Route & Relationship Progression Quality Plan

## Goal

Implement an API-first, admin-only diagnostic for route progression and relationship state quality. The review should explain whether existing route affinities, milestones, endings, player choices, GM proposals, world events, and relationship edges form a coherent progression without replacing any existing route or relationship semantics.

## Scope

- Add a read-only narrative quality progression review API.
- Reuse existing `AgentRelationshipEdge` records for affection/trust/hostility/intimacy/obligation/rivalry/debt state.
- Reuse `RouteAffinity`, `RouteMilestone`, `EndingCandidate`, `PlayerChoiceRecord`, `GMEventProposal`, `PlotThread`, and `world_events`.
- Produce deterministic summaries, findings, evidence refs, and review-only recommendations.
- Detect route/relationship drift, missing route scaffolding, blocked or stale routes, route stage/milestone mismatch, ending requirement pressure, relationship contradiction, and unresolved high-risk proposals.
- Keep output dashboard-ready but backend/API-only.
- No migration expected.

## Non-goals

- No replacement of relationship model semantics.
- No automatic relationship, route, milestone, ending, choice, proposal, event, or plot-thread mutation.
- No provider calls.
- No new canonical route/relationship tables.
- No Web dashboard or UI.
- No broad `worlds.py` routes.
- No runtime daemon hook or blocker integration.
- No raw prompt, raw output, storage URI, filesystem path, bytes, base64, or resolved secret exposure.
- No world event writes.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/progression/review`

Request fields:

- `worldline_id`
- optional `agent_id`
- optional `route_affinity_id`
- `include_relationships` default true
- `include_routes` default true
- `include_events` default true
- `include_proposals` default true
- `recent_event_limit` default 20, bounded 0-100

Response fields:

- `world_id`
- `worldline_id`
- optional `agent_id`
- optional `route_affinity_id`
- `progression_status`
- `relationship_summary`
- `route_summary`
- `event_summary`
- `proposal_summary`
- `findings`
- `recommendations`
- `evidence_refs`
- `diagnostics`

## Diagnostic Rules

- Relationship review flags contradictory high affection/trust with high hostility/rivalry unless metadata explicitly justifies tension.
- Relationship review flags one-way relationship edges without reciprocal context as informational, not a hard failure.
- Relationship review flags abrupt relationship deltas only when detectable from recent safe event payload metadata.
- Route review flags active routes with no milestones, blocked routes with no blocking reason, milestones ahead of route stage, completed routes with incomplete milestones, and endings whose requirements are not satisfiable from current route state.
- Route review flags route-affinity records that reference missing/cross-worldline choices through safe evidence refs.
- Proposal review flags unresolved accepted/proposed high-risk relationship or route GM proposals as review pressure.
- Event review summarizes recent safe event counts and only inspects sanitized payload keys needed for relationship/route evidence.
- Findings should be warning/error only for actionable consistency problems; sparse world setup is informational when no active routes or relationships exist.

## Reuse Boundaries

- Use the `narrative_quality` package/router for API and service code.
- Read existing worldline-scoped records directly; do not create a parallel progression model.
- Reuse existing evidence ref DTOs and sanitization helpers.
- Preserve existing route, ending, milestone, player-choice, GM proposal, and relationship write paths.
- Preserve Phase 13 guardrails for secrets, media paths, raw prompts/outputs, and worldline isolation.

## Tests

- Review returns pass/warning with route, relationship, event, and proposal summaries.
- Contradictory relationship metrics produce a finding.
- Active route with no milestones produces a route scaffolding finding.
- Milestone stage ahead of route stage produces a stage mismatch finding.
- Ending requirements blocked by route state produce an ending requirement finding.
- High-risk unresolved route/relationship GM proposals produce review pressure findings.
- Cross-worldline route or agent request is rejected.
- API requires world admin ACL and CSRF.
- Review performs no provider call, canonical mutation, or world event write.
- Response contains no raw prompt, raw output, storage URI, filesystem path, bytes, base64, or secrets.
