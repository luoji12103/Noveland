# v0.7.7 Security Regression Suite Plan

## Goal

Consolidate high-risk security regression coverage for the hardened v0.4-v0.7 API surface without adding new product behavior.

This phase is test/docs focused. It should make secret, prompt/output, storage/path, ACL, and worldline-isolation regressions easier to catch before v0.7 readiness aggregation.

## Scope

- Add a focused regression suite for forbidden payload content:
  - resolved secrets
  - authorization headers
  - raw prompts and raw outputs
  - storage URIs
  - filesystem paths
  - bytes/base64 payload markers
- Reuse and extend existing regression fixtures where useful:
  - Phase 13 multimodal sample world
  - v0.5 authoring sample import
  - v0.7 permission matrix tests
  - provider secret and budget tests
  - multimodal eval diagnostics
  - narrative quality diagnostics
  - observability incident summary tests
- Cover lower-privilege denial or safe projection for admin-only surfaces:
  - providers
  - model invocations and prompt snapshots
  - media/admin catalog
  - authoring/import
  - narrative quality
  - multimodal evals
  - observability incident diagnostics
  - future readiness gate placeholder if available
- Add cross-worldline isolation regression checks for:
  - media/visual bindings
  - conversation presentations
  - authoring proposals/assets
  - narrative quality diagnostics
  - multimodal evals
- Add shared test helpers only if they reduce duplication. Do not create a new security framework.

## Non-goals

- No new runtime behavior unless a regression exposes a narrow bug that can be fixed safely.
- No migrations.
- No Web UI.
- No SAST/DAST platform rollout.
- No external penetration testing workflow.
- No public bug bounty process.
- No broad `worlds.py` route refactor.
- No real secrets, raw media bytes, or raw source bodies in fixtures.

## Architecture Decision

Keep Phase 7 as a backend test-and-fixture hardening phase.

If implementation needs reusable helpers, place them under `backend/tests/fixtures/` or `backend/tests/helpers/`. Do not add a production package/router for this phase. Production readiness aggregation belongs to Phase 8.

## Expected Migration

No migration is expected.

Stop if the suite requires schema changes, new persisted evidence tables, or historical backfill.

## Guardrails

- Do not store real secrets in test fixtures.
- Do not write raw prompt/output, storage URI, filesystem path, bytes, or base64 into `world_events.payload`.
- Do not expose admin-only evidence through member, reader, player, or unauthenticated routes.
- Do not mutate canonical world state from regression checks unless the existing API under test already does so.
- Do not loosen existing ACLs to make tests pass.

## Stop Conditions

- A failing regression requires broad route refactors before the specific leak or isolation issue is understood.
- Test fixtures need real secrets, raw prompt bodies, raw media bytes, raw source bodies, or local filesystem paths.
- A fix would add product runtime behavior, a new router, a new migration, Web UI, public reader delivery, streaming, or daemon execution.
- Targeted tests or full local gate fail.
