# v0.3.1.8 Real Provider Smoke Validation Phase 8 Plan

## Summary

Phase 8 hardens the Provider Execution Kernel for real provider configuration and smoke validation without adding new product-facing media features. The central decision is that `provider_integrations.auth_ref` is an opaque secret reference, never a secret value. Real provider calls resolve secrets in memory at execution time, write safe invocation/media records, and never persist resolved secrets in provider config, model invocations, prompt snapshots, media jobs, health checks, logs, diagnostics, or API responses.

No schema migration is planned for Phase 8.

## Scope

- Add provider secret reference resolution for env-backed keys and simple aliases.
- Reject sensitive keys recursively in provider `config_json`, `default_params_json`, health metadata, and smoke-test payloads.
- Sanitize provider config, health metadata, request snapshots, and API responses.
- Extend provider health checks and add provider smoke-test APIs.
- Keep live provider tests skipped unless explicitly enabled by environment.
- Do not add a vault, encrypted DB secret storage, provider marketplace, Web UI, streaming, fallback routing, or load balancing.

## Secret Boundary

- `auth_ref` is a reference string such as `env:OPENAI_API_KEY`, `env:MIMO_API_KEY`, `env:COMFYUI_API_KEY`, `env:OMNIVOICE_API_KEY`, or `env:GPT_SOVITS_API_KEY`.
- First-version aliases may map `openai:default` to `env:OPENAI_API_KEY` and `mimo:default` to `env:MIMO_API_KEY`.
- Resolved secrets are passed to adapters only in memory.
- `ProviderIntegrationRead` may expose `auth_ref` as the reference string on admin-scoped APIs, but never exposes the resolved secret.
- Secret-like keys are rejected recursively: `api_key`, `apikey`, `token`, `bearer_token`, `authorization`, `secret`, `client_secret`, `access_key`, `password`, and `private_key`.

## API Changes

- Add `GET /worlds/{world_id}/providers/{provider_id}/health-checks`.
- Add `POST /worlds/{world_id}/providers/{provider_id}/smoke-test`.
- Existing provider CRUD remains admin-scoped.
- Existing `/worlds/{world_id}/providers/test-invocation` remains available but must use the same secret sanitization and resolution boundary.

## Service Changes

- Add `ProviderSecretResolver` under `noveland.providers`.
- Extend provider registry validation to reject sensitive provider config/default params before persistence.
- Extend `ProviderHealthService` to record safe status metadata for fake, auth missing, auth resolved, auth failed, timeout, malformed response, provider unreachable, and capability mismatch.
- Extend `ProviderExecutionService` so all ledger request/snapshot payloads are sanitized and record only safe auth booleans.
- Update provider adapters so `config_json.api_key` is no longer accepted; adapters receive a resolved in-memory secret from the execution service.

## Tests

- Provider create with `auth_ref=env:OPENAI_API_KEY` succeeds.
- Provider create/update rejects `config_json.api_key`, nested `token`, and `default_params_json.authorization`.
- `ProviderIntegrationRead` never returns resolved secret values.
- Smoke test resolves env secret at execution time.
- Missing env secret records safe `auth_missing` metadata and a failed invocation without a stack trace.
- Failed auth records safe metadata only.
- Model invocations and prompt snapshots do not contain resolved API keys or Authorization values.
- Provider health metadata does not contain secret values.
- Recursive sanitizer catches nested sensitive fields.
- Fake provider continues to work without `auth_ref`.
- Mocked smoke tests cover OpenAI image, OpenAI TTS/STT, ComfyUI, MiMo, OmniVoice, and GPT-SoVITS paths.
- Live tests remain skipped unless `NOVELAND_LIVE_PROVIDER_TESTS=1`.

## Deferred

- Full vault/KMS support.
- Encrypted provider secret storage.
- Provider marketplace or user-managed secret UI.
- Web provider configuration UI.
- Streaming provider execution.
- Retry, fallback, and load balancing.
