# v0.9.1 MVP Provider Settings & Model Lab Plan

Date: 2026-05-16
Branch: `feat/v0.9-provider-settings-model-lab`

## Goal

Implement v0.9 Phase 1 only: productize provider setup and model lab workflows over the existing provider integration boundary so an operator can create configurable LLM, image, TTS, and ASR providers, discover models safely, manually enter model names, and run explicit smoke checks without exposing secrets or triggering default external spend.

## Accepted Decisions

- Provider templates are static/code-owned manifests over the existing provider registry.
- No persistent provider-template tables are added in Phase 1.
- Model discovery is server-side, best-effort, redacted, and optional.
- Discovery supports custom `base_url`, `auth_ref` resolved only server-side, adapter/provider-kind strategy, safe error shape, manual `model_name` fallback, and optional configured list endpoint.
- Text adapter alignment is part of Phase 1. Implement ledger-backed OpenAI-compatible and Anthropic-compatible text execution through `ProviderExecutionService`; do not use legacy `ProviderProfileService` for new v0.9 provider-backed flows.
- Real provider tests are not part of the default gate. Any live provider smoke/model-list checks must be opt-in through explicit env such as `NOVELAND_RUN_REAL_PROVIDER_TESTS=1`.
- API keys remain `auth_ref`/secret-only and must not appear in browser responses, logs, prompt snapshots, `world_events.payload`, or reader/player/member APIs.
- `impeccable` was used before Web implementation. Product register is operator-grade product UI; `DESIGN.md` is absent, so keep the UI restrained and aligned with existing admin conventions.

## Scope

- Add static provider templates/presets for:
  - OpenAI-compatible LLM
  - Anthropic-compatible LLM
  - MiMo V2.5 TTS
  - MiMo V2.5 ASR
  - Z-Image image generation
  - GPT Image
  - ComfyUI
  - OpenAI-compatible image
  - generic image/custom HTTP
- Add server-side model discovery service/router action.
- Add manual model-name fallback support in provider settings/model lab UI.
- Add safe smoke/test connection flow improvements.
- Add or align OpenAI-compatible and Anthropic-compatible text adapters.
- Add tests for templates, model list discovery/failure redaction, manual fallback, text adapter routing, ACL, and leak protection.

## Non-Goals

- No Visual Generation Control Plane.
- No ComfyUI workflow template schema, workflow registry, LoRA inventory, checkpoint inventory, or visual generation profile.
- No galgame source intake, script parsing, memory distillation, visual mapping, voice mapping, demo world assembly, or self-use MVP gate.
- No real provider calls in default tests.
- No public/reader/player/member provider routes.
- No broad `worlds.py` growth.
- No hardcoded vendor base URL requirement. Presets may include placeholder/default examples only when override remains explicit.

## UI Plan

- Keep the provider page as a dense operator workspace, not a marketing or game surface.
- Add a template selector that previews provider kind, adapter kind, base URL placeholder, required config/default params, capability keys, and model discovery behavior.
- When a template is selected, populate create fields while preserving manual override.
- Add a model lab panel for the selected provider:
  - current model name source;
  - server-side model discovery action;
  - safe success/failure message;
  - model list selection when available;
  - manual model-name field and smoke-test action.
- Maintain existing JSON fields for advanced config, but make common model fields visible and safer.
- Use textual status labels in addition to color.

## Tests

- Static template list contains all required presets and no forced vendor base URL.
- Template payloads validate with provider kind/adapter compatibility.
- Model discovery succeeds through mocked/fake HTTP responses without exposing auth values.
- Model discovery failure returns safe error code/message and preserves manual fallback.
- OpenAI-compatible and Anthropic-compatible text execution is ledger-backed and redacted.
- Smoke/test responses and prompt snapshots do not contain API keys, authorization headers, storage paths, raw output leaks, bytes, or base64.
- Provider admin UI renders templates, applies a template, runs discovery, selects a model, and supports manual model fallback.

## Stop Conditions

- Model discovery requires exposing credentials to the browser.
- Text generation cannot be represented safely through `ProviderExecutionService`.
- Provider templates require persistent tables before implementation can pass.
- Real provider tests would run in default local/full gates.
- Any new route would expose provider secrets/config to reader/player/member APIs.
- Implementation starts requiring Visual Generation Control Plane data structures.
