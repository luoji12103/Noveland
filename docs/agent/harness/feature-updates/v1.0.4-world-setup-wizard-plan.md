# v1.0.4 World Setup Wizard Plan

Date: 2026-05-20
Branch: feature/v1.0-4-world-setup-wizard
OpenSpec change: `openspec/changes/v1-0-private-beta-mvp/`

## Decision Summary

Phase 4 will implement the private beta world setup wizard as a read-only readiness aggregation
inside the existing observability/readiness boundary. It will not add migrations, persistent setup
signoff tables, a new readiness framework, broad `worlds.py` routes, provider execution, or Web UI.

The setup report answers whether a prepared v0.9 demo world is ready to invite 1-3 private beta
testers by checking access, player session restore, quota controls, provider/model readiness,
persona/memory, visual, voice, media, source traceability, self-use MVP evidence, and world-event
leak checks.

## Ownership

- Package owner: `backend/packages/observability/`
- API owner: existing app-level `backend/services/api/src/noveland/services/api/observability.py`
- Endpoint: `GET /observability/readiness/private-beta-setup`
- Response contract: existing readiness section model with `readiness_kind=private_beta_world_setup`
- Access: platform admin only
- No `worlds.py` route growth

## Evidence Sources

The report reuses existing v0.7-v1.0 evidence:

- `private_beta_invites` for invite redemption and lifecycle evidence
- `world_memberships` and `player_actor_profiles` for least-privilege access/profile bootstrap
- `player_sessions` for server-owned resume evidence
- `provider_budget_policies` for active player/capability quota evidence
- `provider_integrations` and `provider_health_checks` for provider/model readiness
- `conversation_sessions`, `conversation_turns`, and `conversation_turn_presentations` for entry and playback evidence
- `AgentPersona` and `AgentMemoryItem` for persona/memory readiness
- visual, visual generation, speech, media, and authoring records from v0.9 for content completeness
- self-use MVP gate evidence through `ProductionReadinessGateService.self_use_mvp_report()`
- recent `world_events.payload` leak scan using safe forbidden-marker checks

## Report Semantics

The report blocks if any required private beta setup area is missing:

- no viable/redeemed invite evidence
- redeemed testers lack `human_user` membership or active player profile
- no ready player session resume evidence
- quota policies lack player or capability limits
- required providers are missing or unhealthy
- demo entry/playback, persona/memory, visual, voice, media, or traceability evidence is incomplete
- self-use MVP evidence is blocked
- world event payloads contain forbidden path/storage/prompt/secret markers

Returned evidence is limited to safe IDs, record kinds, component names, statuses, reason codes,
world/worldline IDs, and timestamps. It must not expose invite tokens, token hashes, resolved
secrets, storage paths, raw prompts, raw outputs, prompt snapshot internals, binary payloads, raw
source fragments, local model paths, or raw workflow JSON.

## Frontend Scope

No Web UI is required for Phase 4. The implementation is backend/API-only, so `impeccable` is not
required for this phase. A later admin setup checklist UI may consume the safe report.

## Tests

Targeted tests should cover:

- complete beta world setup passes
- missing access/session/quota/provider/persona/memory/visual/voice evidence blocks
- self-use MVP evidence is referenced safely
- platform-admin-only endpoint ACL
- player/member requests are denied
- no forbidden storage/path/base64/bytes/raw prompt/raw output/secret markers in report responses
- setup does not create duplicate readiness framework tables

## Stop Conditions

Stop implementation if:

- setup requires a new readiness framework or persistent setup table
- setup needs raw prompt/output, storage path, provider secret, invite token, prompt snapshot, or
  raw source evidence
- setup cannot validate access, session, and quota evidence through existing Phase 1-3 records
- setup requires broad `worlds.py` routes
- setup requires tester-facing admin diagnostics
- Web UI becomes mandatory but `impeccable` cannot be used
