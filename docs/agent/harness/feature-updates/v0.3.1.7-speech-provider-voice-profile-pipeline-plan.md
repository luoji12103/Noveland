# Phase 7 Speech Provider & Voice Profile Pipeline Plan

## Summary

Phase 7 adds the first speech pipeline on top of Phase 3 invocation ledger, Phase 4 media kernel, Phase 5 provider execution, and Phase 6 media/provider adapter dispatch. The implementation is backend-only and additive: voice profiles, agent voice bindings, speech transcripts, speech style mappings, TTS/STT orchestration, OpenAI speech adapters, Xiaomi MiMo adapter contracts, and configurable OmniVoice/GPT-SoVITS HTTP contracts.

No streaming, local deployment, cloning training, Web recording/player UI, public reader audio route, memory auto-write, or conversation turn text mutation is included.

## Current Source Checks

- OpenAI speech-to-text docs describe `/v1/audio/transcriptions` and `/v1/audio/translations`, with `gpt-4o-transcribe`, `gpt-4o-mini-transcribe`, `gpt-4o-transcribe-diarize`, and `whisper-1` support. File inputs include common audio formats such as mp3, m4a, wav, and webm.
- OpenAI text-to-speech docs describe `/v1/audio/speech`, current `gpt-4o-mini-tts` guidance, built-in voices, `instructions`, and output formats. Streaming exists but is out of scope for Phase 7.
- Xiaomi MiMo public pages identify MiMo-V2.5-TTS-Series as voice synthesis models with speed, emotion, tone, voice design, and voice cloning capabilities. API docs were not reliably machine-readable during planning, so Phase 7 will implement MiMo adapters as configurable HTTP mappers with mocked tests, not fixed undocumented endpoint assumptions.
- Xiaomi MiMo-V2.5-ASR is treated as ASR/STT, not TTS.

## Data Model

### voice_profiles

World-scoped voice identity/profile records. `worldline_id` is nullable so profiles can be world-level defaults or fork-specific overrides.

Required fields: `id`, `world_id`, `worldline_id`, `profile_key`, `display_name`, `description`, `status`, `visibility`, `owner_kind`, `owner_agent_id`, `provider_integration_id`, `provider_voice_id`, `default_language`, `supported_languages_json`, `voice_kind`, `reference_asset_id`, `consent_status`, `usage_policy_json`, `metadata_json`, `created_at`, `updated_at`.

### agent_voice_profile_bindings

Many-to-many agent/profile bindings. Service layer enforces at most one default binding per agent/worldline.

Required fields: `id`, `world_id`, `worldline_id`, `agent_id`, `voice_profile_id`, `binding_role`, `priority`, `is_default`, `style_overrides_json`, `created_at`, `updated_at`.

### speech_transcripts

STT outputs tied to source media and optional conversation turn.

Required fields: `id`, `world_id`, `worldline_id`, `source_asset_id`, `media_job_id`, `model_invocation_id`, `conversation_id`, `turn_id`, `speaker_actor_ref`, `language`, `transcript_text`, `segments_json`, `confidence_json`, `status`, `visibility`, `created_at`, `updated_at`.

### speech_style_mappings

World-scoped emotion/style mappings for provider-specific speech style controls.

Required fields: `id`, `world_id`, `mapping_key`, `provider_kind`, `emotion_key`, `style_json`, `created_at`, `updated_at`.

## Service Behavior

### TTS

1. Resolve worldline.
2. Resolve provider and check `supports_tts`.
3. Resolve voice profile by explicit `voice_profile_id`, agent default binding, or explicit provider default allowance.
4. Validate reference voice asset world/worldline when present.
5. Resolve emotion/style mapping and deterministic fallback.
6. Create or reuse media job.
7. Execute through provider execution service so model invocation and prompt snapshot are written.
8. Store output audio as media asset/object via Media Kernel.
9. Link media asset source invocation and job result.
10. Attach audio to conversation turn with media reference when requested.
11. Never write bytes, paths, storage URIs, raw prompt, raw text, or raw output into world events.

### STT

1. Validate source audio asset/object worldline.
2. Resolve provider and check `supports_stt`.
3. Create media job.
4. Execute through provider execution service so model invocation and prompt snapshot are written.
5. Store transcript in `speech_transcripts`.
6. Optionally attach transcript metadata to turn by reference; do not mutate `conversation_turns.input_text` or `output_text`.
7. Do not enqueue memory writes.

## Provider Adapter Boundaries

- OpenAI speech adapters implement request mapping for `/audio/speech` and `/audio/transcriptions`, with mocked HTTP tests.
- MiMo TTS/ASR adapters expose canonical configurable HTTP request mappings with style/emotion/audio tag fields. No local Xiaomi MiMo deployment is included.
- OmniVoice and GPT-SoVITS adapters are configurable HTTP contracts only. No local model imports, process management, training, or server lifecycle management.
- Fake provider remains available for service/API tests.
