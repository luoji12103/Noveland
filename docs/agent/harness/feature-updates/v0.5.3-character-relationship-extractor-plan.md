# v0.5.3 Character & Relationship Extractor Plan

## Goal

Extract character, alias, faction, identity, relationship, and emotional-baseline candidates from authoring source fragments into reviewable Phase 1 authoring proposals.

## Scope

- Add deterministic extractor contracts and service logic inside `backend/packages/authoring/`.
- Add authoring API route(s) under `backend/services/api/src/noveland/services/api/authoring.py`.
- Read existing `authoring_source_fragments.excerpt_text` and existing Phase 2 dialogue proposals; do not accept or persist full raw source bodies in Phase 3.
- Create Phase 1 `authoring_import_proposals` linked to source fragments and import runs.
- Represent character candidates, aliases, speaker names, faction hints, identity tags, relationship edges, relationship labels, emotional baselines, confidence, and evidence in safe proposal JSON.
- Keep all generated records worldline-scoped and traceable to source fragments.

## Non-goals

- No migration unless implementation proves the Phase 1 schema cannot carry extractor output.
- No Web UI.
- No provider-backed extraction in Phase 3.
- No invocation ledger changes because no provider extraction is used.
- No direct apply to agents, relationship graphs, memories, world bible, narrative state, or visual/voice bindings.
- No raw full source text in API responses, prompt snapshots, or `world_events.payload`.
- No changes to `worlds.py`.

## API Shape

- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/extract-characters`

Request:

- `worldline_id`
- `source_fragment_ids`
- `extractor_mode`: `deterministic`
- `include_dialogue_proposals`: optional boolean, default `true`

Result:

- `run`
- `created_proposal_count`
- `character_count`
- `relationship_count`
- `alias_count`
- `faction_count`
- `identity_count`
- `emotional_baseline_count`

## Extractor Rules

- Character candidates:
  - `character: Name`
  - `name: Name`
  - `alias: Name -> Alias`
  - speaker names from Phase 2 dialogue proposals
- Relationship candidates:
  - `relationship: A -> B: label`
  - `A -> B: label`
  - `A loves B`, `A trusts B`, `A hates B`, `A fears B`, `A protects B`
- Faction and identity candidates:
  - `faction: Name`
  - `identity: Name = value`
  - `role: Name = value`
- Emotional baseline candidates:
  - `emotion: Name = baseline`
  - `baseline: Name = value`
- Unknown lines are skipped rather than guessed.
- Duplicate candidates within the same run should be collapsed deterministically by normalized key when safe.

## Guardrails

- Generated proposals must reuse Phase 1 safe JSON validation.
- Extractor output must not include `storage_uri`, filesystem paths, raw bytes, base64, raw prompts, raw outputs, or full raw source.
- Extractor must not create provider invocations, media jobs, memory writes, world events, conversation turns, agents, relationships, visual bindings, voice bindings, or world bible records.
- Cross-world and cross-worldline source fragments, import runs, and proposals must be rejected.
