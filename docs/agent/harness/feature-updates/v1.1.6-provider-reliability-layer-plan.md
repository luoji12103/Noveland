# v1.1.6 Provider Reliability Layer Plan

Date: 2026-05-21
Branch: `feature/v1.1-6-provider-reliability-layer`
OpenSpec change: `v1-1-normal-use-release-candidate`

## Decision

Phase 6 will extend the existing `providers` package and app-level providers router. It will not add a migration, Web UI, provider marketplace, automatic hidden fallback, duplicate provider execution framework, broad `worlds.py` route growth, or real-provider calls in default tests.

## Ownership

- Health trend and degraded-mode evaluation: `backend/packages/providers/`
- Manual fallback/model switch policy validation: `backend/packages/providers/`
- Provider execution fallback audit metadata: `ProviderExecutionService`
- Manual media-job requeue audit: existing `MediaJobService` plus provider reliability wrapper
- API ownership: `backend/services/api/src/noveland/services/api/providers.py`

## Policy

Provider fallback is manual-first. A fallback/model switch may run only when the caller explicitly selects a fallback provider and the primary provider has opted in through safe provider configuration:

```json
{
  "reliability": {
    "manual_fallback_enabled": true,
    "fallback_provider_ids": ["<uuid>"]
  }
}
```

Fallback validation must check provider ownership, primary degraded evidence, fallback active status, capability compatibility, quota/budget before execution, auth availability without exposing resolved secrets, and safe audit metadata. Automatic fallback remains disabled unless a future checkpoint explicitly approves a stricter policy and evidence model.

## Implementation Scope

- Add provider reliability DTOs and service methods for degraded-mode reports, fallback-plan validation, and media-job requeue audit.
- Add world-admin provider reliability endpoints under the existing provider router.
- Add optional manual fallback fields to provider execution requests and test invocation API paths.
- Record fallback/model-switch evidence in invocation metadata only when fallback is explicitly requested and policy-valid.
- Keep default tests fake-provider only and ensure quota checks happen before provider execution.

## Non-goals

- Real provider reliability tests by default.
- Persisted reliability-policy table.
- Automatic retry or hidden fallback.
- Provider marketplace or provider code forks.
- Web UI changes.

## Tests

- Health trend reports degraded mode from repeated unhealthy checks or failed invocations.
- Fallback is disabled by default.
- Fallback requires opt-in policy.
- Fallback checks capability, quota, auth availability, and audit metadata.
- Manual media-job requeue is audited and does not execute providers.
- No hidden retries or spend.
- No secrets, storage paths, raw prompts, raw outputs, bytes, base64, or prompt snapshot internals leak.

## Stop Conditions

- Fallback would run automatically without explicit request and opt-in policy.
- Fallback can bypass quota or auth checks.
- Provider switch would mutate world state outside provider/media/invocation evidence.
- Retry/requeue would duplicate hidden spend.
