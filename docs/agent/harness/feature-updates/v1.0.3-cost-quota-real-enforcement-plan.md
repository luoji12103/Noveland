# v1.0.3 Cost & Quota Real Enforcement Plan

Date: 2026-05-20
Branch: feature/v1.0-3-cost-quota-enforcement
OpenSpec change: `openspec/changes/v1-0-private-beta-mvp/`

## Decision Summary

Phase 3 will keep quota enforcement inside the existing provider boundary. `ProviderExecutionService`
remains the single spend guard before external adapter execution. The existing
`provider_budget_policies` table is sufficient for the first private beta version because policy
scope can be represented safely in `limits_json` without adding a new quota table.

Implementation will extend provider budget policy semantics rather than add a migration.

## Ownership

- Package owner: `backend/packages/providers/`
- API owner: existing app-level provider router,
  `backend/services/api/src/noveland/services/api/providers.py`
- Enforcement point: `ProviderExecutionService.execute()` before secret resolution and adapter
  execution
- Evidence source: invocation ledger request/response metadata plus provider quota status
- No new package, no `worlds.py` routes, and no duplicate cost framework

## Policy Shape

Existing world/provider limits remain supported:

- `max_daily_invocations`
- `max_daily_estimated_cost`
- `max_daily_media_jobs`
- `emergency_stop_enabled`

Phase 3 adds optional first-version JSON limits:

- `capabilities`: mapping of capability key to per-capability limits
- `players`: mapping of player actor id to per-player limits
- `default_player`: default per-player limits when a `player_actor_id` is supplied

Supported nested keys mirror existing safe limits:

- `max_daily_invocations`
- `max_daily_estimated_cost`
- `max_daily_media_jobs`

The service must sanitize all policy JSON and reject sensitive/leaky fields. Reader/player/member
APIs must not expose policy internals unless a later phase adds an explicitly safe DTO.

## Request Context

`ProviderExecutionRequest` should carry optional:

- `player_actor_id`
- `capability_key`

Provider execution will normalize capability as:

1. explicit `capability_key`
2. provider-kind default capability:
   - text: `text.generate`
   - image generation/editing/composition/analysis: `image.generate` or related image capability
   - text-to-speech: `speech.tts`
   - speech-to-text: `speech.asr`
   - workflow engine: `workflow.execute`

Admin model lab and provider smoke/test calls may omit `player_actor_id`; they remain covered by
world/provider/capability policies.

## Spend Path Coverage

Phase 3 must cover all provider-backed paths that route through `ProviderExecutionService`:

- Provider admin smoke/test invocation
- OpenAI-compatible and Anthropic-compatible text execution
- Image generation and image editing
- TTS and ASR
- Conversation presentation render-speech/transcribe-audio
- Authoring character memory distillation
- Narrative quality GM proposal and writer generation
- Asset generation provider selection and apply paths that call image/TTS services
- Visual generation validation/dry-run remains non-spend by default; future provider-backed visual
  execution must route through `ProviderExecutionService`
- Provider lab real tests remain opt-in and must be skipped by default

Any runtime provider call bypassing `ProviderExecutionService` is a blocker.

## API Scope

Use existing admin budget policy endpoints:

- `GET/POST /worlds/{world_id}/providers/budget-policies`
- `PATCH /worlds/{world_id}/providers/budget-policies/{policy_id}`
- `GET /worlds/{world_id}/providers/quota-status`

Extend quota status with safe optional filters:

- `provider_id`
- `player_actor_id`
- `capability_key`

No tester Web quota UI is required in Phase 3. Player-facing degraded states can be produced by
the calling surfaces when provider execution returns a quota error.

## Security Model

- Quota checks run before secret resolution and before adapter execution.
- Quota failures must not retry into hidden spend.
- Quota failure evidence must be safe: world id, provider id, optional player actor id,
  capability key, active policy count, limit keys, and blocked reason.
- Do not include resolved secrets, raw prompts, raw outputs, storage paths, bytes, base64, prompt
  snapshot internals, or invite tokens in quota responses or world events.
- Do not write quota evidence to `world_events.payload`.
- Admin-only provider budget endpoints stay admin-only.

## Tests

Targeted tests should cover:

- world/provider emergency stop still blocks before secret resolution
- provider/world daily invocation limit still blocks
- capability limit blocks only the matching capability
- per-player limit blocks one tester without blocking another
- default per-player limit applies when `player_actor_id` is supplied
- quota status reports safe scoped usage and blocked reasons
- provider smoke/test path is quota-guarded
- text, image, TTS, ASR paths route through pre-call quota checks
- no real provider calls by default
- no secret/path/raw prompt/raw output/base64/bytes leaks
- no hidden retries after quota failure

## Stop Conditions

Stop implementation if:

- any provider spend path bypasses `ProviderExecutionService`
- `ProviderExecutionRequest` cannot identify the current private beta player for player-scoped
  runtime calls
- quota is only advisory and not enforced before adapter execution
- quota failures require exposing prompt snapshots, raw prompts, raw outputs, storage paths, or
  resolved secrets
- quota failure silently retries into hidden spend
- implementation requires broad `worlds.py` growth
- a new quota table becomes necessary but schema ownership is unclear
