# v0.4.3 Media Asset Admin Console Plan

## Goal

Implement the v0.4 Media Asset Admin Console so world admins can inspect media assets, media objects, media jobs, references, uploads, downloads, and lifecycle state from the Web workspace without exposing internal storage paths or creating a second media framework.

## Source Of Truth

- OpenSpec change: `openspec/changes/v0-4-operator-admin-ux`
- Capability spec: `openspec/changes/v0-4-operator-admin-ux/specs/media-admin-console/spec.md`
- Phase plan: `openspec/changes/v0-4-operator-admin-ux/phase-plan.md`
- Architecture contracts: `docs/agent/architecture/current-system-contracts.md`
- API inventory: `docs/agent/architecture/api-contract-inventory.md`
- Data model inventory: `docs/agent/architecture/data-model-inventory.md`

## Route Decision

- Add a world-scoped Web route at `/worlds/{worldId}/media`.
- Use the existing `/api/worlds/[...worldPath]` same-origin proxy for backend media API calls.
- Add a `Media` link to the world workspace nav.
- Keep reader/public media delivery out of scope.

## Scope

- Add Web types and client helpers for media assets, objects, jobs, references, upload, and download route construction.
- Add a server data loader for world media admin data.
- Add a media console component with asset list/detail, object list/download actions, job list/status, reference browser, upload flow, and visibility/status filters.
- Show safe media metadata summaries, dimensions, checksums, lifecycle status, and reference counts.
- Reuse v0.4.1 admin foundation components and existing media backend APIs.
- Add focused Web unit tests for client helpers, component behavior, upload/download path construction, filter behavior, and safe redaction.

## Non-goals

- No backend media kernel behavior changes.
- No migrations.
- No new storage backend.
- No public reader media delivery.
- No inline rendering from storage URIs.
- No Web UI for visual/speech/invocation/diagnostics phases.
- No provider execution, asset generation, or daemon behavior.

## Guardrails

- Do not render `storage_uri`, filesystem paths, raw bytes, base64 payloads, raw prompts, raw outputs, or provider secrets.
- Do not copy internal object storage references into UI state, world events, query strings, logs, or test fixtures.
- Downloads must use backend download endpoints and object IDs only.
- Media uploads must use backend `/worlds/{world_id}/media/assets/upload` with CSRF and existing ACL.
- Respect backend visibility filtering; hidden/developer-only records remain backend-authoritative.
- Do not use `narrative_artifacts` as media storage.
