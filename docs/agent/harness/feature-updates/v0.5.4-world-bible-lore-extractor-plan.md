# v0.5.4 World Bible & Lore Extractor Plan

## Goal

Extract lore, location, organization, world-rule, secret, and knowledge-boundary candidates from authoring source fragments into reviewable Phase 1 authoring proposals.

## Scope

- Add deterministic lore extractor contracts and service logic inside `backend/packages/authoring/`.
- Add authoring API route(s) under `backend/services/api/src/noveland/services/api/authoring.py`.
- Read existing `authoring_source_fragments.excerpt_text`; do not accept or persist full raw source bodies in Phase 4.
- Create Phase 1 `authoring_import_proposals` linked to source fragments and import runs.
- Represent lore candidates, location keys, organization labels, world rules, secrets, knowledge boundary labels, canon/inferred/uncertain classification, confidence, and evidence in safe proposal JSON.
- Keep all generated records worldline-scoped and traceable to source fragments.

## Non-goals

- No migration unless implementation proves the Phase 1 schema cannot carry extractor output.
- No Web UI.
- No provider-backed extraction in Phase 4.
- No invocation ledger changes because no provider extraction is used.
- No direct apply to `WorldBible`, global canon tables, scenes, organizations, memories, narrative state, or event history.
- No raw full source text in API responses, prompt snapshots, or `world_events.payload`.
- No changes to `worlds.py`.

## API Shape

- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/extract-lore`

Request:

- `worldline_id`
- `source_fragment_ids`
- `extractor_mode`: `deterministic`

Result:

- `run`
- `created_proposal_count`
- `lore_count`
- `location_count`
- `organization_count`
- `world_rule_count`
- `secret_count`
- `knowledge_boundary_count`
- `uncertain_count`

## Extractor Rules

- Lore candidates:
  - `lore: text`
  - `canon: text`
  - `inferred: text`
  - `uncertain: text`
- Location candidates:
  - `location: key`
  - `place: key`
- Organization candidates:
  - `organization: label`
  - `org: label`
- World rule candidates:
  - `rule: text`
  - `world rule: text`
- Secret candidates:
  - `secret: text`
  - `spoiler: text`
- Knowledge boundary candidates:
  - `knowledge: actor -> fact`
  - `knows: actor -> fact`
  - `hidden from: actor -> fact`
- Unknown lines are skipped rather than guessed.
- Duplicate candidates within the same run should be collapsed deterministically by normalized key when safe.

## Guardrails

- Generated proposals must reuse Phase 1 safe JSON validation.
- Lore extractor output must not include `storage_uri`, filesystem paths, raw bytes, base64, raw prompts, raw outputs, or full raw source.
- Lore extractor must not create provider invocations, media jobs, memory writes, world events, conversation turns, scenes, agents, relationships, visual bindings, voice bindings, or world bible records.
- Cross-world and cross-worldline source fragments, import runs, and proposals must be rejected.
- Direct canonical apply for lore proposals must remain blocked by the existing apply guardrails.
