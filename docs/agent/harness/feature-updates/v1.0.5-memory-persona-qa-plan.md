# v1.0.5 Memory & Persona QA Plan

Date: 2026-05-20
Branch: feature/v1.0-5-memory-persona-qa
OpenSpec change: `openspec/changes/v1-0-private-beta-mvp/`

## Decision Summary

Phase 5 will implement memory/persona QA as read-only admin diagnostics inside the existing
`narrative_quality` boundary. It will not add migrations, persisted QA run tables, Web UI,
provider execution, direct persona or memory mutation, a replacement eval framework, or broad
`worlds.py` routes.

The diagnostic report should help admins catch private beta blockers before testers see them:
missing persona cards, missing initial memory, memory contamination, persona drift, dialogue style
drift, relationship drift, source traceability gaps, and worldline contamination.

## Ownership

- Package owner: `backend/packages/narrative_quality/`
- API owner: existing app-level narrative quality router
- Endpoint: `POST /worlds/{world_id}/narrative-quality/memory-persona/qa`
- Response contract: response-only QA report DTOs with safe evidence refs and proposal-only repair
  suggestions
- Access: world admin only through existing narrative quality ACL
- No `worlds.py` route growth

## Evidence Sources

The report reuses existing v0.6-v1.0 records:

- `AgentPersona` for current persona card evidence
- `Agent.character_profile` for structured profile and style hints where applicable
- `AgentMemoryItem` for worldline-scoped active memory evidence
- `conversation_sessions`, `conversation_participants`, and `conversation_turns` for recent
  dialogue and speaker context
- v0.9 authoring/persona/memory distillation metadata for source traceability refs
- model invocation IDs only as safe refs, never prompt snapshot or provider payload internals

## Report Semantics

The report is deterministic and non-mutating. It returns:

- `status=blocked` when critical persona, memory, contamination, or worldline evidence fails
- `status=watch` for non-blocking warnings such as drift or traceability gaps
- `status=ok` when no findings are present
- safe finding codes, severities, summaries, evidence refs, source traceability refs, and
  `suggested_repair_proposal_types`
- `repair_policy=proposal_only` and `mutation_count=0`

It must not include raw memory content, raw persona text, raw turn text, raw prompts, raw outputs,
prompt snapshot internals, provider payloads, storage paths, bytes/base64, resolved secrets, or
reader/player/member diagnostics.

## Frontend Scope

No Web UI is required for Phase 5. The implementation is backend/API-only, so no new
`impeccable` UI work is required in this phase. A later admin QA surface may consume the safe
report only after `impeccable` is used.

## Tests

Targeted tests should cover:

- successful QA report with traceable persona and memory
- missing persona and missing memory blockers
- memory contamination fixture
- persona drift and dialogue style drift fixture
- relationship drift fixture
- cross-worldline conversation/evidence rejection
- admin-only API ACL
- no direct persona/memory/world-event mutation
- no forbidden storage/path/base64/bytes/raw prompt/raw output/secret markers in responses
- repair suggestions remain proposal-type hints only

## Stop Conditions

Stop implementation if:

- QA requires raw prompt/output, prompt snapshot internals, provider payloads, storage paths, bytes,
  base64, resolved secrets, or raw memory/persona/turn bodies in non-admin responses
- repair suggestions bypass authoring review/apply or directly mutate persona/memory
- source traceability cannot be represented with safe refs
- worldline isolation cannot be validated for referenced conversations, turns, memory, or agents
- QA requires a duplicate persistent eval framework or new memory framework
- Web UI becomes mandatory but `impeccable` cannot be used
