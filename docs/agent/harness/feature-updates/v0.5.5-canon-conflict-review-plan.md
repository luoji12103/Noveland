# v0.5.5 Canon Conflict Review Plan

## Goal

Detect duplicate and conflicting authoring proposals inside a target import run so admins can review canon risk before selective apply.

## Scope

- Add deterministic conflict review contracts and service logic inside `backend/packages/authoring/`.
- Add authoring API route(s) under `backend/services/api/src/noveland/services/api/authoring.py`.
- Analyze existing Phase 1 proposals from the selected import run; do not read or persist full raw source bodies.
- Create Phase 1 `authoring_import_proposals` of kind `other` for conflict reports linked to the import run and, when possible, a source fragment.
- Represent duplicate character candidates, duplicate lore/location/organization candidates, contradictory relationship labels, contradictory identity/baseline values, and uncertain/OOC risk as safe proposal JSON.
- Keep all generated records worldline-scoped and traceable to source fragments when available.

## Non-goals

- No migration unless implementation proves the Phase 1 schema cannot carry conflict report output.
- No Web UI.
- No provider-backed conflict review in Phase 5.
- No invocation ledger changes because no provider review is used.
- No automatic conflict resolution.
- No direct mutation of agents, relationships, memories, world bible, narrative state, or event history.
- No raw full source text in API responses, prompt snapshots, or `world_events.payload`.
- No changes to `worlds.py`.

## API Shape

- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/review-conflicts`

Request:

- `worldline_id`
- `review_mode`: `deterministic`
- `include_statuses`: optional proposal statuses, default `["proposed", "reviewed", "approved"]`

Result:

- `run`
- `created_proposal_count`
- `duplicate_count`
- `contradiction_count`
- `uncertain_count`
- `ooc_risk_count`

## Review Rules

- Duplicate candidates:
  - same normalized character label
  - same normalized location key
  - same normalized organization key
  - same normalized lore text/classification pair
- Contradictions:
  - same relationship source/target with different labels
  - same character identity key with different values
  - same character emotional baseline with different values
- Uncertain/OOC risk:
  - lore candidates with `classification=uncertain`
  - proposal evidence or payload with `ooc_risk=true`
- Unknown proposal shapes are skipped rather than guessed.
- Duplicate conflict reports within the same review run should be collapsed deterministically.

## Guardrails

- Generated conflict proposals must reuse Phase 1 safe JSON validation.
- Conflict review output must not include `storage_uri`, filesystem paths, raw bytes, base64, raw prompts, raw outputs, or full raw source.
- Conflict review must not create provider invocations, media jobs, memory writes, world events, conversation turns, scenes, agents, relationships, visual bindings, voice bindings, or world bible records.
- Cross-world and cross-worldline import runs and proposals must be rejected.
- Direct canonical apply must remain governed by the existing apply guardrails.
