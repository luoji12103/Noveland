# v0.5.7 Asset Import & Matching Plan

## Goal

Create reviewable asset match proposals that connect imported media-backed source assets to character sprites, scene backgrounds, CG references, and voice references without directly mutating visual or speech bindings.

## Scope

- Add deterministic asset matching contracts and service logic inside `backend/packages/authoring/`.
- Add authoring API route(s) under `backend/services/api/src/noveland/services/api/authoring.py`.
- Read existing Phase 1 `authoring_source_assets` and `authoring_source_fragments`; do not introduce a new upload or media storage path.
- Require matched source assets to reference existing `media_assets` when a media-backed proposal is created.
- Create Phase 1 `authoring_import_proposals` of kind `asset_match` linked to source assets, source fragments when available, and import runs.
- Represent sprite, background, CG, and voice-reference match candidates in safe proposal JSON with source traceability, confidence, and deterministic reason fields.
- Keep all generated proposals worldline-scoped and validate same world/same worldline for source assets, source fragments, media assets, and import runs.

## Non-goals

- No migration unless implementation proves the Phase 1 schema cannot carry asset match proposal output.
- No Web UI.
- No provider-backed image, audio, ASR, TTS, or embedding matching in Phase 7.
- No invocation ledger changes because no provider matching is used.
- No media upload endpoint or public media delivery.
- No automatic visual binding, sprite variant, background, voice profile, or speech binding apply.
- No direct mutation of agents, scenes, relationships, memories, world bible, narrative state, media storage, visual bindings, speech bindings, or event history.
- No raw filesystem path, storage URI, bytes, base64, raw prompt, raw output, or full raw source in API responses, prompt snapshots, or `world_events.payload`.
- No changes to `worlds.py`.

## API Shape

- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/match-assets`

Request:

- `worldline_id`
- `source_asset_ids`: optional explicit source assets to match
- `source_fragment_ids`: optional asset fragments to inspect
- `matching_mode`: `deterministic`
- `include_visual_matches`: optional boolean, default `true`
- `include_voice_matches`: optional boolean, default `true`
- `include_cg_matches`: optional boolean, default `true`

Result:

- `run`
- `created_proposal_count`
- `sprite_match_count`
- `background_match_count`
- `cg_match_count`
- `voice_match_count`
- `blocked_count`

## Matching Rules

- Source assets with image media can produce sprite, background, or CG match proposals.
- Source assets with audio media can produce voice-reference match proposals.
- Candidate hints come only from safe source asset metadata, source fragment metadata, source fragment kind, source asset kind, and display labels.
- Sprite candidates may use safe hints:
  - `character_label`
  - `expression_key`
  - `pose_key`
  - `outfit_key`
  - `mood_tags`
- Background candidates may use safe hints:
  - `scene_id`
  - `location_key`
  - `time_of_day`
  - `weather_key`
- Voice candidates may use safe hints:
  - `speaker_label`
  - `voice_label`
  - `emotion_key`
  - `style_key`
- CG candidates may use safe hints:
  - `scene_id`
  - `cg_key`
  - `route_key`
- Unknown media kinds or missing media references should create blocked counts or skip with deterministic evidence, not random matches.
- Duplicate candidates within the same run should be collapsed by normalized media asset, source asset, match kind, and target hint key.

## Guardrails

- Generated asset match proposals must reuse Phase 1 safe JSON validation.
- Asset matching output must not include `storage_uri`, filesystem paths, raw bytes, base64, raw prompts, raw outputs, or full raw source.
- Asset matching must not create provider invocations, media jobs, memory write jobs, world events, conversation turns, scenes, agents, relationships, visual bindings, voice bindings, speech transcripts, or world bible records.
- Cross-world and cross-worldline source assets, source fragments, media assets, import runs, and proposals must be rejected.
- Hidden or developer-only media assets must not be selected for ordinary admin matching unless an explicit future internal path is accepted.
- Direct canonical asset apply must remain blocked by the existing apply guardrails unless a future phase defines reviewed apply semantics.
