# v0.4.5 Speech Admin Console Plan

## Goal

Implement the v0.4 Speech Admin Console so world admins can manage voice profiles, agent voice bindings, speech style mappings, transcripts, and explicit TTS/STT test actions from the Web workspace without adding realtime voice, streaming, local voice server deployment, or backend speech behavior changes.

- Capability spec: `openspec/changes/v0-4-operator-admin-ux/specs/speech-admin-console/spec.md`
- Phase plan: `openspec/changes/v0-4-operator-admin-ux/phase-plan.md`
- Architecture contracts: `docs/agent/architecture/current-system-contracts.md`
- API inventory: `docs/agent/architecture/api-contract-inventory.md`
- Data model inventory: `docs/agent/architecture/data-model-inventory.md`

## Route Decision

- Add a world-scoped Web route at `/worlds/{worldId}/speech`.
- Use the existing `/api/worlds/[...worldPath]` same-origin proxy for backend speech API calls.
- Add a `Speech` link to the world workspace nav.
- Keep public reader audio delivery out of scope.

## Scope

- Add Web types and client helpers for voice profiles, agent voice profile bindings, speech style mappings, transcripts, TTS, and STT.
- Add a server data loader for world speech admin data using worlds, memberships, worldlines, agents, provider integrations, audio media assets, voice profiles, bindings, style mappings, and transcripts already exposed by existing APIs.
- Add a speech console component with:
  - voice profile list/detail and create/update/delete forms;
  - agent voice binding list/create/delete controls;
  - speech style mapping list/create/update/delete controls;
  - transcript browser filtered by worldline/source asset;
  - explicit TTS test action that returns safe media job, output asset/object, and invocation IDs;
  - explicit STT test action that returns safe transcript, media job, and invocation IDs.
- Show safe speech/media metadata: IDs, status, visibility, language, provider reference IDs, checksums, object IDs, transcript text, and invocation IDs.
- Reuse v0.4.1 admin foundation components, existing provider/media helpers where useful, and existing speech backend APIs.
- Add focused Web unit tests for client helpers, component behavior, TTS/STT request construction, style mapping updates, transcript display, workspace navigation, and leak-safe rendering.

## Non-goals

- No backend speech service behavior changes.
- No migrations.
- No realtime voice or streaming.
- No local voice server deployment.
- No provider adapter changes.
- No automatic STT memory writes.
- No public reader audio delivery.
- No raw audio bytes, base64 payloads, storage URI, filesystem path, raw prompt, raw output, or resolved secret rendering.
- No Web UI for invocation ledger or diagnostics phases.
- No daemon behavior, asset generation orchestration, or marketplace behavior.

## Guardrails

- TTS/STT test actions must be explicit admin actions and must use existing `/worlds/{world_id}/speech/tts` and `/worlds/{world_id}/speech/stt`.
- TTS/STT result displays must use returned media job IDs, media asset IDs, object IDs, transcript IDs, and invocation IDs only.
- Audio output may be linked through safe existing media object download endpoints when object IDs are available; do not embed storage URIs or raw binary payloads.
- STT transcript display must not imply a memory write and must not mutate conversation turn text.
- Voice profile and binding forms must preserve world/worldline/agent/provider boundaries and rely on backend validation.
- Non-platform users must not be offered restricted `developer_only` or `hidden` visibility choices.
- UI copy should make provider, voice, media, transcript, and invocation boundaries visible without exposing secrets or raw prompts.
