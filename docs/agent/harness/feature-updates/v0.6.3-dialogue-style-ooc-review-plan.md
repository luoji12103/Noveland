# v0.6.3 Dialogue Style & OOC Review Plan

## Goal

Implement the first API-first dialogue quality review for character speech style, relationship consistency, and out-of-character risk.

## Scope

- Add admin-only narrative quality APIs for dialogue review.
- Reuse conversation sessions, turns, participants, agent profiles, relationships, and Phase 1 context helpers.
- Support reviewing an existing conversation turn or an explicit text sample.
- Return structured findings with severity, evidence refs, and suggested operator action.
- Keep diagnostics out of reader/member routes and world event payloads.

## Non-goals

- No Web dashboard or UI.
- No provider-backed style review in this phase.
- No automatic blocking of dialogue generation.
- No mutation of conversation turn text.
- No automatic memory writes.
- No migration unless implementation proves persistent review records are required.
- No broad `worlds.py` routes.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/dialogue/review`

Request fields:

- `worldline_id`
- `conversation_id`
- `turn_id` optional
- `speaker_agent_id` optional
- `text` optional when `turn_id` is not provided
- `context_limit`

Response fields:

- `world_id`
- `worldline_id`
- `conversation_id`
- `turn_id`
- `speaker_agent_id`
- `review_status`
- `style_score`
- `ooc_risk_score`
- `relationship_consistency_score`
- `findings`
- `evidence_refs`
- `diagnostics`

## Review Heuristics

- Missing speaker profile or speaker mismatch produces actionable warnings.
- Empty or very short dialogue produces low-confidence findings.
- Text that conflicts with agent profile style hints, speech style tags, or relationship context produces OOC/relationship findings.
- Text containing storage URIs, filesystem paths, base64, raw prompt/output markers, or secret-like content is redacted in responses and flagged.
- Review remains deterministic and provider-free in Phase 3.

## Tests

- Review existing turn for a known speaker.
- Review explicit text sample without mutating the turn.
- Detect missing speaker profile.
- Detect cross-worldline conversation/turn.
- Detect leaky text and redact response.
- Verify no `world_events` payload pollution.
- Verify API requires world admin ACL and CSRF.
