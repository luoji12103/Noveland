# v0.3.1.9 Character Sprite / Scene Asset System Phase 9 Plan

## Summary

Phase 9 adds a worldline-strict visual binding layer for galgame character sprites, expression/pose/outfit variants, scene backgrounds, and scene composition convenience APIs. It reuses Phase 4 media assets/objects/jobs/references and Phase 6 deterministic `ImageService.compose_image()` instead of introducing a second media or composition framework.

This phase is backend/API only. It does not add Web UI, background generation, public reader media delivery, provider calls, streaming, or changes to `worlds.py`.

## Schema

Add migration `20260512_0037_visual_asset_system.py`, revising current head `20260512_0036`.

Create:

- `character_sprite_sets`
- `character_sprite_variants`
- `scene_background_profiles`

All records have `world_id` and non-null `worldline_id`. No nullable worldline defaults are allowed. Visual records point to existing `media_assets`; they never copy `storage_uri`, object paths, bytes, or base64 data.

`scene_composition_templates` is deferred unless implementation proves reusable layouts cannot be represented in request metadata. The first version composes scenes directly through request-layer layout data.

## Service Rules

- Validate every referenced `media_asset` is same world and same worldline.
- Validate sprite/background assets are image assets.
- Default ordinary resolve flow suppresses hidden/developer-only media assets.
- Platform-admin/internal resolve can opt into hidden/developer-only media assets.
- Sprite resolve order is exact expression/pose/outfit/mood match, then neutral expression, then default variant. If none is usable, return an actionable validation error.
- Background resolve order is exact scene/location/time/weather, then default background for scene/location. If none is usable, return an actionable validation error.
- Compose scene builds an `ImageComposeRequest` and calls `ImageService.compose_image()`.
- No `world_events.payload` writes.
