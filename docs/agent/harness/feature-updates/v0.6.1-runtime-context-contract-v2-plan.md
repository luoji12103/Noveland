# v0.6.1 Runtime Context Contract v2 Plan

## Goal

Implement the first v0.6 backend foundation for runtime narrative quality: explicit, safe, worldline-aware context contracts for agent, conversation, GM, narrative, and eval call sites.

This phase establishes the dedicated `narrative_quality` package/router boundary and does not implement Web UI.

## Scope

- Add `backend/packages/narrative_quality/`.
- Add `backend/services/api/src/noveland/services/api/narrative_quality.py`.
- Register the router at app level only.
- Add DTOs and service entrypoints for runtime context preview.
- Reuse `LivingWorldContextSelector`, conversation services, agents, worldlines, invocation ledger concepts, and memory/world guardrail records.
- Return sanitized context metadata and prompt-ready text through admin-scoped APIs.
- Keep all responses free of resolved secrets, storage paths, raw binary/base64, raw prompts, and raw outputs.

## Accepted v0.6 Pre-implementation Decisions

- Provider-backed GM and narrative generation must use `ProviderExecutionService` with `ProviderKind.TEXT_GENERATION`; legacy provider profiles remain legacy compatibility only.
- New v0.6 runtime-quality APIs belong in `backend/packages/narrative_quality/` and `narrative_quality.py`.
- v0.6 remains API-first. Web dashboard work is deferred.
- No broad runtime-quality route growth in `worlds.py`.
- Narrative Writer v2 will require first-class worldline persistence before writing generated artifacts. The selected strategy is to add explicit `worldline_id` handling for v2-generated narrative artifacts/publications in the Narrative Writer v2 phase; until that phase lands, v0.6 context APIs may read existing legacy artifact metadata but must not treat metadata-only worldline values as sufficient for new v2 write isolation.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/context/preview`

The request selects a `context_kind`:

- `agent`
- `conversation`
- `gm`
- `narrative`
- `eval`

The response includes:

- `world_id`
- `worldline_id`
- `context_kind`
- `subject_ref`
- `prompt_text`
- `metadata`
- `diagnostics`
- `evidence_refs`
- `generated_at`

## Non-goals

- No Web dashboard or Web routes.
- No provider-backed generation.
- No GM proposal generation.
- No narrative artifact generation.
- No migration.
- No broad new runtime-quality routes in `worlds.py`.
- No runtime daemon integration.

## Guardrails

- Admin-scoped by default.
- Validate all worldline-scoped records against the resolved worldline.
- Do not write to `world_events.payload`.
- Do not expose prompt snapshots or raw provider evidence.
- Do not duplicate media, provider, memory, visual, speech, or eval subsystems.

## Targeted Tests

- Runtime context service returns agent context from existing living-world selector.
- Conversation context includes safe turn summaries and participant diagnostics.
- GM/narrative/eval context previews are worldline-scoped.
- API requires world admin access.
- API suppresses storage URI, filesystem path, base64, bytes, raw prompt, raw output, and secret-like values.
- New package/router imports through workspace import coverage.

## Validation

- `openspec validate --specs --strict`
