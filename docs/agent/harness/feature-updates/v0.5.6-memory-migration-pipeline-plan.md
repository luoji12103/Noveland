# v0.5.6 Memory Migration Pipeline Plan

## Goal

Convert source fragments and authoring proposals into reviewable memory migration proposals without directly writing to memory stores.

## Scope

- Add deterministic memory migration contracts and service logic inside `backend/packages/authoring/`.
- Add authoring API route(s) under `backend/services/api/src/noveland/services/api/authoring.py`.
- Read existing `authoring_source_fragments.excerpt_text` and selected import-run proposals; do not accept or persist full raw source bodies in Phase 6.
- Create Phase 1 `authoring_import_proposals` of kind `memory` linked to source fragments and import runs.
- Represent fact, episodic, relationship, preference, and style memory candidates in safe proposal JSON with source traceability and confidence.
- Keep all generated records worldline-scoped and traceable to source fragments when available.

## Non-goals

- No migration unless implementation proves the Phase 1 schema cannot carry memory proposal output.
- No Web UI.
- No provider-backed memory extraction in Phase 6.
- No invocation ledger changes because no provider extraction is used.
- No direct memory backend SDK access.
- No automatic memory writes outside explicit future apply semantics.
- No direct mutation of agents, relationships, world bible, narrative state, or event history.
- No raw full source text in API responses, prompt snapshots, or `world_events.payload`.
- No changes to `worlds.py`.

## API Shape

- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/migrate-memory`

Request:

- `worldline_id`
- `source_fragment_ids`
- `migration_mode`: `deterministic`
- `include_proposals`: optional boolean, default `true`

Result:

- `run`
- `created_proposal_count`
- `fact_count`
- `episodic_count`
- `relationship_count`
- `preference_count`
- `style_count`

## Migration Rules

- Fact memory candidates:
  - `fact: text`
  - lore proposals with `candidate_kind=lore`
- Episodic memory candidates:
  - `episode: text`
  - `episodic: text`
- Relationship memory candidates:
  - `relationship memory: A -> B: text`
  - relationship proposals with source/target labels
- Preference memory candidates:
  - `preference: actor = value`
  - `actor likes value`
  - `actor dislikes value`
- Style memory candidates:
  - `style: actor = value`
  - dialogue proposals with speaker labels may produce style candidate stubs
- Unknown lines and proposal shapes are skipped rather than guessed.
- Duplicate candidates within the same run should be collapsed deterministically by normalized key when safe.

## Guardrails

- Generated memory proposals must reuse Phase 1 safe JSON validation.
- Memory migration output must not include `storage_uri`, filesystem paths, raw bytes, base64, raw prompts, raw outputs, or full raw source.
- Memory migration must not create provider invocations, media jobs, memory write jobs, world events, conversation turns, scenes, agents, relationships, visual bindings, voice bindings, or world bible records.
- Cross-world and cross-worldline source fragments, import runs, and proposals must be rejected.
- Direct canonical memory apply must remain blocked by the existing apply guardrails.
