# v1.1.8 Release Candidate Gate Plan

## Scope

Phase 8 adds a backend/API-only release-candidate readiness report under the existing observability/readiness boundary. It aggregates v1.1 normal-use evidence and prior readiness gates without adding migrations, Web UI, duplicate readiness tables, provider calls, or public-launch behavior.

## Decisions

- Ownership stays in `backend/packages/observability/` and the app-level `backend/services/api/src/noveland/services/api/observability.py` router.
- The report extends existing readiness DTO/service patterns and reuses production, public-launch, self-use MVP, private beta, backup/restore drill, normal-use stress, moderation, packaging, provider, and no-leak evidence.
- No RC report UI is approved for Phase 8, so `impeccable` is not required for this phase.
- The endpoint is platform-admin only and must return safe evidence summaries and refs only.
- The RC gate distinguishes self-use MVP, private beta, normal use, release candidate, and public launch. Passing RC must not set `public_launch_ready` or enable automatic launch.

## Evidence Model

The RC report should include:

- Operational runbook review/manual evidence.
- Private beta gate evidence.
- Backup/restore drill report evidence.
- Normal-use stress report evidence.
- Content safety/moderation evidence and review confirmation.
- Import/export/package stability evidence and review confirmation.
- Provider reliability/degraded-mode evidence and review confirmation.
- User-facing polish review evidence.
- World-event no-leak evidence.
- Manual normal-use checklist confirmation.

## Tests

- Pass with complete normal-use evidence.
- Fail when backup/restore drill evidence is missing.
- Fail when stress, moderation, packaging, provider reliability, UX, or manual evidence is missing.
- Fail on leak fixture.
- Require platform admin for the endpoint.
- Verify the RC gate does not create duplicate readiness framework tables and does not imply public launch.
- Verify reports do not expose secrets, storage paths, raw prompts, raw outputs, invite tokens, bytes, or base64.

## Stop Conditions

- RC gate duplicates observability/readiness framework tables or persisted gate runs.
- RC gate implies public launch or unauthenticated access.
- RC evidence requires raw prompt/output, storage path, provider secret, invite token, prompt snapshot internals, bytes, or base64.
- RC endpoint exposes admin diagnostics to tester/player/member surfaces.
