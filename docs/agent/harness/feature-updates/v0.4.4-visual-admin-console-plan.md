# v0.4.4 Visual Asset Admin Console Plan

## Goal

Implement the v0.4 Visual Asset Admin Console so world admins can manage strict-worldline sprite sets, expression variants, scene backgrounds, resolver previews, and explicit compose-scene actions from the Web workspace without adding visual generation, changing backend visual behavior, or exposing media storage internals.

## Route Decision

- Add a world-scoped Web route at `/worlds/{worldId}/visual`.
- Use the existing `/api/worlds/[...worldPath]` same-origin proxy for backend visual API calls.
- Add a `Visual` link to the world workspace nav.
- Keep public reader visual delivery out of scope.

## Scope

- Add Web types and client helpers for sprite sets, sprite variants, scene backgrounds, sprite/background resolution, and compose-scene calls.
- Add a server data loader for world visual admin data using the selected world, worldlines, agents, scenes, visual records, and image media assets already exposed by existing APIs.
- Add a visual console component with:
  - sprite set list/detail and create/update/delete forms;
  - sprite variant list/detail and create/update/delete forms;
  - scene background list/detail and create/update/delete forms;
  - resolver controls for sprite expression/pose/outfit/style and background scene/location/time/weather;
  - explicit compose-scene action using background and layer asset IDs.
- Show safe media references through asset IDs, dimensions, checksums, status, visibility, and titles only.
- Reuse v0.4.1 admin foundation components, existing media helpers where useful, and existing visual backend APIs.
- Add focused Web unit tests for client helpers, component behavior, resolver fallback display, compose request construction, workspace navigation, and leak-safe rendering.

## Non-goals

- No backend visual service behavior changes.
- No migrations.
- No automatic sprite generation.
- No background generation orchestration.
- No nullable-worldline visual defaults.
- No public reader visual delivery.
- No storage URI, filesystem path, raw bytes, base64, raw prompt, or raw output rendering.
- No Web UI for speech, invocation ledger, or diagnostics phases.
- No provider execution, asset generation, daemon behavior, streaming, or marketplace behavior.

## Guardrails

- Every create/update/resolve/compose workflow must require an explicit non-empty `worldline_id` supplied by the operator or selected from known worldlines.
- Do not offer nullable worldline defaults in forms or helpers.
- Do not bypass backend restrictions for `developer_only` or `hidden` visual records. Only platform-admin context may request restricted resolver inclusion.
- Do not duplicate media storage state. Sprite, variant, background, and compose flows reference `media_assets` by ID.
- Do not render object storage URIs, file paths, binary payloads, base64 payloads, raw prompts, raw outputs, or resolved secrets.
- Compose scene is an explicit admin action and must use existing `/worlds/{world_id}/visual/compose-scene`; it must not start background generation or a daemon loop.
- UI copy should keep visual bindings operational and dense: worldline, agent, scene, asset, fallback reason, status, and visibility are first-class fields.
