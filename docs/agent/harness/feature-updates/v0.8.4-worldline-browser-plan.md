# v0.8.4 Worldline Browser Plan

Date: 2026-05-16
Branch: `main`

## Scope

Implement the first authenticated read-only worldline browser for reader/member/player/admin users. The browser should show branch list/tree context, branch metadata, and safe comparison summaries using existing worldline records and comparison counts.

## Accepted Design

- Add a Web route under the world workspace, preferably `/worlds/{world_id}/worldlines`.
- Reuse existing `Worldline` and `WorldlineComparison` DTOs.
- Reuse existing `GET /worlds/{world_id}/worldlines`.
- Reuse existing `GET /worlds/{world_id}/worldlines/{base_worldline_id}/compare/{compare_worldline_id}` if a narrow member-safe ACL adjustment is needed.
- Keep fork creation, rollback, merge, and branch switching out of the player/reader browser.
- Show safe comparison counts only: divergent event count, relationship delta count, faction delta count, choice delta count, and fork sequence.
- Do not show raw `world_events.payload`, raw prompts, raw outputs, media storage paths, filesystem paths, bytes, base64, resolved secrets, or hidden branch evidence.
- Preserve strict same-world validation for both compared worldlines.

## Non-Goals

- No backend migration.
- No destructive rollback.
- No branch merge.
- No branch switching that mutates user state.
- No fork creation UI in the reader/player browser.
- No raw event timeline payload display.
- No admin diagnostics or hidden future branch evidence in reader/member/player UI.
- No public unauthenticated access.
- No broad new `worlds.py` routes.

## Current Capability Inventory

- `GET /worlds/{world_id}/worldlines` is member-readable and returns worldlines for the selected world.
- `POST /worlds/{world_id}/worldlines/fork` is admin-only and must remain outside the Phase 4 browser.
- `GET /worlds/{world_id}/worldlines/{base_worldline_id}/compare/{compare_worldline_id}` returns safe aggregate comparison counts but is currently admin-scoped.
- The Web client already has `listWorldlines()` and `compareWorldlines()` helpers.
- Mock e2e data already contains a primary worldline and an `empty-fork` child worldline.

## Implementation Notes

- Use `impeccable` context before editing Web UI files.
- Keep the surface task-focused and read-only: branch inventory, selected base/compare controls, and safe comparison output.
- Add a workspace `Worldlines` nav link if the browser route is added.
- Server-side loading should tolerate compare-route authorization gaps and show a safe unavailable state rather than leaking detail.
- If compare becomes member-readable, keep the response shape safe and add backend ACL tests for cross-world rejection and member access.
- Do not reuse admin-only event audit payloads for branch details.

## Targeted Validation

- Backend API/ACL tests if the compare endpoint ACL changes.
- Web component tests for worldline list/tree, comparison controls, comparison result, empty state, and no destructive controls.
- E2E smoke proving an authenticated member can open the worldline browser and see safe branch/comparison information.
- Leak test coverage proving no `storage_uri`, filesystem path, base64, bytes, raw prompt/output, resolved secret, or raw event payload appears in the page.
- Full local gate after implementation.
