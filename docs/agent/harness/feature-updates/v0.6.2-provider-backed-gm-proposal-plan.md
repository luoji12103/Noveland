# v0.6.2 Provider-backed GM Proposal Plan

## Goal

Implement the v0.6 Phase 2 backend/API foundation for provider-backed GM proposal generation without allowing provider output to directly mutate world state.

## Scope

- Add an admin-only narrative quality API endpoint for GM proposal generation.
- Reuse `ProviderExecutionService` with `ProviderKind.TEXT_GENERATION`.
- Reuse invocation ledger and prompt snapshots for provider execution evidence.
- Reuse `LivingWorldContextSelector` / Phase 1 context preview shape for worldline-scoped prompt context.
- Reuse `LivingWorldGMService.create_proposal()` and existing `gm_event_proposals`.
- Store only safe traceability in proposal `source_context`, including provider id, invocation id, context kind, and redacted generation metadata.
- Return actionable errors for unsupported provider/adapter choices.

## Provider Text Execution Decision

The provider kernel already supports `ProviderKind.TEXT_GENERATION` through fake/local-stub provider execution with ledger writes and prompt snapshots. Phase 2 will use that existing provider-kernel path.

Real OpenAI/Anthropic text adapters are not implemented in the current provider package. Phase 2 must not route through legacy provider profiles to fill that gap. If a selected provider cannot execute provider-kernel text generation safely, the API returns an actionable error and still relies on provider execution failure evidence when an invocation was created.

## Non-goals

- No automatic GM proposal apply or world event mutation.
- No broad new `worlds.py` routes.
- No provider marketplace, streaming, Web UI, or dashboard work.
- No new external provider adapter unless required by a later accepted OpenSpec update.
- No migration unless implementation proves the existing `gm_event_proposals.source_context` cannot safely hold traceability.
- No raw provider output, raw prompt, secret, storage URI, path, bytes, or base64 in `world_events.payload`.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/gm/proposals/generate`

Request fields:

- `worldline_id`
- `provider_id` or `capability_key`
- `prompt_goal`
- `importance`
- `risk_score`
- `affected_agents`
- `affected_organizations`
- `event_name`
- `dry_run`
- optional `context_limit`

Response fields:

- `proposal`
- `invocation`
- `provider`
- `dry_run`
- `diagnostics`

## Implementation Notes

- Use the dedicated `narrative_quality` package/router only.
- Sanitize request JSON before provider execution.
- Build a bounded GM prompt from Phase 1 context service helpers.
- For deterministic fake/local provider output, derive a safe proposal title/reason from output text and request fields.
- For malformed provider output, create no proposal and return an actionable 422 with invocation evidence if available.
- If `dry_run=true`, execute the provider and return parsed/safe proposal preview without writing `gm_event_proposals`.
- If `dry_run=false`, create a `gm_event_proposals` row with `status=proposed`.
- Do not append `world_events`.
- Do not write raw prompt/output into proposal payload or source context.

## Tests

- Fake text provider creates a GM proposal.
- Dry run writes invocation but no proposal.
- Generated proposal is same-worldline and status `proposed`.
- Provider invocation and prompt snapshot are written.
- Missing or non-text provider returns an actionable error.
- Provider failure does not create a proposal.
- Request rejects secret-like fields.
- API requires world admin ACL and CSRF.
- Response and proposal payload/source context do not contain secrets, storage URI, paths, base64, raw prompt, or raw output.
- No `world_events` rows are created by generation.

## Validation

- Targeted backend tests for narrative quality service/API and provider execution.
- `openspec validate --changes --strict`
- `openspec validate --specs --strict`
- Full local gate before fast-forward merge.
