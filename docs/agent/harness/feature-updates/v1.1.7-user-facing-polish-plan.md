# v1.1.7 User-facing Polish Plan

Date: 2026-05-21
Branch: `feature/v1.1-7-user-facing-polish`
OpenSpec change: `v1-1-normal-use-release-candidate`

## Decision

Phase 7 will polish existing Web surfaces only. It will not add backend behavior, migrations, API routes, new product flows, broad redesigns, landing pages, real provider calls, or admin diagnostics on tester/player surfaces.

## Impeccable Preflight

`impeccable` was loaded before Web edits.

`IMPECCABLE_PREFLIGHT: context=pass product=pass command_reference=pass shape=not_required image_gate=skipped:product UI polish uses existing operational surfaces and no generated imagery mutation=open`

`PRODUCT.md` identifies Noveland as a product UI for operator-grade virtual-world administration. `DESIGN.md` is absent, so this phase follows the product and polish references plus the existing Noveland CSS/component conventions.

## Scope

Polish remains narrow and applies to existing surfaces:

- Private beta invite redemption and player identity setup.
- Beta feedback submission, filtering, and triage.
- Player resume and recovery status.
- Conversation playback and scene media fallback states.
- Provider profile health/status clarity.
- Shared responsive, focus, disabled, and compact status styles used by those surfaces.

## Non-goals

- No Web redesign or marketing-style onboarding.
- No backend contract expansion.
- No new API route or proxy route.
- No new admin evidence on tester/player UI.
- No public/social feedback behavior.
- No storage paths, raw prompts, raw outputs, prompt snapshot internals, bytes, base64, resolved secrets, provider credentials, or invite-token rendering.

## Implementation Plan

- Use existing `management-panel`, `resource-row`, `management-notice`, button, table, and form patterns.
- Add small shared CSS utilities for inline safe hints, status pills, responsive action rows, and media fallback text.
- Improve busy/disabled labels and required labels on forms.
- Keep evidence refs and provider status summaries descriptive but redacted.
- Preserve reader-safe media download paths and existing player/member/admin ACL boundaries.

## Tests

- Focused Web unit tests for private beta onboarding, beta feedback, playback, scene view, player interactions, and provider admin.
- Web lint, typecheck, unit tests, build, and `check:next-env`.
- Web e2e because playback/scene/session-adjacent surfaces are touched.
- OpenSpec strict validation and `git diff --check`.

## Stop Conditions

- UI polish requires backend/API contract changes.
- Tester/player UI would need admin diagnostics.
- Any surface renders token, secret, storage path, raw prompt/output, prompt snapshot internals, bytes, or base64 evidence.
- The work expands into a redesign, landing page, marketing scope, or new product feature.
- `impeccable` cannot be read or used before Web edits.
