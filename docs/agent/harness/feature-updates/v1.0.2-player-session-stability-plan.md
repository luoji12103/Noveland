# v1.0.2 Player Session Stability Plan

## Scope

Phase 2 adds the server-owned resume contract that private beta testers need after closing and
reopening the browser. It is not a multiplayer sync system, an offline cache, or an admin
diagnostics surface.

## Decisions

- Package ownership: add `backend/packages/player_sessions/`.
- Router ownership: add `backend/services/api/src/noveland/services/api/player_sessions.py`.
- Router registration: app-level include only; do not add broad `worlds.py` routes.
- Web scope: extend the existing player surface with a compact resume panel and restore action.
- UI register: product. Use the existing restrained management-panel vocabulary; no marketing
  onboarding, graph editor, or decorative restore flow.

## Schema Plan

Add migration `20260517_0047_player_sessions.py` with table `player_sessions`.

Fields:

- `id`
- `world_id`
- `worldline_id`
- `user_id`
- `player_actor_id`
- `conversation_session_id`
- `scene_id` nullable
- `last_turn_id` nullable
- `last_presentation_id` nullable
- `route_state_json` safe JSON
- `resume_state_json` safe JSON
- `recovery_status`
- `status`
- `last_seen_at`
- `created_at`
- `updated_at`

Use a unique constraint on `(world_id, worldline_id, user_id, player_actor_id)` so each tester has
one active resume record per player identity and worldline. Keep route/resume JSON bounded and
sanitized; do not store raw event payloads, raw prompts, raw outputs, storage URIs, local paths,
base64, bytes, prompt snapshot internals, resolved secrets, or invite tokens.

## API Plan

Add member/player-safe endpoints under the dedicated router:

- `GET /worlds/{world_id}/player-sessions/resume?worldline_id=...&player_actor_id=...`
- `POST /worlds/{world_id}/player-sessions/resume`

The service validates world membership, worldline, player actor ownership, conversation scope,
scene scope, turn scope, presentation scope, and safe media/recovery fallback status before
returning a player-safe DTO.

## Recovery Model

`recovery_status` values:

- `ready`
- `stale_conversation`
- `missing_media`
- `provider_failure`
- `media_failure`
- `presentation_unavailable`

The DTO returns safe labels and actions only. Admin-only ledger details, media storage paths, raw
object metadata, prompt snapshots, raw event payloads, and provider internals stay out of the
player/member response.

## Web Plan

Extend `/worlds/{world_id}/player` to load the current resume state for the active player actor
when one exists. The panel shows:

- worldline and player identity
- conversation/scene/presentation pointers as IDs or names already present on the player page
- recovery status with short next action
- a restore link to the reader scene or playback page when a conversation exists
- a small form to update the safe resume pointers

This keeps the tester flow operational and explicit without creating a separate browser-only state
store.

## Tests

- create/read/update player resume state
- close/reopen resume through API read after write
- reject another tester's player actor/session
- reject cross-world and cross-worldline references
- stale conversation fallback
- missing media fallback
- provider/media failure fallback
- no raw event payload exposure
- no storage URI/path/base64/bytes/raw prompt/raw output/prompt snapshot/secret/invite token leaks
- Web unit test for the player resume panel

## Stop Conditions

- Multiple testers share mutable session state unintentionally.
- Resume requires raw event payloads or admin diagnostics.
- Session state conflicts with worldline isolation.
- Route/page state remains browser-only with no server-owned recovery contract.
- Implementation requires broad `worlds.py` route growth.
