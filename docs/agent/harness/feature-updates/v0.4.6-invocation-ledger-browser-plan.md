# v0.4.6 Invocation Ledger Browser Plan

## Goal

Implement the v0.4 Invocation Ledger Browser so world admins can inspect model invocation records, prompt snapshot evidence, tags, redaction state, visibility, and retention state from the Web workspace without exposing raw prompt data to reader/member surfaces or changing backend ledger behavior.

## Route Decision

- Add a world-scoped Web route at `/worlds/{worldId}/invocations`.
- Use the existing `/api/worlds/[...worldPath]` same-origin proxy for backend invocation ledger API calls.
- Add an `Invocations` link to the world workspace nav.
- Keep reader/member raw prompt exposure out of scope.

## Scope

- Add Web types and client helpers for invocation list/detail, prompt snapshots, tags, redaction, and safe search filters.
- Add a server data loader for invocation admin data using worlds, memberships, worldlines, recent invocations, tags for loaded invocations, and prompt snapshot summary for the selected invocation.
- Add an invocation ledger browser component with:
  - invocation overview metrics by status, redaction state, sensitive-context flag, and retention state;
  - filters for worldline, invocation kind, provider kind, status, visibility, redaction status, retention policy, sensitive-context flag, text search, and tags;
  - invocation list/detail showing IDs, related worldline/agent/conversation/turn/media/job refs, status, latency, estimated cost, visibility, redaction, retention, timestamps, and safe JSON summaries;
  - prompt snapshot detail gated behind admin route access and displayed as redacted/summarized evidence;
  - tag list/create/delete controls;
  - explicit redaction action using the existing backend redaction endpoint.
- Show raw prompt/output fields only on this world-admin route, and add visible labels for sensitive context and redaction status.
- Reuse v0.4.1 admin foundation components and existing invocation backend APIs.
- Add focused Web unit tests for client helpers, component behavior, filters, tag actions, redaction action, prompt snapshot rendering, workspace navigation, and leak-safe rendering.

## Non-goals

- No backend invocation ledger service behavior changes.
- No migrations.
- No new prompt snapshot storage or redaction model.
- No external tracing exporter.
- No public reader/member prompt or output exposure.
- No automatic retention purge UI beyond displaying existing retention fields.
- No provider execution, asset generation, daemon behavior, streaming, marketplace behavior, or diagnostics dashboard work.
- No storage URI, filesystem path, raw bytes, base64, resolved secret, or provider credential rendering.

## Guardrails

- The browser must rely on backend world-admin ACLs and must not bypass prompt snapshot permission checks.
- Prompt snapshots must remain within the admin workspace route and must not be added to reader/member pages, world events, or realtime public payloads.
- JSON summaries must recursively redact secret-like keys and path-like/media-uri/base64-like values before rendering.
- Invocation list/detail may display IDs and safe metadata summaries, but it must not render resolved provider secrets or media storage internals.
- Redaction must be an explicit admin action with a required reason and mode.
- Tag creation/deletion must use existing invocation tag APIs and backend worldline validation.
- UI copy should make ledger, provider, prompt snapshot, media, redaction, retention, and visibility boundaries easy to inspect.
