# v0.7.3 Cost & Rate Control Plan

## Goal

Add internal provider-spend guardrails for world/provider execution, media-backed provider jobs, asset generation proposal budgets, and provider-backed narrative quality generation.

This phase is backend/API/test focused. It should block unsafe or over-budget execution before external provider calls and expose safe admin quota status.

## Scope

- Add provider-owned budget policy persistence for:
  - per-world daily invocation limits
  - per-world daily estimated-cost limits
  - optional per-provider limits
  - reversible world/provider emergency stop
- Enforce provider budget checks in `ProviderExecutionService` before secret resolution and adapter execution.
- Record safe failed invocation/snapshot evidence for blocked execution.
- Mark associated non-terminal `media_jobs` failed when provider execution is blocked.
- Expose admin-only quota status and policy management under the existing providers API boundary.
- Reuse existing `asset_generation_policies` for asset-generation proposal/apply budget behavior.
- Add focused tests proving provider, image, speech, narrative quality, and asset-generation budget behavior.

## Non-goals

- No billing marketplace.
- No subscriptions or public user quota UX.
- No provider fallback or load balancing.
- No Web UI.
- No streaming.
- No broad `worlds.py` route growth.
- No runtime daemon auto-generation.
- No external observability exporter.

## Architecture Decision

Use the existing provider boundary for v0.7 Phase 3:

- Add a small provider budget service/model inside `backend/packages/providers/`.
- Add admin-only routes to `backend/services/api/src/noveland/services/api/providers.py`.
- Do not create a dedicated production-hardening package/router for this phase.

Rationale: paid external work already funnels through `ProviderExecutionService`. Provider-level enforcement covers direct provider tests, smoke tests, image, speech, and narrative quality provider-backed generation without new broad routing.

## Expected Migration

Add one migration for provider budget policies.

Suggested table:

- `provider_budget_policies`
  - `id`
  - `world_id`
  - `provider_id` nullable
  - `policy_key`
  - `status`
  - `emergency_stop_enabled`
  - `limits_json`
  - `metadata_json`
  - `created_at`
  - `updated_at`

The table must not store raw prompts, raw outputs, resolved secrets, storage URIs, filesystem paths, bytes, or base64.

## Guardrails

- Budget checks must run before secret resolution and before external adapter calls.
- Blocked execution must not mutate canonical world state.
- Blocked execution may write safe failed invocation/snapshot evidence and may fail a non-terminal associated media job.
- Quota status must include aggregate counts and cost estimates only.
- No response or persisted budget evidence may include raw prompts, raw outputs, resolved secrets, storage URIs, filesystem paths, bytes, or base64.
- Asset generation remains proposal/admin-apply only and must not execute providers in preview/apply.

## Stop Conditions

- Provider boundary cannot express the accepted budget policy without a new cross-cutting production-hardening router.
- Migration conflicts with the current Alembic head.
- Budget checks require raw prompt/output, storage path, or resolved secret exposure.
- Budget blocking would silently drop jobs or mutate canonical world state.
- Targeted tests or the full local gate fail.

## Targeted Tests

- Emergency stop blocks direct provider execution before secret resolution.
- Daily invocation limit blocks direct provider execution after the limit is reached.
- Daily estimated-cost limit blocks provider execution using existing `model_invocations.estimated_cost`.
- Smoke test returns safe failed evidence when blocked.
- Image generation creates no output asset and marks media job failed when blocked.
- Speech TTS creates no output asset and marks media job failed when blocked.
- Narrative quality provider-backed generation creates no proposal/artifact when blocked.
- Asset generation proposal budget continues to block excess proposals via existing `asset_generation_policies`.
- Quota status includes safe aggregate counts and excludes forbidden data.
