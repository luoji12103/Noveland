# v0.5.1 Authoring Import Core Plan

## Goal

Create the dedicated v0.5 authoring/import foundation for source registry, import runs, proposals, review decisions, source traceability, preview, and selective apply.

## Scope

- Add `backend/packages/authoring/` with contracts, models, services, and package exports.
- Add `backend/services/api/src/noveland/services/api/authoring.py` and register it at app level.
- Add core authoring migration after `20260512_0039`.
- Add source batch, source asset, source fragment, import run, proposal, review decision, and traceability records.
- Reuse `MediaService` for source media references and worldline validation helpers for strict target worldline scope.
- Implement preview/apply foundation without provider execution, automatic memory writes, direct lore/world-bible apply, or Web UI.

## Non-goals

- No parser/extractor implementation beyond minimal manual/source proposal creation.
- No provider-backed extraction.
- No asset matching automation.
- No direct apply to `WorldBible` or global canon tables.
- No automatic memory writes.
- No new media/provider/memory framework.
- No new routes in `worlds.py`.

## API Shape

- `GET/POST /worlds/{world_id}/authoring/source-batches`
- `GET /worlds/{world_id}/authoring/source-batches/{batch_id}`
- `POST /worlds/{world_id}/authoring/source-batches/{batch_id}/assets`
- `POST /worlds/{world_id}/authoring/source-assets/{source_asset_id}/fragments`
- `GET/POST /worlds/{world_id}/authoring/import-runs`
- `GET /worlds/{world_id}/authoring/import-runs/{run_id}`
- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/proposals`
- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/preview`
- `POST /worlds/{world_id}/authoring/import-runs/{run_id}/apply`
- `POST /worlds/{world_id}/authoring/proposals/{proposal_id}/review`

## Guardrails

- All core authoring records must carry `world_id` and non-null `worldline_id`.
- Source assets must reference existing `media_assets` in the same worldline.
- Preview must create proposals only and must not call providers.
- Apply must be explicit, selective, and proposal-kind gated.
- Unsupported proposal kinds, including lore/world-bible candidates in Phase 1, must remain unapplied.
- `world_events.payload` must not receive storage URIs, filesystem paths, raw bytes, base64, raw prompts, raw outputs, or full raw source bodies.
