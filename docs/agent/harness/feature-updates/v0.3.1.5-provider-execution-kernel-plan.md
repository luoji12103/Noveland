# v0.3.1.5 Provider Execution Kernel Phase 5 Plan

Date: 2026-05-11

## Summary

Phase 5 adds a provider execution kernel that all future text, image, audio,
vision, and workflow providers can route through. The kernel is a separate
`noveland-providers` package with world-scoped provider integrations,
capabilities, health checks, execution routing, fake providers for tests, Phase 3
invocation ledger writes, and Phase 4 media job/asset linkage.

Implementation flow:

1. Save this final plan and update harness docs on `main`.
2. Commit the docs-only planning checkpoint.
3. Create `feat/provider-execution-kernel`.
4. Implement backend package, migration, API router, and tests.
5. Run targeted and full local gates.
6. Fast-forward merge locally back to `main`.
7. Do not push until explicitly confirmed.

## Key Decisions

- Add `backend/packages/providers` rather than expanding `worlds.py`, media,
  invocations, or legacy provider profile modules.
- Keep existing `provider_profiles` as the legacy LLM provider profile table.
  Do not convert it into a universal provider registry.
- Add `provider_integrations.adapter_kind` as a required field from the initial
  migration.
  - `provider_kind` describes the capability family, for example
    `image_generation`, `text_to_speech`, or `speech_to_text`.
  - `adapter_kind` describes the concrete executor, for example `fake`,
    `openai`, `openai_compatible`, `comfyui`, `mimo_tts`, `mimo_asr`,
    `omnivoice`, `gpt_sovits`, or `custom_http`.
  - Dispatch uses `adapter_kind`; never infer adapter behavior from
    `provider_key`, and never let `config_json` silently override adapter
    selection.
- Use `model_invocations` and `prompt_snapshots` as the canonical model-call
  ledger for all provider executions.
- Use `media_jobs`, `media_assets`, and `media_objects` for fake image/audio
  outputs.
- Do not write storage URIs, bytes, base64, filesystem paths, raw prompts, or raw
  outputs into `world_events.payload`.

## API Changes

Add an independent world-scoped router in
`backend/services/api/src/noveland/services/api/providers.py`:

- `GET /worlds/{world_id}/providers`
- `POST /worlds/{world_id}/providers`
- `GET /worlds/{world_id}/providers/{provider_id}`
- `PATCH /worlds/{world_id}/providers/{provider_id}`
- `DELETE /worlds/{world_id}/providers/{provider_id}`
- `GET /worlds/{world_id}/providers/{provider_id}/capabilities`
- `POST /worlds/{world_id}/providers/{provider_id}/health-check`
- `POST /worlds/{world_id}/providers/test-invocation`

ACL defaults:

- World admins can manage world-scoped providers for their world.
- Platform admins can manage global providers and restricted records.
- World members, players, and readers cannot manage providers.
- Mutating routes require CSRF.
- `auth_ref` is write-only and is never returned in API responses.

## Execution Behavior

- `ProviderRegistryService` handles create/update/list/get, capability updates,
  and world-over-global capability resolution.
- `ProviderHealthService` records health checks and delegates checks by
  `adapter_kind`.
- `ProviderExecutionService.execute()` resolves the integration, validates
  same-world/same-worldline media references, creates a pending invocation and
  prompt snapshot, dispatches to the adapter, then updates ledger status and
  snapshot output.
- The fake adapter supports:
  - `text_generation`: deterministic text result plus invocation ledger.
  - `image_generation`: deterministic fake image bytes, media job, asset,
    object, invocation ledger, and links.
  - `speech_to_text`: deterministic transcript plus invocation ledger.
  - `text_to_speech`: deterministic fake audio bytes, media job, asset, object,
    invocation ledger, and links.
- Provider-kind and adapter-kind compatibility is validated in service logic.

## Assumptions

- Phase 5 does not implement real OpenAI image, OpenAI speech, ComfyUI, MiMo,
  OmniVoice, GPT-SoVITS, streaming, complex retry/load balancing, Web UI, or
  provider profile refactors.
- Fake image/audio bytes are deterministic local fixtures stored through the
  Phase 4 media storage abstraction.
- Later Phase 6 and Phase 7 will add concrete image and speech adapters after
  checking current official provider docs.
