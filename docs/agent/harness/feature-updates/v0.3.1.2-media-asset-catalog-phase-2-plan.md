# v0.3.1.2 Media Asset Catalog Phase 2 Plan

## Summary

Implement Media Asset Catalog / Tag Index on top of Phase 1 Media Kernel.
Phase 2 adds tags, collections, collection items, asset search, and
visibility-safe references/lineage enrichment. It does not add providers,
upload/download APIs, Web UI, invocation ledger, performance annotations, or
pgvector search.

Recommended implementation branch: `feat/media-asset-catalog`.

## API And Search Semantics

Extend `backend/services/api/src/noveland/services/api/media.py`; do not add
routes to `worlds.py`.

Route order requirement:

- Register `GET /worlds/{world_id}/media/assets/search` before
  `GET /worlds/{world_id}/media/assets/{asset_id}`.

Routes:

- `GET /worlds/{world_id}/media/assets/search`
- `GET /worlds/{world_id}/media/assets/{asset_id}/tags`
- `POST /worlds/{world_id}/media/assets/{asset_id}/tags`
- `PATCH /worlds/{world_id}/media/assets/{asset_id}/tags/{tag_id}`
- `DELETE /worlds/{world_id}/media/assets/{asset_id}/tags/{tag_id}`
- `GET /worlds/{world_id}/media/collections`
- `POST /worlds/{world_id}/media/collections`
- `GET /worlds/{world_id}/media/collections/{collection_id}`
- `PATCH /worlds/{world_id}/media/collections/{collection_id}`
- `DELETE /worlds/{world_id}/media/collections/{collection_id}`
- `GET /worlds/{world_id}/media/collections/{collection_id}/items`
- `POST /worlds/{world_id}/media/collections/{collection_id}/items`
- `PATCH /worlds/{world_id}/media/collections/{collection_id}/items/{item_id}`
- `DELETE /worlds/{world_id}/media/collections/{collection_id}/items/{item_id}`

Search filters:

- `worldline_id`
- `asset_kind`, `asset_role`, `source_kind`, `status`, `visibility`
- `has_alpha`, `mime_type`, `provider_kind`
- `used_by_agent_id`, `used_in_conversation_id`, `used_in_turn_id`,
  `used_in_world_event_id`
- `collection_id`
- `contains_text`
- repeatable `tag`

Repeatable `tag` query encoding:

- Format: `tag=tag_type:tag_key:tag_value`.
- Split only on the first two `:` characters.
- `tag_type` and `tag_key` must not contain `:`.
- `tag_value` may contain `:`.
- Invalid encodings return 422.
- Repeated `tag` filters use AND semantics.

`contains_text`:

- Search only `media_assets.title` and `media_assets.description`.
- Do not search `metadata`, `storage_uri`, `preview_uri`, or `thumbnail_uri`.
- Trim input.
- Max length: 120 characters.
- If the parameter is present but trims to empty, return 422.
- If the parameter is absent, ignore the filter.

## Visibility And Worldline Rules

All new rows must include `world_id` and `worldline_id`.

All tag, collection, and collection item mutations must validate same world and
same worldline:

- tag asset must match tag worldline.
- collection owner agent must belong to the same world.
- collection item asset must match collection worldline.
- collection item cannot reference deleted assets.

Visibility rules:

- Admin/platform admin reads can see all catalog records and full counts.
- Member reads require asset visibility AND matched tag visibility AND collection
  visibility.
- Member-visible values are `world_member`, `player_visible`, and
  `reader_visible`.
- Member search must not match private, admin-only, developer-only, or hidden
  tags/collections.
- Hidden tags must not affect member-visible result membership, ranking, counts,
  or response shape.
- Member references/lineage must not expose hidden asset IDs, tag IDs,
  collection IDs, or hidden counts.
- Member references/lineage returns only visible items and visible counts.

Do not write media paths, storage URIs, preview URIs, thumbnail URIs, or base64
into `world_events.payload`.

## Indexing Strategy

Add indexes:

- `media_asset_tags`
  - `(world_id, worldline_id, tag_type, tag_key, tag_value)`
  - `(world_id, worldline_id, visibility)`
  - `(asset_id)`
  - unique tag identity constraint
- `media_asset_collections`
  - `(world_id, worldline_id, collection_kind)`
  - `(world_id, worldline_id, visibility)`
  - `(world_id, worldline_id, status, created_at)`
  - `(owner_agent_id)`
- `media_asset_collection_items`
  - `(collection_id, display_order)`
  - `(asset_id)`
  - `(world_id, worldline_id, asset_id)`

Do not add pgvector, similarity search, or full-text GIN indexes in Phase 2.

## Risks And Deferrals

- Recursive lineage traversal is deferred; Phase 2 keeps direct one-hop
  inputs/outputs.
- Asset embeddings, similarity search, pgvector, upload/download, provider
  execution, model invocation ledger, performance annotations, and Web asset
  browser are deferred.
- `narrative_artifact_id` media contexts remain rejected until
  `narrative_artifacts` gains first-class `worldline_id`.
- Mixed-visibility collections are allowed for admin organization, but member
  reads filter invisible items without exposing hidden counts.
- Tags can encode sensitive semantics, so tag visibility is enforced
  independently from asset visibility.
