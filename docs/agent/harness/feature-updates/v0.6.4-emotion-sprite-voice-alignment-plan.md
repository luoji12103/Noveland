# v0.6.4 Emotion/Sprite/Voice Alignment Plan

## Goal

Implement API-first diagnostics that check whether a conversation turn presentation has coherent emotion, sprite variant, and voice profile/style bindings.

## Scope

- Add admin-only narrative quality alignment API.
- Reuse `conversation_turn_presentations`.
- Reuse visual sprite set/variant and background records.
- Reuse speech voice profiles, voice bindings, and style mappings.
- Return deterministic findings and suggested fixes only.

## Non-goals

- No Web dashboard or UI.
- No automatic visual or speech binding changes.
- No provider calls.
- No media generation or media job creation.
- No turn text mutation.
- No migration unless implementation proves persistent alignment records are required.
- No broad `worlds.py` routes.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/presentations/alignment`

Request fields:

- `worldline_id`
- `conversation_id`
- `turn_id`
- optional `allow_missing_assets`

Response fields:

- `world_id`
- `worldline_id`
- `conversation_id`
- `turn_id`
- `alignment_status`
- `emotion_key`
- `sprite_variant_id`
- `voice_profile_id`
- `findings`
- `suggested_fixes`
- `evidence_refs`
- `diagnostics`

## Diagnostic Rules

- Missing presentation returns actionable error/finding.
- Missing emotion, sprite variant, or voice profile produces warning unless explicitly allowed.
- Sprite variant expression/mood tags should match or reasonably cover emotion.
- Voice profile/style mapping should exist for the speaker/emotion when speech style is expected.
- Cross-worldline or cross-world references are rejected.
- Responses must not expose media storage URI, path, base64, bytes, raw prompt, raw output, or secrets.

## Tests

- Passes aligned emotion/sprite/voice presentation.
- Detects missing sprite variant.
- Detects missing voice profile or binding.
- Detects emotion/sprite mismatch.
- Rejects cross-worldline presentation/turn.
- API requires world admin ACL and CSRF.
- No event payload pollution or unsafe response strings.

## Validation

- Targeted backend tests for narrative quality service/API.
- `openspec validate --changes --strict`
- `openspec validate --specs --strict`
- Full local gate before fast-forward merge.
