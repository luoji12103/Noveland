# v0.3.1.6 Image Provider & Visual Asset Pipeline Phase 6 Plan

Date: 2026-05-11

## Summary

Phase 6 builds on Phase 3 invocation ledger, Phase 4 media kernel, and Phase 5
provider execution kernel. It adds the first image provider and visual asset
pipeline: image generation, image edit, deterministic local composition, OpenAI
image request mapping, OpenAI-compatible image mapping, and a minimal remote
ComfyUI workflow adapter contract.

Implementation flow:

1. Save this final plan and update harness docs on `main`.
2. Commit the docs-only planning checkpoint.
3. Create `feat/image-provider-visual-pipeline`.
4. Implement backend image services, provider adapters, routes, and tests.
5. Run targeted and full local gates.
6. Fast-forward merge locally back to `main`.
7. Do not push until explicitly confirmed.

## API Changes

Add world-scoped image routes:

- `POST /worlds/{world_id}/images/generate`
- `POST /worlds/{world_id}/images/edit`
- `POST /worlds/{world_id}/images/compose`
- `GET /worlds/{world_id}/images/jobs/{job_id}`

Core contracts:

- `ImageGenerateRequest`: `worldline_id`, `provider_id`, `prompt`,
  optional `negative_prompt`, `asset_role`, optional existing `media_job_id`,
  reference asset IDs, output kind/size/background preference, and metadata.
- `ImageEditRequest`: `worldline_id`, `provider_id`, prompt, input assets,
  optional mask asset, output role, and metadata.
- `ImageComposeRequest`: `worldline_id`, background asset, ordered layers with
  position/size/opacity/z-index/blend mode, output role, and metadata.
- `ImageResult`: media job, output asset, output objects, and optional model
  invocation ID.

ACL defaults:

- Image generation/edit/compose routes require world admin or platform admin and
  CSRF.
- The image job read route follows the media job visibility/admin pattern.
- Restricted media assets (`developer_only`, `hidden`) require platform admin.

## Execution Behavior

- Provider-backed generate/edit routes create a media job, execute through
  `ProviderExecutionService`, write `model_invocations` and `prompt_snapshots`,
  store output media objects, link invocation/media records, and return a unified
  image result.
- OpenAI image adapters only implement a minimal stable subset:
  `prompt`, `model`, `size`, output format, background preference when supported
  by capabilities/config, and input/mask assets for edit.
- Transparent background is capability-gated. If requested as `require` and the
  provider lacks `supports_transparent_background`, return a validation error.
- ComfyUI adapter uses remote endpoint/config only: base URL, workflow template
  JSON, input mapping JSON, output mapping JSON, optional auth ref. If real
  workflow polling is too broad for this phase, keep the adapter dry-run
  compatible but keep request/response mapping fixed.
- Deterministic compose is not a model call. It writes media job plus output
  media asset/object and does not write a model invocation.
- Do not write storage URIs, file paths, bytes, base64, raw prompts, or raw
  outputs into `world_events.payload`.
- Do not add character sprite tables unless implementation proves media asset
  metadata cannot express the first version.

## Assumptions

- Phase 6 does not add Web UI, public reader delivery, background scheduling,
  WebSockets/progress streaming, rembg, SAM2, IP-Adapter, ControlNet,
  LayerDiffuse, local ComfyUI installation, or high-level queue orchestration.
- Provider credentials remain referenced by `auth_ref`; tests use mocked HTTP or
  fake providers only.
- No push is performed after merge.
