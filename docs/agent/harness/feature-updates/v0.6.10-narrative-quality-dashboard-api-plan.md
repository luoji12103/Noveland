# v0.6.10 Narrative Quality Dashboard/API Plan

## Goal

Implement the final v0.6 API-first narrative quality dashboard summary under the dedicated narrative quality boundary. The phase should aggregate already-implemented v0.6 quality signals into an admin-scoped, dashboard-ready API response without adding Web UI, runtime mutation, provider execution, schema changes, or broad `worlds.py` routes.

## Scope

- Add a read-only narrative quality dashboard/API summary endpoint.
- Reuse `backend/packages/narrative_quality/` and `narrative_quality.py`.
- Summarize existing v0.6 quality surfaces:
  - runtime context readiness
  - provider-backed GM proposal readiness
  - dialogue/OOC review evidence
  - emotion/sprite/voice alignment readiness
  - Narrative Writer v2 artifact evidence
  - Continuity Review v2 results
  - runtime pacing diagnostics
  - route and relationship progression signals
  - long-run eval status
- Reuse existing persistence and services; do not create a dashboard table.
- Return safe metrics, blockers, warnings, recommendations, and evidence refs.
- Validate `world_id` and `worldline_id` scope.
- Keep the response admin-only and safe for later Web use.
- No migration expected.

## Non-goals

- No Web dashboard routes, components, or e2e scenarios.
- No provider calls.
- No runtime daemon execution.
- No media generation or asset generation apply.
- No state mutation, review creation, eval run creation, or world event writes.
- No public reader/member delivery.
- No broad new `worlds.py` routes.
- No duplicate eval/release/dashboard framework.
- No raw prompt, raw output, prompt snapshot payload, storage URI, filesystem path, bytes, base64, or resolved secret exposure.

## API Shape

- `GET /worlds/{world_id}/narrative-quality/dashboard`

Query fields:

- `worldline_id` optional; defaults through existing worldline resolution.

Response fields:

- `world_id`
- `worldline_id`
- `quality_status`
- `summary`
- `metrics`
- `blockers`
- `warnings`
- `recommendations`
- `evidence_refs`
- `diagnostics`
- `generated_at`

## Diagnostic Rules

- Missing text-generation provider readiness is a warning, not a provider call.
- Recent failed provider health checks are warnings or blockers based on status.
- Failed or missing long-run eval evidence is surfaced in metrics and recommendations.
- Continuity review failures are blockers.
- Open high-risk GM proposals are warnings.
- Missing presentation coverage, sprite defaults, or voice bindings are warnings.
- Pending pacing media jobs and asset proposals are summarized without mutation.
- World event payload leak indicators become blockers.
- Dashboard output is recursively sanitized before returning.

## Reuse Boundaries

- Use `NarrativeQualityService` for dashboard aggregation.
- Reuse `LongRunEvalRun`, `NarrativeContinuityReview`, `GMEventProposal`, `ConversationTurnPresentation`, visual/speech records, provider integration/health records, media jobs, asset generation proposals, model invocations, and world events.
- Reuse existing `_sanitize_json` and safe evidence-ref patterns.
- Preserve existing v0.4 multimodal diagnostics APIs; this phase does not replace them.
- Preserve existing release/beta gate semantics.

## Tests

- Dashboard summary returns dashboard-ready metrics for a seeded worldline.
- Dashboard detects continuity failures as blockers.
- Dashboard detects provider health/config warnings without resolving secrets or calling providers.
- Dashboard detects missing sprite default or missing voice binding warnings.
- Dashboard detects unsafe `world_events.payload` indicators as blockers.
- Dashboard response is sanitized.
- API requires world admin ACL.
- API rejects cross-worldline access.
- Dashboard performs no provider call, eval run creation, media job mutation, or world event write.
