# v0.6.5 Narrative Writer v2 Plan

## Goal

Implement an API-first Narrative Writer v2 path that generates reader-safe narrative drafts from a strict worldline context using the provider execution kernel.

## Scope

- Add first-class nullable `worldline_id` columns to `narrative_artifacts` and `narrative_publications`.
- Keep legacy rows nullable; do not backfill historical data.
- Require non-null `worldline_id` for new v2 writer-created artifacts.
- Add an admin-only narrative quality writer generation API.
- Reuse `ProviderExecutionService` for text generation.
- Reuse `NarrativeArtifactService` for draft persistence.
- Reuse `LivingWorldContextSelector` and conversation turns for prompt context.
- Persist safe traceability metadata, including provider and invocation references.

## Non-goals

- No Web dashboard or UI.
- No broad `worlds.py` routes.
- No legacy provider profile expansion.
- No real external text provider adapter work.
- No automatic publication.
- No automatic world-state mutation.
- No `world_events.payload` writes.
- No narrative artifacts as media storage.
- No raw prompt, raw output, storage URI, filesystem path, bytes, base64, or resolved secret exposure.
- No historical data backfill.

## Worldline Strategy

`narrative_artifacts.worldline_id` and `narrative_publications.worldline_id` become the first-class isolation fields for v2.

Migration behavior:

- Add both columns as nullable to avoid requiring historical backfill.
- Add foreign keys to `worldlines.id` with `ON DELETE SET NULL`.
- Add worldline-focused indexes for listing and publication queries.

Write-path behavior:

- v2 writer requests must resolve a concrete worldline.
- v2-created artifacts must store that worldline in the new column.
- v2 artifact metadata may keep `worldline_id` as compatibility evidence only.
- v2 publication rows, when later created, must match the artifact worldline.
- Legacy metadata-only worldline values do not satisfy v2 isolation authority.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/writer/generate`

Request fields:

- `worldline_id`
- optional `conversation_id`
- optional `provider_id`
- optional `capability_key`
- optional `model_name`
- `artifact_kind`: `conversation_summary` or `chapter_draft`
- optional `title`
- `prompt_goal`
- optional `provider_request_json`
- `context_limit`
- `dry_run`

Response fields:

- `world_id`
- `worldline_id`
- `dry_run`
- `provider`
- `invocation`
- `artifact`
- `diagnostics`
- `evidence_refs`

## Behavior

- Resolve and validate the requested worldline.
- If a conversation is provided, require same worldline.
- Resolve a text generation provider through the provider registry.
- Accept only provider-kernel text execution adapters currently supported by `ProviderExecutionService`.
- Build a prompt from safe living-world context, recent conversation turns, and the requested writing goal.
- Execute provider text generation through `ProviderExecutionService`.
- For `dry_run=true`, write invocation evidence but do not persist a narrative artifact.
- For `dry_run=false`, create a draft `narrative_artifact` with non-null `worldline_id`.
- Do not publish the artifact.
- Do not append world events.
- Return safe text only through the admin-scoped narrative quality API.

## Tests

- Generate a v2 draft with a fake text provider and persist non-null `worldline_id`.
- Dry run writes invocation evidence but creates no artifact.
- Reject cross-worldline conversation input.
- Reject non-text providers.
- Reject unsafe request JSON.
- Ensure prompt snapshots and invocations are written through the provider kernel.
- Ensure v2 artifact metadata is safe and does not contain raw prompt/output, storage URI, path, bytes, base64, or secrets.
- Ensure API requires world admin ACL and CSRF.
- Ensure member routes cannot access the new writer endpoint.
- Ensure schema metadata includes new worldline columns, foreign keys, and indexes.
- Ensure no `world_events` are written by writer generation.
