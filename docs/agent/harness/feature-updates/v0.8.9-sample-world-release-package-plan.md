# v0.8.9 Sample World Release Package Plan

## Status

Planned for implementation after v0.8 Phase 8 Plugin/Provider Package Contract passed the full local gate and fast-forward merged to local `main`.

## Goal

Create a deterministic sample world release package that links the Phase 13 multimodal sample-world fixture to v0.8 world packaging, reader-safe playback expectations, rights metadata, and diagnostics evidence.

## Scope

- Backend/test/docs only first implementation.
- Add a lightweight sample release package fixture helper, not a production seed framework.
- Build a safe `WorldPackageManifest` from the existing multimodal sample world fixture.
- Include content rights, source, visibility, fixture linkage, expected records, and diagnostics evidence in manifest-safe metadata.
- Validate import preview/apply through `WorldPackagingService`.
- Verify reader-safe playback/scene-relevant media is represented by safe media manifest entries.
- Add deterministic package, import preview/apply, rights/visibility, diagnostics, and leak tests.

## Proposed Boundary

- Test fixture helper: `backend/tests/fixtures/sample_world_release_package.py`
- Regression tests: `backend/tests/test_sample_world_release_package.py`
- Documentation: `docs/agent/fixtures/sample-world-release-package.md`

The first implementation stays in tests/docs. It does not introduce runtime package records or a production seed CLI.

## Package Shape

The sample release package should contain:

- Package metadata with manifest version, package key, generated timestamp, and capabilities.
- Safe world metadata derived from the Phase 13 fixture.
- Primary worldline metadata.
- One scene.
- Media manifest entries for:
  - background
  - neutral/happy/sad sprites
  - TTS audio
  - STT source audio
  - composite image
- Portable references for scene, conversation turn/presentation, sprite, speech, and diagnostics linkage.
- Explicit rights metadata for every media entry.
- Fixture linkage metadata that identifies the Phase 13 fixture source and expected record counts.
- Diagnostics/eval evidence refs only, not raw prompt/output or storage data.

## Import Discipline

- Build the sample package from fixture records through safe DTOs.
- Run import preview first and assert no blockers.
- Run import apply only in tests after preview passes.
- Apply may create a safe imported world/worldline/scene and placeholder media metadata through existing world packaging behavior.
- Do not copy media bytes or create `MediaObject` records from the sample package in Phase 9.

## Migration Decision

No migration for Phase 9 first implementation. The sample release package is a deterministic test fixture and docs artifact. If future public distribution requires persisted release package records, stop and add a dedicated migration plan first.

## Tests

- Sample package builds deterministically from the Phase 13 fixture.
- Package metadata includes fixture linkage and expected record counts.
- Every media manifest entry has explicit rights/source/visibility metadata.
- Import preview returns no blockers and creates no records.
- Import apply creates safe placeholder world/worldline/scene/media metadata only.
- Reader playback/scene media roles are represented in the manifest.
- Diagnostics/eval evidence refs are included without raw evidence.
- No storage URI, filesystem path, object storage path, bytes/base64, raw prompt/output, prompt snapshot internals, or resolved secrets leak from the manifest or preview/apply responses.

## Guardrails

- No production seed framework.
- No migrations.
- No Web UI.
- No provider execution.
- No daemon jobs or automatic spend.
- No public marketplace.
- No copyrighted or unlicensed raw source content.
- No direct storage path, storage URI, bytes/base64, raw prompt/output, prompt snapshot internals, or resolved secrets.
