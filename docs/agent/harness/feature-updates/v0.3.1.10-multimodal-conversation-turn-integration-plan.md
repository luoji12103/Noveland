# v0.3.1.10 Multimodal Conversation Turn Integration Phase 10 Plan

## Summary

Phase 10 adds backend/API-only conversation turn presentation state and render orchestration. Each conversation turn can carry structured emotion, selected sprite, voice profile, background, composite scene, TTS audio, and STT transcript references without changing `conversation_turns.input_text` or `conversation_turns.output_text`.

This phase reuses Phase 9 visual resolvers, Phase 6 `ImageService.compose_image()`, Phase 7 `SpeechService`, and Phase 4 `media_references`. It does not add Web preview/playback UI, public reader delivery, streaming, daemon execution, or memory auto-write from STT.

## API Scope

- `GET /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/presentation`
- `PUT /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/presentation`
- `PATCH /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/presentation`
- `POST /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/render-visual`
- `POST /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/render-speech`
- `POST /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/transcribe-audio`

## Service Rules

- Resolve the conversation turn from the route, then derive and enforce the conversation worldline.
- Validate every referenced sprite set, sprite variant, voice profile, transcript, and media asset is same world and same worldline.
- Keep one canonical presentation per turn via unique `turn_id`.
- Render visual:
  - use Phase 9 `VisualResolver` to resolve sprite/background
  - compose scene through `VisualCompositionService`, which delegates to `ImageService.compose_image()`
  - attach sprite, background, and composite assets to the turn through `MediaReferenceService`
  - update presentation IDs and render state
- Render speech:
  - use `SpeechService.text_to_speech()`
  - resolve agent default voice profile when explicit profile is not supplied
  - apply emotion/style mapping through existing speech service behavior
  - attach TTS audio to the turn through existing speech/media reference behavior
  - update presentation IDs and render state
- Transcribe audio:
  - use `SpeechService.speech_to_text()`
  - store transcript and set `transcript_id`
  - attach source audio to the turn through existing speech/media reference behavior
  - do not mutate turn text and do not enqueue memory writes
- No `world_events.payload` writes.
- API responses must not expose storage URIs, file paths, bytes, base64, raw prompts, or raw provider outputs.
