# v0.8.1 Reader Media Delivery Plan

Date: 2026-05-15
Branch: `main`

## Goal

Implement reader-safe media delivery as an authenticated, application-mediated backend/API boundary. This phase gives later playback and galgame UI work a stable descriptor/download contract without exposing admin media DTOs or storage internals.

## Accepted Decisions

- Delivery is authenticated only for the first implementation.
- No public unauthenticated media delivery is added.
- Canonical delivery is application-mediated streaming/download.
- Optional opaque media tokens are deferred unless they still resolve through app authorization.
- Direct `storage_uri`, filesystem paths, object storage paths, S3/GCS URLs, long-lived signed URLs, bytes, base64, raw prompts, raw outputs, and resolved secrets must not appear in reader/member/player responses.
- Asset visibility alone is insufficient. A reader-deliverable asset must pass the visibility-policy intersection:
  - caller has world access;
  - asset status is `available`;
  - asset visibility allows reader/member/player delivery;
  - object belongs to the asset and is deliverable;
  - media reference links the asset to a reader-visible context;
  - referenced publication, conversation turn, or presentation belongs to the same worldline and is visible to the caller;
  - hidden, developer-only, and private assets are suppressed unless a platform-admin/internal path explicitly allows them.
- The implementation uses a dedicated reader delivery boundary:
  - package: `backend/packages/reader_delivery/`
  - router: `backend/services/api/src/noveland/services/api/reader_media.py`
- The admin media router remains unchanged.

## Existing Route Inventory

- Admin/member media routes live under `backend/services/api/src/noveland/services/api/media.py`.
- Existing download route: `GET /worlds/{world_id}/media/objects/{object_id}/download`.
  - It is world-admin scoped.
  - It returns bytes through existing media storage.
  - It must not become the reader contract.
- Narrative reader routes currently use narrative publication filtering under `worlds.py` and Web reader surfaces.
  - Published narrative filtering already respects `NarrativePublication.status == published` and `reader_visible`.
  - Reader media needs to bind media assets to published narrative artifacts, conversation turns, and presentation records through safe references.

## Implementation Scope

- Add `noveland.reader_delivery` package with contracts and service.
- Add `reader_media.py` router and register it at app level.
- Add endpoints:
  - `GET /worlds/{world_id}/reader/media`
  - `GET /worlds/{world_id}/reader/media/{asset_id}`
  - `GET /worlds/{world_id}/reader/media/objects/{object_id}/download`
- Responses expose safe descriptors only:
  - asset id, object id, world id, worldline id;
  - asset kind/role, title, description, content type, size, dimensions/duration;
  - visibility label and reader delivery URL;
  - safe reference summaries.
- Download endpoint streams/returns bytes through `MediaService`/media storage with safe content type.
- No migration is expected.

## Visibility Rules

- `reader_visible`, `player_visible`, and `world_member` media visibility can be delivered to world members/readers/players after reference visibility passes.
- `private`, `world_admin`, `developer_only`, `hidden`, deleted, failed, or registered-only assets are not reader-deliverable.
- Platform-admin/internal routes are out of scope for Phase 1; this phase is reader-safe by default.
- Cross-world and cross-worldline assets, objects, references, publications, conversations, and presentations are rejected or omitted.

## Tests

- Authenticated reader/member can list and fetch reader-visible published media.
- Unauthenticated request is rejected.
- Hidden, developer-only, private, unavailable, deleted, and unreferenced assets are suppressed or rejected.
- Cross-world and cross-worldline objects/references are rejected.
- DTOs contain no `storage_uri`, path, base64, bytes, raw prompt, raw output, or secret markers.
- Download streams bytes with safe content type.
- Admin media download behavior remains unchanged.

## Stop Conditions

- Reader auth model becomes unclear.
- Any response would need to expose storage internals.
- Any implementation path needs broad `worlds.py` growth.
- Any schema migration becomes necessary without updating this checkpoint first.
- The implementation duplicates the media storage framework.
