# v0.6.9 Long-run Living World Simulation Eval Plan

## Goal

Implement an API-first long-run living world simulation eval entrypoint under the narrative quality boundary. The phase should reuse existing `LongRunEvalRun` persistence and `LivingWorldBetaService.run_long_eval()` metrics while returning v0.6 quality-oriented drift metrics, blocker summaries, failure reports, and safe recommendations.

## Scope

- Add admin-only narrative quality long-run eval API.
- Reuse `LongRunEvalRun`; do not create a duplicate eval table.
- Reuse `LivingWorldBetaService.run_long_eval()` for persisted eval runs.
- Reuse existing world events, GM proposal, route, relationship, player-choice, narrative artifact, publication, continuity review, diagnostics, and traceability metrics.
- Add a response contract that summarizes drift/failure quality signals for v0.6.
- Add optional list/get helpers under narrative quality only if needed for testable API-first workflow.
- Keep output dashboard-ready but backend/API-only.
- No migration expected.

## Non-goals

- No external observability platform.
- No human scoring system.
- No provider calls.
- No runtime daemon simulation or automatic world advancement.
- No Web dashboard or UI.
- No broad `worlds.py` routes.
- No duplicate eval/release framework.
- No raw prompt, raw output, storage URI, filesystem path, bytes, base64, or resolved secret exposure.
- No world event writes outside existing eval persistence.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/long-run-evals/run`
- `GET /worlds/{world_id}/narrative-quality/long-run-evals`
- `GET /worlds/{world_id}/narrative-quality/long-run-evals/{run_id}`

Request fields:

- `worldline_id`
- `eval_key` default `narrative-quality-long-run`
- `horizon_days` default 7, bounded 1-90
- `metadata` optional safe JSON

Response fields:

- `world_id`
- `worldline_id`
- `run_id`
- `eval_key`
- `horizon_days`
- `status`
- `drift_metrics`
- `failure_reports`
- `blockers`
- `recommendations`
- `evidence_refs`
- `diagnostics`

## Diagnostic Rules

- Event scarcity or missing worldline events is a failure report.
- Sparse relationships, route milestones, ending candidates, GM proposals, daily candidates, player choices, narrative artifacts, and publications become drift or readiness metrics.
- Continuity failures and warning counts become narrative-break signals.
- Traceability ref counts become evidence quality signals.
- Unsafe metrics/recommendation metadata is sanitized before API response.
- Existing `LongRunEvalRun.status` remains the source of eval status.

## Reuse Boundaries

- Use the `narrative_quality` package/router for new v0.6 API and service code.
- Use `LongRunEvalRun` and `LivingWorldBetaService`; do not duplicate eval persistence.
- Preserve existing `/worlds/{world_id}/long-run-evals` behavior.
- Preserve existing release/beta gate semantics.
- Preserve Phase 13 guardrails for secrets, media paths, raw prompts/outputs, and worldline isolation.

## Tests

- Run long-run narrative quality eval persists a `LongRunEvalRun`.
- Response includes drift metrics and failure reports derived from existing eval metrics.
- List/get long-run narrative quality evals are worldline scoped.
- Cross-worldline get is rejected.
- Sensitive metadata is rejected or sanitized before persistence/response.
- API requires world admin ACL and CSRF for run.
- Eval performs no provider call, daemon run, or world event write.
- Response contains no raw prompt, raw output, storage URI, filesystem path, bytes, base64, or secrets.
