# v0.8.11 Public Launch Gate Plan

Date: 2026-05-16
Branch: main
OpenSpec change: `v0-8-public-experience-ecosystem`

## Goal

Implement public launch readiness aggregation for v0.8 by reusing the v0.7 internal production readiness gate and adding public-surface evidence from v0.8. The gate remains admin-only, read-only by default, and never auto-launches a world.

## Architecture Decision

Use the existing observability/readiness boundary:

- Extend `backend/packages/observability/src/noveland/observability/contracts.py`.
- Extend `backend/packages/observability/src/noveland/observability/services.py`.
- Extend `backend/services/api/src/noveland/services/api/observability.py`.

Do not create a duplicate release/readiness package or tables. Do not add a migration. Do not add public/reader/member/player readiness routes.

## API Scope

Add platform-admin-only endpoint:

- `GET /observability/readiness/public-launch`

Request inputs:

- optional `world_id`
- optional explicit signoff flags such as `security_signoff`, `privacy_signoff`, `moderation_signoff`, `sample_world_signoff`, and `operator_signoff`
- existing production readiness tuning query params

Response:

- public readiness report with status, sections, blockers, warnings, evidence refs, suppressed fields, required signoffs, and explicit `auto_launch=false`.

## Evidence Inputs

The first implementation aggregates:

- v0.7 internal production readiness via `ProductionReadinessGateService`.
- Reader media delivery evidence from reader-visible `media_assets`, `media_objects`, and `media_references`.
- Playback/scene evidence from `conversation_turn_presentations`.
- Player privacy evidence from `player_privacy_requests`.
- Moderation evidence from `moderation_reports`, `moderation_actions`, and `moderation_incidents`.
- Sample world package evidence from the deterministic sample package test fixture markers and multimodal/sample eval records.
- Plugin/provider safety evidence from package contract capability being present and provider governance readiness sections.
- Security/public DTO safety evidence from existing v0.7/v0.8 security regression suites.
- Explicit signoff flags supplied by the platform admin.

## Behavior

- If internal production readiness is blocked, public launch readiness is blocked.
- If required public evidence is missing, readiness is blocked or warning depending on risk.
- If automated checks pass but explicit signoff flags are missing, readiness remains blocked.
- The report is safe for admin review and does not expose raw prompts, raw outputs, storage paths, resolved secrets, bytes, base64, hidden content bodies, or prompt snapshot internals.
- The gate does not mutate state, publish worlds, enable public unauthenticated access, execute providers, or write `world_events`.

## Tests

Targeted tests should cover:

- Public readiness fails when internal production readiness has blockers.
- Public readiness fails when moderation signoff is missing.
- Public readiness remains blocked when checks pass but signoffs are missing.
- Public readiness passes when internal readiness, public evidence, and all signoffs are present.
- Report redaction suppresses forbidden markers.
- Endpoint is platform-admin-only.
- No duplicate readiness/release framework tables.

## Non-Goals

- Public unauthenticated access.
- Automatic world launch or publication.
- Web dashboard/UI.
- New release/readiness persistence tables.
- Provider execution, daemon execution, marketplace behavior, or streaming.
- Broad `worlds.py` growth.
