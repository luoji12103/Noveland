# v1.1.2 Backup Restore Drill Plan

Date: 2026-05-21
Branch: `feature/v1.1-2-backup-restore-drill`
Scope: Phase 2 backend/API and docs checkpoint for a fresh local/single-host restore drill.

## Decision

Phase 2 will add a read-only backup/restore drill verifier that reuses the existing storage integrity audit and observability/readiness boundary. It will not add migrations, write drill records, run providers, expose storage paths, or create a new backup framework.

## Restore Target

The accepted target remains a fresh local/single-host profile:

- empty target database before restore;
- empty object storage root before restore;
- restored database dump;
- restored object/media payload archive;
- current code with migrations applied to head only when needed.

## Ownership

- Verification logic: `backend/packages/storage/src/noveland/storage/restore_drill.py`.
- Admin API/report surface: existing app-level `noveland.services.api.observability` router under `/observability/readiness/backup-restore-drill`.
- DTO exports: storage package and observability contracts as needed.

## Verification Scope

The drill report will verify:

- world and worldline records exist;
- conversations and turn presentations are present when expected;
- memory records exist when expected;
- storage integrity audit passes for media objects and snapshot payloads;
- provider integration config uses safe metadata and `auth_ref` only;
- OpenSpec current specs and archived v0.9/v1.0 provenance exist;
- report findings identify safe refs and failure types only.

## Safety Rules

The report must not expose resolved secrets, storage paths, object paths, raw prompts, raw outputs, bytes, base64, prompt snapshot internals, provider credentials, local model paths, or invite tokens. Provider config restore is metadata-only; resolved secrets must remain outside backup artifacts and reports.

## Tests

Add targeted backend tests for:

- complete restored fixture passes;
- missing media/checksum failure is reported safely;
- provider config export/restore report excludes secrets;
- worldline, conversation, presentation, and memory fixture state is counted;
- admin-only endpoint access;
- no forbidden marker leaks.

## Stop Conditions

Stop Phase 2 if:

- restore verification requires committed secrets;
- provider config cannot be separated from provider credentials;
- media/object verification needs storage paths in reader/player/member APIs;
- the drill needs a new persisted readiness framework;
- default tests require real provider calls.
