# v0.9.9 Demo World Assembly Plan

Date: 2026-05-17
Branch: `feat/v0.9-demo-world-assembly`
Scope: v0.9 Self-use MVP Demo World Cut Phase 9 only.

## Decision

Phase 9 stays backend/API/docs/tests only. No Web UI is added, so `impeccable` is not required. No migration is required because the first implementation can reuse authoring proposals, agents, worldlines, conversations, conversation turn presentations, visual bindings, voice bindings, visual generation profile records, media assets, and memory records.

Demo assembly is implemented as a reviewable authoring proposal with target `demo_world_assembly`. The assembly endpoint creates the proposal and an admin-visible safe report. Existing authoring review/apply then creates the playable conversation session, participants, seed turn, initial presentation references, and applied report. This keeps demo assembly behind preview/review/apply and avoids broad `worlds.py` routes.

## Boundaries

- No direct canon mutation or global launch state.
- No raw source, storage URI, filesystem path, object path, bytes, base64, raw prompt, raw output, prompt snapshot internals, or resolved secret exposure.
- No provider calls during assembly.
- No automatic apply of provider or AI output.
- No new Web UI.
- No broad `worlds.py` routes.
- No public launch or private beta readiness claim.

## Implementation Shape

- Add authoring contracts for a demo assembly request/result.
- Add `POST /worlds/{world_id}/authoring/import-runs/{run_id}/assemble-demo-world`.
- Validate 2-3 existing agents in the requested worldline.
- Require safe evidence for persona, memory, visual mappings, voice mappings, background, and reviewed dialogue when requested.
- Create a `demo_world_assembly` authoring proposal with safe IDs/counts and source evidence refs.
- Extend `AuthoringService.apply` to apply approved `demo_world_assembly` proposals.
- On apply, create a manual-chain conversation session, replace participants, seed an initial operator turn, and attach an initial turn presentation using reviewed visual/voice/background references where available.
- Return an applied report with conversation/session/turn/presentation IDs and safe status details.

## Tests

Targeted tests cover:

- Demo assembly proposal creation from reviewed/applied persona, memory, visual, voice, visual generation profile, and dialogue evidence.
- Explicit approval before apply.
- Conversation session, participants, seed turn, and turn presentation creation after apply.
- Blocking missing required persona/memory/visual/voice/dialogue evidence.
- Admin API access and member rejection.
- Source traceability preservation through proposal evidence and apply traces.
- No world-event writes and no secret/path/storage/base64/raw prompt/output leaks.

## Stop Conditions

- Stop if assembly requires direct DB edits as the primary workflow.
- Stop if source traceability cannot be preserved through reviewed proposals and safe refs.
- Stop if visual generation profiles must activate without review/apply.
- Stop if conversation entry requires provider calls or hidden external spend.
- Stop if Web UI becomes required and `impeccable` cannot be used first.
