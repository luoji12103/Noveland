# v0.6.7 Runtime Pacing Controller Plan

## Goal

Implement an API-first Runtime Pacing Controller diagnostic that explains whether a worldline's current conversation/media/asset-generation state is within safe pacing limits for active turns, lookahead work, offscreen compression, pending media jobs, and asset generation budget.

## Scope

- Add admin-only narrative quality pacing review API.
- Reuse existing `asset_generation_policies`, `asset_generation_runs`, `asset_generation_proposals`, and `media_jobs`.
- Reuse conversation sessions, turns, and turn presentations for active/current/lookahead context.
- Produce deterministic findings, budget summaries, queue summaries, and recommendations.
- Keep output dashboard-ready but backend/API-only.
- No migration expected.

## Non-goals

- No daemon auto-generation or daemon hook.
- No provider calls.
- No media job creation, reprioritization, cancellation, or automatic spend.
- No Web dashboard or UI.
- No broad `worlds.py` routes.
- No changes to asset-generation proposal/apply semantics.
- No raw prompt, raw output, storage URI, filesystem path, bytes, base64, or resolved secret exposure.
- No world event writes.

## API Shape

- `POST /worlds/{world_id}/narrative-quality/pacing/review`

Request fields:

- `worldline_id`
- optional `conversation_id`
- optional `current_turn_id`
- optional `policy_id`
- `lookahead_turns` default 2, bounded 0-20
- `max_pending_jobs` optional
- `max_pending_cost` optional
- `include_offscreen` default true

Response fields:

- `world_id`
- `worldline_id`
- `conversation_id`
- `current_turn_id`
- `pacing_status`
- `queue_summary`
- `budget_summary`
- `lookahead_summary`
- `offscreen_summary`
- `findings`
- `recommendations`
- `evidence_refs`
- `diagnostics`

## Diagnostic Rules

- Active/current turn missing required presentation assets is higher priority than lookahead or offscreen work.
- Pending media jobs above policy/request limit become a warning or error depending on severity.
- Queued/running jobs with duplicate `invalidation_key` become a supersession recommendation.
- Pending proposed asset-generation cost above policy/request limit becomes a budget finding.
- Lookahead beyond configured limit is reported, not executed.
- Offscreen conversations may be recommended for compression only as an advisory finding.
- Disabled or missing asset-generation policy is informational unless explicit limits are requested.

## Reuse Boundaries

- Use `narrative_quality` package/router for API and service code.
- Read existing asset generation policies/proposals/runs directly or through existing records; do not duplicate the subsystem.
- Read existing media jobs; do not create or mutate jobs in this phase.
- Preserve existing asset generation admin apply-only semantics.
- Preserve Phase 13 guardrails for secrets, media paths, raw prompts/outputs, and worldline isolation.

## Tests

- Review returns pass/warning with policy and pending media job summary.
- Excess pending media jobs produces a pacing finding.
- Duplicate invalidation keys produce a cancel-superseded recommendation.
- Budget overflow from proposed asset-generation work produces a budget finding.
- Current turn is prioritized over lookahead/offscreen context.
- Cross-worldline conversation/turn/policy is rejected.
- API requires world admin ACL and CSRF.
- Review performs no media job mutation, provider call, or world event write.
- Response contains no raw prompt, raw output, storage URI, filesystem path, bytes, base64, or secrets.
