# v0.8.10 Moderation & Incident Workflow Plan

Date: 2026-05-16
Branch: main
OpenSpec change: `v0-8-public-experience-ecosystem`

## Goal

Implement the first backend/API moderation and incident workflow for public-facing readiness. The phase creates reviewable report records, bounded moderator actions, safe audit summaries, and redacted incident evidence references without automatic public moderation.

## Architecture Decision

Moderation lives in a dedicated package and router:

- Package: `backend/packages/moderation/`
- Router: `backend/services/api/src/noveland/services/api/moderation.py`

This phase must not add broad routes to `worlds.py`. It reuses v0.7 observability incident diagnostics for safe evidence concepts, but it does not extend observability into a workflow ownership boundary. Observability remains derived diagnostics/readiness; moderation owns persisted public reports, review decisions, disable/takedown action records, and incident workflow records.

## Migration Scope

Add a migration after the current latest revision, `20260516_0043_player_privacy_requests`.

Planned tables:

- `moderation_reports`
- `moderation_actions`
- `moderation_incidents`

All report/action/incident records include `world_id`. Records that target worldline-scoped content include `worldline_id`; provider/global targets may leave `worldline_id` null only when the target is not worldline-scoped.

## API Scope

Dedicated backend/API routes only:

- `GET /worlds/{world_id}/moderation/reports`
- `POST /worlds/{world_id}/moderation/reports`
- `PATCH /worlds/{world_id}/moderation/reports/{report_id}`
- `GET /worlds/{world_id}/moderation/actions`
- `POST /worlds/{world_id}/moderation/actions`
- `GET /worlds/{world_id}/moderation/incidents`
- `POST /worlds/{world_id}/moderation/incidents`
- `PATCH /worlds/{world_id}/moderation/incidents/{incident_id}`

Reader/member/player callers may create safe reports for accessible worlds. World admins and platform admins may list/review reports and create/review moderation actions/incidents. Platform-admin-only actions may target global provider safety decisions.

## Safe Evidence Contract

Reports, actions, incidents, and API responses may contain:

- target kind/id
- world/worldline refs
- status, severity, category, reason code
- redacted reporter/admin notes
- evidence refs by kind/id/component/status
- timestamps and actor refs

They must not contain:

- resolved provider secrets
- `storage_uri`, object storage paths, filesystem paths, or signed storage URLs
- bytes, base64, or raw binary payloads
- raw prompt, raw output, prompt snapshot internals
- hidden/developer-only/private content bodies
- unredacted reporter private data in reader/member responses

## Behavior

- Creating a report persists a reviewable record with safe evidence refs.
- Reviewing a report changes status and records reviewed actor/timestamp/note.
- Creating an action records an explicit reviewed action proposal/application such as `disable_media`, `disable_world`, `disable_provider`, `rollback_review`, or `takedown_content`.
- The first implementation records action state and safe audit summary only. It must not automatically execute destructive rollback, provider disable, public takedown, daemon work, provider calls, or public launch changes.
- Incidents group reports/actions and provide admin-scoped workflow state for later launch-readiness aggregation.

## Reused Systems

- `WorldAccessContext` authorization dependencies.
- v0.7 `IncidentEvidenceRef` safe evidence shape.
- Provider status/governance records by reference only.
- Media/reader delivery visibility rules by target reference only.
- Worldline/snapshot/replay records by reference only.
- Existing security regression forbidden-marker checks.

## Tests

Targeted tests should cover:

- reader/member report creation
- unauthenticated access rejection
- world admin report listing and review
- cross-world rejection
- worldline-scoped target validation
- evidence/note redaction rejects or redacts forbidden fields
- moderation action creation without automatic execution
- provider action audit never exposes resolved secrets
- incidents group reports/actions safely
- API ACL protection
- no storage/path/base64/bytes/raw prompt/raw output/secret in responses or `world_events.payload`
- existing observability incident diagnostics remain unchanged

## Non-Goals

- Automated public moderation or punitive action.
- Public moderator UI or Web dashboard.
- Public unauthenticated reports.
- Provider execution, daemon execution, or automatic spend.
- Public reader media contract changes.
- Duplicate v0.7 observability/readiness framework.
- Broad `worlds.py` growth.
