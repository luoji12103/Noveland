# v0.5.8 Authoring Regression Fixture Plan

## Goal

Create a deterministic galgame import regression fixture that exercises the v0.5 authoring pipeline across source registry, script parsing, character extraction, lore proposal extraction, conflict review, memory migration, asset matching, review decisions, and guarded apply behavior.

## Scope

- Add a lightweight backend test fixture helper using existing test fixture/factory patterns.
- Prefer `backend/tests/fixtures/authoring_sample_import.py` or the nearest existing test-fixture location.
- Add a focused regression test file, likely `backend/tests/test_authoring_regression_fixture.py`.
- Build one world, one primary worldline, two agents/characters as source candidates, one import source batch, script/lore/asset source assets, source fragments, media-backed image/audio source assets, one import run, and generated proposals from Phase 2-7 service methods.
- Validate proposal review/apply behavior, including trace-only apply for supported `other` proposals and blocked apply for canonical proposal kinds.
- Validate no provider calls, media jobs, memory write jobs, visual/speech binding writes, or world event pollution occur during fixture generation.
- Keep the fixture deterministic and local-test-only; do not add production seed commands.

## Non-goals

- No migration.
- No Web UI.
- No production seed framework.
- No large content corpus.
- No content quality benchmark.
- No provider-backed parsing, extraction, matching, or evaluation.
- No direct canonical mutation for lore, memory, asset, visual, speech, character, relationship, or world-bible proposals.
- No new media/provider/memory framework.
- No raw full source, storage URI, filesystem path, bytes, base64, raw prompt, or raw output in API responses or `world_events.payload`.
- No changes to `worlds.py`.

## Fixture Shape

- World:
  - one world
  - one primary worldline
  - one world admin user
- Source registry:
  - one source batch
  - script source asset and fragment
  - lore source asset and fragment
  - character source asset and fragment
  - image source assets for sprite/background/CG matches
  - audio source asset for voice match
- Generated proposal flows:
  - script parser creates dialogue, scene, choice, route, and event candidates
  - character extractor creates character, alias, relationship, faction, identity, and emotional-baseline candidates
  - lore extractor creates proposal-only lore, location, organization, world-rule, secret, and knowledge-boundary candidates
  - conflict review creates at least one reviewable conflict report
  - memory migration creates fact, episodic, relationship, preference, and style candidates
  - asset matching creates sprite, background, CG, and voice-reference candidates
- Review/apply:
  - one `other` conflict/report proposal may apply trace-only
  - unsupported canonical proposal kinds remain blocked on apply

## Guardrails

- Fixture setup must reuse `AuthoringService`, existing authoring ORM models, `MediaAsset`, `World`, `Worldline`, and existing test DB patterns.
- Fixture setup must not call provider execution, image generation, speech generation, speech transcription, memory backend SDKs, runtime daemon paths, or Web code.
- Fixture output must not write `WorldEventModel` rows.
- Fixture output must not create `MediaJob` rows.
- Fixture output must not create `MemoryWriteJob` rows.
- Fixture output must not create visual/speech binding records as a side effect.
- All created authoring records must be same world and same worldline.
