# v0.9.10 Self-use MVP Gate Plan

Date: 2026-05-17
Branch: `feat/v0.9-self-use-mvp-gate`
Scope: v0.9 Self-use MVP Demo World Cut Phase 10 only.

## Decision

Phase 10 stays backend/API/docs/tests only. No Web UI is added, so `impeccable` is not required. No migration is required because the gate can reuse the existing observability readiness pattern plus already-implemented provider, authoring, conversation, media, memory, visual, visual generation, speech, and invocation evidence.

The self-use MVP gate is an admin-only read-only report under observability. It validates whether a specific world/worldline/conversation has enough evidence for the developer to enter, play for about 30 minutes, inspect failures, and resume later. It is not persisted as a new readiness framework and does not imply private beta or public launch readiness.

## Boundaries

- No real provider calls, hidden daemon work, or quota-consuming tests.
- No writes to world state, memory, canon, visual bindings, voice bindings, media records, provider records, or `world_events`.
- No duplicate beta/public/production readiness framework tables.
- No raw source, storage URI, filesystem path, object path, bytes, base64, raw prompt, raw output, prompt snapshot internals, local model path, raw workflow JSON, or resolved secret exposure.
- No broad `worlds.py` routes.
- No Web UI.
- No archive of v0.9 during this phase.

## Implementation Shape

- Extend `ProductionReadinessGateService` with `self_use_mvp_report`.
- Add read-only DTOs for the report and manual checklist.
- Add platform-admin-only `GET /observability/readiness/self-use-mvp`.
- Select the requested worldline and optional conversation, or use the latest conversation for the worldline.
- Aggregate evidence sections for:
  - demo entry and participant count
  - conversation continuity
  - persona and initial memory
  - visual playback and visual generation plan readiness
  - voice playback
  - required provider/model lab presence
  - media job/output state
  - invocation ledger state
  - source traceability and applied assembly proposal evidence
  - recent world event payload leak markers
- Include manual checklist items for the 30-minute play session, resume verification, and failure-note capture.
- Return only IDs, counts, statuses, safe reason codes, and safe recommendations.

## Tests

Targeted tests cover:

- Passing report with seeded demo evidence and manual checklist confirmation.
- Blocking report when memory, visual generation plan, voice, providers, invocation evidence, traceability, or manual checklist evidence is missing.
- Safe provider/world-event failure reporting without leaking forbidden markers.
- Platform-admin-only API access and member rejection.
- No new persisted self-use framework tables or side-effect writes.

## Stop Conditions

- Stop if the gate needs to persist a new readiness framework to pass.
- Stop if evidence aggregation requires direct DB mutation or provider calls.
- Stop if safe failure messages cannot explain missing provider/media/memory/visual/speech evidence.
- Stop if world-event leak checks must expose payload bodies.
- Stop if Web UI becomes required and `impeccable` cannot be used first.
