# v0.9.6 Character Memory Distillation Agent Plan

Date: 2026-05-17
Branch: `feat/v0.9-character-memory-distillation`

## Goal

Implement v0.9 Phase 6 only: turn reviewed/imported character source fragments into reviewable persona cards, initial memory candidates, and optional visual generation profile recommendations so demo-world character agents are no longer empty-memory agents.

## Scope Decision

Phase 6 is backend/API/docs/tests only.

- Reuse `backend/packages/authoring/` for distillation requests, proposals, source traceability, review, and apply.
- Reuse `ProviderExecutionService` for provider-backed text distillation so `model_invocations` and `prompt_snapshots` are written by the provider kernel.
- Reuse `AgentPersonaService` for approved persona-card apply.
- Reuse existing `Agent.character_profile` JSON for structured character fields.
- Write approved initial memory candidates into existing `AgentMemoryItem` records with traceable authoring metadata and deterministic local embeddings.
- Do not change `MemoryWriteJob.source_kind`; that queue remains runtime-event oriented.
- Add no migration for Phase 6.
- Add no Web UI; `impeccable` is not needed.

## Proposal Shape

Distillation creates proposals only:

- `agent_persona_candidate` as `AuthoringProposalKind.CHARACTER`
- `memory_candidate` as `AuthoringProposalKind.MEMORY`
- `visual_generation_profile_recommendation` as `AuthoringProposalKind.ASSET_MATCH`

Provider raw output is not copied into proposal payloads. Proposal payloads contain bounded, structured summaries such as persona text, speech style, relationship summary, emotional baseline, key memories, taboo/secret knowledge, route-specific facts, sample dialogue style, uncertainty notes, and safe provider invocation IDs.

## Apply Decision

Approved proposals may be applied explicitly through the existing authoring apply endpoint:

- Approved `agent_persona_candidate` proposals upsert `AgentPersona`, update `Agent.character_profile`, and preserve source traceability.
- Approved `memory_candidate` proposals create `AgentMemoryItem` records with `source_kind=authoring_distillation`, proposal/run/source references, and `visibility=private`.
- Approved visual generation profile recommendations remain proposal-only in Phase 6 and are trace-applied without mutating visual-generation profile records.
- Unsupported proposal kinds still block rather than mutating canon.

## Safety Rules

- No provider output directly mutates persona, memory, visual bindings, or world state.
- No unreviewed apply.
- No direct canon mutation.
- No raw full scripts in runtime prompts or broad proposal payloads.
- Prompt snapshots may hold provider prompts through the invocation ledger, but API responses must not expose prompt snapshot internals, raw prompts, raw outputs, secrets, storage paths, bytes, or base64.
- No `world_events.payload` writes.


Web validation is not required because Phase 6 touches no Web files.

## Stop Conditions

Stop if:

- persona apply cannot preserve source traceability and review/apply;
- memory apply requires widening `MemoryWriteJob.source_kind`;
- provider execution would need legacy `ProviderProfileService`;
- proposal payloads would need raw provider output, raw full scripts, resolved secrets, storage URIs, filesystem paths, bytes, or base64;
- apply would require direct world-event/canon mutation;
- a migration becomes required without a separate checkpoint.
