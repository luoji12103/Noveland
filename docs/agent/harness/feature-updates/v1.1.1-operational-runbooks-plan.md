# v1.1.1 Operational Runbooks Plan

Date: 2026-05-21
Branch: `feature/v1.1-1-operational-runbooks`
Scope: docs-only Phase 1 checkpoint for v1.1 Normal Use / Release Candidate.

## Decision

Phase 1 is documentation-only. It adds normal-use operator runbooks under `docs/agent/operations/runbooks/` and a lightweight docs consistency test. It does not add backend behavior, Web UI, migrations, API routes, runtime behavior, or provider calls.

## Runbook Set

The Phase 1 runbook set covers:

- provider outage;
- quota exhaustion;
- stuck media jobs;
- migration failure;
- backup and restore;
- rollback;
- worldline restore;
- secret rotation;
- private beta invite/session/feedback incident;
- import/export recovery;
- provider fallback and degraded mode.

Each runbook uses the same operator shape: purpose, scope, immediate actions, evidence to collect, redaction rules, escalation, and closeout.

## Evidence Model

Runbooks should reference existing controls before proposing manual intervention:

- platform-admin runtime and readiness endpoints;
- provider health, provider budget, model lab, and provider lab docs;
- media job list/cancel/retry controls;
- package preview/apply, authoring import, and provider config export controls;
- private beta invite, player session, beta feedback, and readiness evidence;
- existing backup, restore, deployment, and runtime recovery docs.

Evidence must stay safe. Operators may record IDs, status, counts, safe evidence refs, health states, timestamps, and redacted error classes. They must not record resolved secrets, storage paths, raw prompts, raw outputs, bytes, base64, invite tokens, provider credentials, prompt snapshot internals, or local model paths.

## Test Strategy

Add a docs-only regression test that verifies:

- all required runbook files exist;
- required sections are present;
- safe redaction language is present in every runbook;
- critical existing reference docs are still present;
- runbooks do not instruct operators to bypass preview/review/apply or mutate data directly as the default recovery path.

## Stop Conditions

Stop Phase 1 if:

- a runbook requires exposing secrets, raw prompts, raw outputs, storage paths, bytes, base64, invite tokens, or provider credentials;
- a runbook requires broad `worlds.py` route growth or runtime behavior changes;
- import/export recovery bypasses preview/review/apply;
- provider fallback is described as automatic without an explicit opt-in policy and quota/audit checks;
- backup/restore requires committed secrets or proprietary galgame assets.

## Validation

Required Phase 1 validation:

- targeted docs consistency test;
- OpenSpec strict changes validation;
- OpenSpec strict specs validation;
- `git diff --check`.
