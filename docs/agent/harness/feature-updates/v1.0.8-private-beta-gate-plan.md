# v1.0.8 Private Beta Gate Plan

Date: 2026-05-20
Branch: feature/v1.0-8-private-beta-gate
OpenSpec change: `openspec/changes/v1-0-private-beta-mvp/`

## Decision Summary

Phase 8 will implement the private beta gate as a read-only readiness aggregation under the
existing observability boundary. It will not create a new gate framework, persistent gate table,
setup wizard clone, public launch gate, migration, Web UI, provider call, or broad `worlds.py`
route.

The gate answers whether a prepared v1.0 world is ready for 1-3 invited testers to use for 1-2
hours with bounded cost, recoverable sessions, feedback, QA evidence, content repair traceability,
and no leak blockers. It is explicitly not public launch readiness.

## Ownership

- Package owner: `backend/packages/observability/`
- API owner: existing app-level `backend/services/api/src/noveland/services/api/observability.py`
- Endpoint: `GET /observability/readiness/private-beta`
- Response contract: readiness DTOs with `readiness_kind=private_beta_gate`
- Access: platform admin only
- No `worlds.py` route growth

## Evidence Sources

The report will reuse v1.0 and prior evidence:

- private beta setup readiness through `private_beta_setup_report`
- invite redemption, least-privilege membership, and player profiles
- player session restore evidence
- provider quota policy and emergency-stop state
- memory/persona QA evidence from narrative quality diagnostics
- beta feedback report submission/triage evidence
- beta content repair proposal/link/apply evidence from authoring and feedback records
- provider, media, visual, speech, persona, memory, source traceability, and self-use MVP evidence
- recent `world_events.payload` leak scan through existing forbidden-marker checks
- manual 1-2 hour beta checklist flags supplied as request parameters

## Report Semantics

The gate blocks if:

- setup readiness has blockers
- no onboarding/access evidence exists
- no player session resume evidence exists
- quota controls are missing or emergency stop is active
- no feedback path has been exercised
- memory/persona QA evidence is missing or has critical blockers
- no content repair linkage exists from feedback/diagnostics to authoring proposals
- provider/media/memory/visual/voice/self-use evidence has blockers
- manual 1-2 hour tester-session evidence is not confirmed
- leak checks find forbidden prompt, secret, storage, path, byte/base64, invite token, or raw output markers

Returned evidence is limited to safe readiness sections, counts, record IDs, statuses, reason
codes, world/worldline IDs, and timestamps.

## Frontend Scope

No Web UI is scoped for Phase 8. The implementation is backend/API-only, so `impeccable` is not
required. A later admin readiness UI may consume the safe report after a separate UI scope decision.

## Tests

Targeted tests should cover:

- private beta gate passes with complete setup, feedback, QA, repair, and manual checklist evidence
- gate fails without onboarding/session/quota/feedback/QA/repair evidence
- gate fails with leak fixture
- platform-admin-only endpoint ACL
- report is redacted and distinguishes private beta from public launch readiness
- no duplicate private beta gate tables are required

## Stop Conditions

Stop implementation if:

- the gate needs a new readiness framework or persistent report table
- gate evidence requires raw prompt/output, prompt snapshot internals, resolved secrets, storage
  paths, object paths, bytes/base64, invite tokens, raw source fragments, or local model paths
- gate result implies public launch readiness
- gate exposes admin diagnostics to testers
- implementation requires broad `worlds.py` route growth
- Web UI becomes necessary and `impeccable` cannot be read/used first
