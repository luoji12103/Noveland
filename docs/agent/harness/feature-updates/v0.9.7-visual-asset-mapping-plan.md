# v0.9.7 Visual Asset Mapping Plan

Date: 2026-05-17
Branch: `feat/v0.9-visual-asset-mapping`
Scope: v0.9 Self-use MVP Demo World Cut Phase 7 only.

## Decision

Phase 7 stays backend/API/docs/tests only. No Web UI is added, so `impeccable` is not required for this phase. No migration is required because the existing authoring proposals, media assets, and visual binding tables can support the first implementation.

Reviewed `sprite_asset_match`, `background_asset_match`, and `cg_asset_match` proposals will apply through `AuthoringService.apply` only. Sprite and background mappings use the existing `VisualAssetService`, `CharacterSpriteSet`, `CharacterSpriteVariant`, and `SceneBackgroundProfile` records. CG assets have no first-class applied visual binding table today, so Phase 7 records them as traceable safe media metadata and generation-reference candidates instead of inventing a new schema.

## Boundaries

- No cracking, unpacking, DRM bypass, or source acquisition.
- No direct visual binding mutation during intake or matching.
- No image generation provider calls.
- No broad `worlds.py` routes.
- No storage URI, local path, bytes, base64, raw prompt, raw output, prompt snapshot internals, or resolved secret exposure.
- No `world_events.payload` writes.
- Hidden or developer-only media remains rejected for reviewed apply.

## Implementation Shape

- Reuse authoring asset-match proposals created by Phase 4/5.
- Resolve sprite target agent by explicit `agent_id` when present, otherwise by normalized `character_label` against `Agent.agent_key`/`display_name`.
- Create or reuse one imported sprite set per agent/worldline/style key.
- Create sprite variants for expression, pose, outfit, and mood metadata.
- Create scene background profiles for location/time/weather/scene metadata.
- Mark approved visual media as internal visual generation reference candidates where appropriate.
- Preserve proposal, run, source asset, source fragment, and media asset refs in applied metadata and traceability.
- Keep CG support conservative: traceable media metadata only until a first-class CG playback/binding model is accepted.

## Tests

Targeted tests cover:

- Reviewed sprite/background/CG proposal apply.
- Source traceability and no world-event writes.
- Worldline isolation rejection for visual mapping payloads.
- Restricted media rejection through the authoring apply path.
- Generation-reference metadata for approved imported visual assets.
- No leak markers in proposal/application responses or visual metadata.

## Stop Conditions

- Stop if visual mapping needs a new CG binding table before demo assembly.
- Stop if agent resolution cannot be made explicit or deterministic enough for imported sprite proposals.
- Stop if visual bindings require reader/player DTO exposure of raw media paths.
- Stop if Phase 7 unexpectedly needs Web UI and `impeccable` cannot be used first.
