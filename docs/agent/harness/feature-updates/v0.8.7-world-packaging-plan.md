# v0.8.7 World Packaging Plan

## Status

Planned for implementation after v0.8 Phase 6 Player Privacy & Data Controls passed the full local gate and fast-forward merged to local `main`.

## Goal

Add a safe world packaging boundary that can export portable world/media manifests and run import preview/apply discipline without exposing secrets, storage internals, raw prompts, raw outputs, or binary payloads.

## Scope

- Backend/API-only first implementation.
- Add a dedicated packaging package/router rather than growing `worlds.py`.
- Produce deterministic export preview manifests for an existing world and selected worldline.
- Validate submitted package manifests in an import preview step before mutation.
- Apply only after explicit admin request and only for safe manifest-backed records.
- Reuse existing world, media, authoring preview/apply, ACL, and security regression conventions.

## Proposed Boundary

- Package: `backend/packages/world_packaging/`
- API router: `backend/services/api/src/noveland/services/api/world_packaging.py`
- Route prefix: `/worlds/{world_id}/packages`

## First API Shape

- `POST /worlds/{world_id}/packages/export-preview`
- `POST /worlds/{world_id}/packages/import-preview`
- `POST /worlds/{world_id}/packages/import-apply`

The first implementation is admin-scoped. It does not add reader/player/public delivery routes and does not add Web UI.

## Manifest Contract

World package manifests may include:

- Package metadata: manifest version, package key, generated timestamp, capability list.
- Safe world metadata: name, slug, description, active flag, memory/world-rules plugin identifiers, and sanitized non-secret config.
- Worldline metadata: id/key/name/status as portable references.
- Scene metadata: scene key, name, region, tags, and active flag.
- Media manifest entries: portable asset refs, asset kind/role/source/status/visibility, mime type, checksum/size, and media references by safe context.
- Publication/presentation references when safe and available.

Manifest must not include:

- `storage_uri`, filesystem paths, object storage paths, S3/GCS URLs, long-lived signed URLs.
- Bytes, base64, inline binary, raw prompt, raw output, prompt snapshot internals.
- Resolved provider secrets, auth tokens, passwords, access keys, or provider health metadata secrets.
- Hidden/developer-only/private assets unless the package is an admin-internal preview and the response still redacts storage internals.

## Import Discipline

- Import preview validates manifest version, capability support, worldline/media reference consistency, duplicate keys, and forbidden-token leakage.
- Import preview returns blockers/warnings and creates no world, media, provider, event, or package records.
- Import apply reruns preview and refuses to mutate on blockers.
- Apply may create a new world from safe world/scene metadata and may create manifest-safe media metadata through existing media tables only when the manifest is portable and has no storage/object path.
- Apply does not execute providers, copy bytes, enqueue daemon jobs, publish worlds, or write world events.

## Migration Decision

No migration for Phase 7 first implementation. Package preview/apply is synchronous and response-only. If later phases need persisted package runs or release package records, stop and add a dedicated migration plan first.

## Tests

- Export manifest contains safe world/worldline/scene/media metadata.
- Export manifest omits storage paths, raw prompts/outputs, bytes/base64, and secrets.
- Import preview reports blockers and creates no records.
- Import apply refuses blocked manifests.
- Import apply creates safe world/scene records for valid manifests without provider calls or world events.
- Media manifest references are portable and do not create a second media framework.
- Cross-world/worldline mismatches are rejected.
- ACL checks require world admin access.
- Existing world composition routes remain unchanged.

## Guardrails

- No Web UI.
- No migration.
- No provider execution, daemon execution, public marketplace, public unauthenticated access, or streaming.
- No broad `worlds.py` changes.
- No exporting resolved secrets, storage internals, prompt snapshots, raw prompts, or raw outputs.
- No mutation before explicit import apply.
