# Phase 3 Implementation Plan: Model Invocation Ledger

## Summary

- Current `main` is clean and aligned with `origin/main`; no Phase 3 files or migrations exist yet.
- Implement a new `noveland-invocations` package and independent `/worlds/{world_id}/model-invocations` API router.
- Add worldline-aware model-call ledger tables, prompt templates, prompt snapshots, tags, redaction, retention, search, and new-runtime integration.
- Do not implement provider adapter changes, Web UI, external tracing, pgvector, legacy backfill, `conversation_turns` changes, or `world_events.payload` changes.

### Ledger Semantics

- `model_invocations` is the canonical concrete provider/model call ledger.
- `AgentRuntimeRun` remains the agent execution record.
- Link runtime runs through `agent_runtime_run_model_invocations`, not through `agent_runtime_run_id` on `model_invocations`.
- Use `prompt_snapshots.invocation_id` as the one-to-one relation; do not add reverse FK from `model_invocations`.
- Store raw prompt/output inline in DB by default, with redaction/retention/visibility controls from day one.
- Keep `AgentRuntimeRun.prompt_text` populated with a compact placeholder/summary for schema compatibility; canonical raw prompt/output lives in ledger/snapshot tables.

### ACL, Search, And Redaction

- Reader/player/world member receive no Phase 3 invocation access.
- World admin can access `private` and `world_admin` records for their world, with raw fields only when `redaction_status=raw`.
- Platform admin can access `developer_only` and hidden records when explicitly requested.
- Mutations require CSRF.
- Search supports worldline, trace, parent, entity refs, kind, provider/model, status, visibility, redaction, retention, sensitivity, `contains_text`, repeated `tag`, limit/cursor/order.
- `contains_text` trims, rejects empty, max 200 chars, and only searches fields the caller may see.
- Tag filter matches Media Phase 2: `tag_type:tag_key:tag_value`, split first two `:`, repeated tags use AND, malformed filters return 422.
- Redaction modes:
  - `clear_raw_payloads`
  - `checksum_only`
  - `hide`

### Runtime Integration

- Wrap new `AgentRuntimeOrchestrator.run_agent` provider calls:
  - create pending invocation and prompt snapshot before `invoke_profile`
  - update invocation/snapshot on success/failure
  - insert join row with `invocation_role=primary`, `sequence_index=0`
- Do not backfill legacy `AgentRuntimeRun`.
- Do not enqueue memory from raw invocation.
- Do not write raw prompt/output to `world_events.payload`.

## Validation Rules

- Resolve `worldline_id` with `worldline_or_404`.
- Parent invocation must match same `world_id` and `worldline_id`.
- `agent_id` must match same world.
- `conversation_id`, `turn_id`, `world_event_id`, `media_job_id`, `media_asset_id`, and `memory_write_job_id` must match same worldline.
- Legacy nullable-worldline referenced rows are treated as primary-worldline only and rejected for forks.
- Media references store IDs only; do not copy `storage_uri`, bytes, base64, or file paths.
