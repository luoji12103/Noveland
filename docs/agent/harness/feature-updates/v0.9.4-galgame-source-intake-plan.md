# v0.9.4 Galgame Source Intake Plan

Date: 2026-05-17
Branch: `feat/v0.9-galgame-source-intake`

## Goal

Implement v0.9 Phase 4 only: accept user-provided already-unpacked galgame source directories into existing authoring and media systems with safe preview/apply boundaries.

## Scope Decision

Phase 4 is backend/API/docs/tests only.

- Reuse `backend/packages/authoring/` source batches, source assets, source fragments, import runs, and traceability.
- Reuse the media kernel for imported image and audio files.
- Add a narrow authoring route under `/worlds/{world_id}/authoring/galgame-source-intake/*`.
- Add no migration because the existing authoring/media tables already represent source registry, fragments, media assets, media objects, and import run summaries.
- Add no Web UI in this phase; `impeccable` is not needed unless later Web scope is approved.

## Intake Boundary

The intake accepts only local directories that the operator confirms are already unpacked and user provided.

It does not:

- crack, decrypt, unpack, extract archives, bypass DRM, scrape, or acquire files;
- mutate canon, memory, visual bindings, voice bindings, world state, or world events;
- expose raw filesystem paths, object storage paths, storage URIs, bytes, base64, raw prompts, raw outputs, or resolved secrets in API responses.

Packed/archive/container/executable-like files are rejected as source inventory items instead of opened or extracted.

## Data Shape

Preview produces a safe inventory:

- hashed `source_ref`
- filename only
- role guess
- media/source kind
- size, MIME type, fragment count, and safe rejection reason

Apply creates:

- one private source batch
- one import run summary
- source asset records
- source fragments for text/script/profile/route files
- private media assets and media objects for accepted image/audio files

Imported media uses `imported_original` source kind and metadata flags suitable for later visual-generation reference selection, while applied visual/voice binding remains out of scope for Phase 4.

## Validation

Targeted validation:

```sh
cd backend && uv run pytest tests/test_authoring_service.py tests/test_api_authoring.py -q
```

Full local gate:

```sh
cd backend && uv run ruff check .
cd backend && uv run mypy .
cd backend && uv run pytest
openspec validate --changes --strict
openspec validate --specs --strict
git diff --check
```

Web validation is not required because Phase 4 touches no Web files.

## Stop Conditions

Stop if:

- intake requires unpacking, decryption, archive extraction, or DRM circumvention;
- safe preview cannot avoid raw filesystem paths;
- imported media cannot go through the media kernel;
- source content would need to be exposed through reader/player/member APIs;
- apply would directly mutate canon, memory, visual, voice, world state, or world events;
- a migration becomes required without a separate checkpoint.
