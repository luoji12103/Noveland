# v0.7.6 Observability & Incident Diagnostics Plan

## Goal

Expose safe incident diagnostics over the existing runtime, provider, invocation, media, eval, cost, and narrative-quality evidence without creating a duplicate diagnostics framework.

This phase is backend/API/test/docs focused. It should make incident summaries easier for platform admins while preserving redaction, ACL, and evidence-ref boundaries.

## Scope

- Add a small incident diagnostics service under `backend/packages/observability/`.
- Add a bounded platform-admin API router only if needed:
  - `backend/services/api/src/noveland/services/api/observability.py`
  - preferred route: `GET /observability/incidents/summary`
- Aggregate safe evidence from existing records:
  - `runtime_diagnostic_events`
  - provider health checks and provider profile health where applicable
  - failed or blocked `model_invocations`
  - failed `media_jobs`
  - v0.7 provider budget policy status and budget-block evidence
  - multimodal eval runs and diagnostics
  - narrative quality dashboard summary
- Return safe counts, status, timestamps, component names, and evidence refs only.
- Reuse existing diagnostic retention dry-run/prune endpoints; document retention status in the summary but do not add a second retention system.
- Add focused service/API tests for safe aggregation, redaction, ACL, and retention reuse.

## Non-goals

- External observability exporter
- Real-time incident Web dashboard
- Raw prompt/output replay
- Prompt snapshot exposure
- Public/member/reader/player incident routes
- Duplicate diagnostics, eval, or release evidence tables
- New production-hardening catchall router
- Broad `worlds.py` or runtime route growth

## Architecture Decision

Use `noveland.observability` as the owner for incident-summary aggregation.

If an API is required, add a dedicated observability router instead of expanding `worlds.py` or turning `runtime.py` into a general production-hardening surface. The router must remain platform-admin-only and read-only for the first version.

## Expected Migration

No migration is expected.

Stop if implementation requires persisted incident reports, new evidence tables, or retention state beyond existing `runtime_diagnostic_events` retention behavior.

## Reused Systems

- `RuntimeDiagnosticsService`
- `redact_diagnostic_details`
- `runtime_diagnostic_events`
- provider health checks and provider profiles
- `model_invocations`
- `prompt_snapshots` redaction evidence without exposing prompt content
- `media_jobs`
- provider budget policies and safe quota evidence
- `MultimodalEvalService`
- `NarrativeQualityService.dashboard_summary`
- platform-admin authorization dependencies

## Deliverables

- Incident diagnostics contracts/service under `noveland.observability`.
- Optional dedicated observability API router registered at app level.
- Safe incident summary response with counts and evidence refs.
- Focused tests for aggregation, redaction, ACL, and retention reuse.
- Updated OpenSpec task status and harness docs after implementation.

## Guardrails

- Do not expose resolved provider secrets.
- Do not expose raw prompts, raw outputs, prompt snapshots, storage URIs, filesystem paths, bytes, or base64.
- Do not expose incident summaries to world members, readers, or player routes.
- Do not duplicate multimodal eval or narrative quality diagnostics; summarize their safe outputs only.
- Do not write incident summaries into `world_events.payload`.

## Stop Conditions

- Incident reporting requires raw prompt/output, prompt snapshot body, storage URI, file path, bytes, base64, or resolved secret exposure.
- Existing evidence cannot be summarized without a new persisted incident schema.
- Implementation expands `worlds.py` or turns `runtime.py` into a broad production-hardening router.
- Targeted tests or the full local gate fail.

## Targeted Tests

- Incident summary includes safe evidence refs for runtime diagnostic errors.
- Incident summary includes safe evidence refs for failed provider/model invocations.
- Incident summary includes safe evidence refs for failed media jobs.
- Incident summary includes safe eval and narrative quality blockers without raw evidence payloads.
- Runtime diagnostic retention dry-run remains the retention authority.
- API is platform-admin-only.
- Response text excludes resolved secrets, raw prompts, raw outputs, storage URIs, filesystem paths, bytes, and base64.

## Validation

- Targeted observability incident diagnostics tests.
- `openspec validate --changes --strict`
- `openspec validate --specs --strict`
- Full local gate before fast-forward merge.
