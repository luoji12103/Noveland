# v0.3.1.4 Media Kernel Phase 4 Additive Extension Plan

Date: 2026-05-11

## Summary

Phase 4 extends the existing Media Phase 1/2 foundation instead of replacing it.
Current `main` already has `noveland-media`, `media_assets`, `media_jobs`,
`media_asset_contexts`, `media_asset_inputs`, tags, collections, search,
storage, and `/worlds/{world_id}/media` routes. Phase 4 adds the missing kernel
pieces: multi-object assets, upload/download, generalized references, richer job
updates, and Phase 3 invocation links.

Implementation flow:

1. Save this final plan and update harness docs on `main`.
2. Commit the docs-only planning checkpoint.
3. Create `feat/media-kernel`.
4. Implement additive backend changes.
5. Run targeted and full local gates.
6. Fast-forward merge locally back to `main`.
7. Do not push until explicitly confirmed.

## Compatibility Matrix

- Existing `media_assets` -> required logical asset record -> reuse as
  canonical; do not rename/drop. Add `source_invocation_id`; keep `asset_kind`
  as coarse media class and `asset_role` as detailed role.
- Existing `storage_uri` fields on `media_assets` -> required binary object
  support -> keep as backward-compatible primary/original summary fields; add
  `media_objects` for multiple object variants.
- Existing `media_asset_contexts` -> current fixed asset contexts -> keep
  existing API/behavior; do not backfill or replace.
- Missing generic refs -> required `media_references` -> add companion table for
  future/general refs. New reference APIs use this table; legacy context APIs
  remain.
- Optional `conversation_turn_media_attachments` -> turn attachments -> do not
  add table. Use `media_references` for new turn media API and include legacy
  `media_asset_contexts` in reads where relevant.
- Existing `media_jobs` -> required task ledger -> reuse; add safe missing
  columns and update/list filters. Do not add background execution.
- Phase 3 `model_invocations.media_job_id` and `media_asset_id` -> invocation
  relation -> reuse as-is. Add media-side `source_invocation_id` on assets/jobs.

## Key Changes

- Add migration `20260512_0033_media_kernel.py`, revising latest head
  `20260511_0032`.
- Add `media_objects` with `asset_id`, `world_id`, `worldline_id`,
  `object_role`, `storage_uri`, `filename`, `mime_type`, `size_bytes`,
  `checksum_sha256`, dimensions/audio/video metadata, `metadata`, and
  `created_at`; unique `storage_uri`; indexes on asset/role, checksum, and
  worldline.
- Add `media_references` with `world_id`, `worldline_id`, `asset_id`,
  `ref_kind`, `ref_id`, `ref_role`, `display_order`, `metadata`, and
  `created_at`; unique `(world_id, worldline_id, asset_id, ref_kind, ref_id,
  ref_role)`.
- Extend existing tables:
  - `media_assets.source_invocation_id` FK to `model_invocations.id`.
  - `media_jobs.source_event_id`, `source_invocation_id`, and
    `provider_config_json`.
  - Expand enum/check constraints only where backward-compatible and needed.
- Extend `noveland.media.contracts` with media object, reference, upload
  response, richer filters, and turn media DTOs.
- Extend `MediaService` for upload, add object, list objects, and download
  metadata.
- Add `MediaReferenceService` for polymorphic same-world/same-worldline
  validation and reference CRUD.
- Extend `MediaJobService` with filtered list, `update_job`, and terminal-state
  cancel rejection.
- Keep `LocalMediaObjectStorage`; add convenience aliases `put_bytes`,
  `open_read`, and `normalize_key` without breaking existing methods.
- Store local media under `AppSettings.object_storage_root / "media"` using keys
  like
  `worlds/{world_id}/worldlines/{worldline_id}/assets/{asset_id}/{object_role}-{checksum}.{ext}`.
- Extend only `backend/services/api/src/noveland/services/api/media.py`; do not
  add routes to `worlds.py`.

## API Changes

Add routes under the existing world-scoped media router:

- `POST /worlds/{world_id}/media/assets/upload`
- `GET /worlds/{world_id}/media/assets/{asset_id}/objects`
- `POST /worlds/{world_id}/media/assets/{asset_id}/objects`
- `GET /worlds/{world_id}/media/objects/{object_id}/download`
- `GET /worlds/{world_id}/media/references`
- `POST /worlds/{world_id}/media/references`
- `DELETE /worlds/{world_id}/media/references/{reference_id}`
- `PATCH /worlds/{world_id}/media/jobs/{job_id}`
- `GET /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/media`
- `POST /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/media`
- `DELETE /worlds/{world_id}/conversations/{conversation_id}/turns/{turn_id}/media/{asset_id}`

`POST /media/assets/upload` must be registered before
`/media/assets/{asset_id}`.

ACL defaults:

- New upload/object/download/reference/job mutation routes require world admin
  or platform admin, and mutating routes require CSRF.
- World members keep existing visible metadata reads but cannot upload,
  download, or manage media.
- `developer_only` and `hidden` are platform-admin only for new
  object/download/reference surfaces.
- `reader_visible` remains future eligibility, not a public reader download
  route.

## Safety Rules

- Never write storage URI, filesystem path, bytes, or base64 to
  `world_events.payload`.
- Upload computes checksum and size from actual bytes.
- Uploaded filename is metadata only and never controls storage paths.
- Download returns bytes with stored MIME type and never exposes filesystem
  paths.
- Media references validate same world and same worldline, including Phase 3
  invocation links.
- Do not implement provider adapters, Web UI, public reader media routes, S3/GCS,
  pgvector/full-text search, or background media execution.

## Assumptions

- Phase 4 is additive consolidation over existing Media Phase 1/2.
- No table renames, dropped columns, legacy backfill, provider adapters, Web UI,
  public reader media route, S3/GCS, pgvector/full-text, or background media
  execution.
- Existing `asset_kind`, `source_kind`, and `asset_role` names remain canonical;
  new requested names are mapped to current concepts in docs rather than forcing
  schema normalization.
- `conversation_turn_media_attachments` is intentionally not added to avoid
  double-write; `media_references` plus existing contexts cover the use case.
