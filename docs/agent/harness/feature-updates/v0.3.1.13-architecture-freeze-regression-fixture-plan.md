## Regression Fixture

Add a lightweight test helper, preferably:

- `backend/tests/fixtures/multimodal_sample_world.py`

The helper should create a deterministic sample world with:

- one world and one primary worldline
- two agents
- one scene
- one conversation and turn
- background, sprite, audio, and composite media assets/objects
- one character sprite set with neutral, happy, and sad variants
- one default voice profile and binding
- one conversation turn presentation
- one STT source/transcript
- one asset generation preview/apply record or proposal/run pair
- enough provider/invocation/prompt snapshot data for multimodal diagnostics to pass

Do not introduce a large seed framework or new runtime CLI.

## Regression Tests

Add:

- `backend/tests/test_multimodal_sample_world_regression.py`

Coverage:

- fixture creation is deterministic enough for repeated test execution
- all fixture records belong to one world
- worldline-scoped records use the primary worldline
- no visual binding has nullable `worldline_id`
- sprite resolver resolves neutral, happy, and sad variants
- background resolver resolves the default scene background
- conversation presentation references valid sprite/background/voice/audio/composite assets
- media objects exist and checksums validate
- provider secrets are absent from provider API output and health metadata
- member/reader routes do not expose prompt snapshot sensitive fields
- STT transcripts are not auto-written to memory
- asset generation preview/apply remains admin-controlled
- `world_events.payload` has no storage URI, filesystem path, bytes, base64, raw prompt, or raw output
- multimodal diagnostics pass for the sample fixture

## Architecture Boundaries To Freeze

- `world_id` and `worldline_id` are first-class isolation parameters.
- Provider calls route through `ProviderExecutionService`; provider adapters do not leak into world/conversation/agent/narrative code.
- `auth_ref` is an opaque secret reference; provider config/default params must not store secret values.
- Every model/provider call writes `model_invocations` and `prompt_snapshots`.
- Binary media is represented by `media_assets`, `media_objects`, `media_jobs`, and `media_references`, not by `narrative_artifacts`.
- Visual bindings are strict-worldline records pointing to media assets.
- Conversation presentation is backend/API-only canonical turn state and must not mutate turn text during render/STT flows.
- Asset generation is proposal plus admin apply; preview/apply must not execute providers or daemon work.
- Multimodal evals reuse `long_run_eval_runs` and must not create a duplicate release framework.
- `world_events.payload` must not store storage URIs, file paths, bytes, base64, raw prompts, or raw outputs.
