# v0.3.1.1 Media Kernel Phase 1 Plan

Date: 2026-05-10

## Summary

Implement the Media Kernel Foundation as a backend-only feature. This phase
adds a dedicated `noveland-media` package, media asset/job/context/input tables,
binary local media storage, media services, an independent FastAPI media router,
and backend tests for schema, storage, service, API, ACL, and worldline
isolation.

This phase does not generate images, call providers, add Web UI, expose public
download routes, or implement model invocation ledgers, prompt snapshots,
performance annotations, provider integrations, pgvector similarity search, or
realtime streaming.

## Required Product Boundaries

- Do not reuse `narrative_artifacts` as a generic media asset table.
- Do not store `storage_uri`, filesystem paths, media URLs, or base64 payloads in
  `world_events.payload`.
- Do not modify `conversation_turns`; turns attach media through
  `media_asset_contexts.turn_id`.
- Do not add media routes to `worlds.py`; add a dedicated API router.
- Every core media table must contain `world_id` and `worldline_id`.
- Every asset, job, context, and input operation must enforce same-world and
  same-worldline references.
- Do not expand existing `provider_profiles` into a universal provider table.
  Phase 1 jobs keep only nullable `provider_kind`.
- Provider jobs are persisted but never executed in Phase 1.

## Backend Changes

- Add `backend/packages/media` with:
  - `contracts.py` for Pydantic enums and DTOs.
  - `models.py` for SQLAlchemy media models.
  - `storage.py` for `MediaObjectStorage` and `LocalMediaObjectStorage`.
  - `service.py` for `MediaService` and `MediaJobService`.
  - `errors.py` for typed validation/not-found/conflict errors.
- Register `noveland-media` in the backend uv workspace and add
  `noveland.media.models` to SQLAlchemy model imports.
- Add migration `20260510_0030_media_kernel_foundation.py`.
- Add `backend/services/api/src/noveland/services/api/media.py` and include it in
  the FastAPI app.

## Schema

Create four tables:

- `media_assets`
  - Tracks image/audio assets, role, source, lifecycle status, visibility,
    opaque storage URIs, checksum, MIME, size, image/audio metadata, source
    event/job refs, actor ref, metadata, and timestamps.
  - Status values: `registered`, `available`, `failed`, `deleted`.
  - `available` means storage exists and checksum/MIME/size have been verified.
  - API-created assets default to `registered`; `available` creation is service
    internal until upload/import routes exist.
- `media_jobs`
  - Tracks queued provider/local work requests without execution.
  - Contains job kind, nullable provider kind, status, priority, cancel policy,
    dedupe/invalidation keys, request/result JSON, error text, actor ref, and
    timestamps.
  - No `provider_profile_id` FK in Phase 1.
- `media_asset_contexts`
  - Links assets to conversations, turns, agents, world events, and reserved
    narrative artifacts.
  - Narrative artifact context creation is rejected by Phase 1 service/API
    because `narrative_artifacts` lacks first-class `worldline_id`.
- `media_asset_inputs`
  - Records input/output lineage for derived assets, including source job,
    input role, display order, and metadata.

## Storage

- Use local binary storage rooted at `AppSettings.object_storage_root / "media"`.
- Return opaque URIs using:
  `media://worlds/{world_id}/worldlines/{worldline_id}/...`
- Reject absolute paths, traversal, `file://`, `http://`, `https://`, raw base64,
  and client-controlled arbitrary storage URIs.
- If service code registers an existing object as `available`, validate that the
  URI belongs to the current world/worldline and that checksum/MIME/size match.
- No public download or file-serving API is added in Phase 1.

## API

Add world-scoped media routes:

- `GET /worlds/{world_id}/media/assets`
- `POST /worlds/{world_id}/media/assets`
- `GET /worlds/{world_id}/media/assets/{asset_id}`
- `PATCH /worlds/{world_id}/media/assets/{asset_id}`
- `DELETE /worlds/{world_id}/media/assets/{asset_id}`
- `POST /worlds/{world_id}/media/assets/{asset_id}/contexts`
- `GET /worlds/{world_id}/media/assets/{asset_id}/contexts`
- `DELETE /worlds/{world_id}/media/assets/{asset_id}/contexts/{context_id}`
- `POST /worlds/{world_id}/media/assets/{asset_id}/inputs`
- `GET /worlds/{world_id}/media/assets/{asset_id}/inputs`
- `GET /worlds/{world_id}/media/assets/{asset_id}/references`
- `GET /worlds/{world_id}/media/assets/{asset_id}/lineage`
- `POST /worlds/{world_id}/media/jobs`
- `GET /worlds/{world_id}/media/jobs`
- `GET /worlds/{world_id}/media/jobs/{job_id}`
- `POST /worlds/{world_id}/media/jobs/{job_id}/cancel`
- `POST /worlds/{world_id}/media/jobs/{job_id}/retry`

ACL defaults:

- Reads require world membership.
- Mutations require world admin and CSRF.
- Non-admin members only see `world_member`, `player_visible`, and
  `reader_visible` assets.
- Strangers keep the existing hidden-world 404 behavior.

## Tests

Backend tests must cover:

- Alembic linear head and downgrade exposure.
- SQLAlchemy metadata registration for all new tables, columns, constraints, and
  indexes.
- Local media storage write/read/delete, opaque URI, checksum/size, and traversal
  rejection.
- Service asset registration, status validation, available-object verification,
  soft delete, context attach/list/detach, narrative artifact rejection, lineage,
  and same-world/worldline enforcement.
- API admin/member/stranger ACL, CSRF, visible-only member reads, job create/list
  /cancel/retry, and no provider execution.
- Event safety: media operations do not create world events and never write
  storage/preview/thumbnail URIs to `world_events.payload`.

## Assumptions

- Existing architecture review docs are committed before the feature branch.
- Branch name: `feat/media-kernel-foundation`.
- Web mock backend changes are not required in Phase 1 because no Web routes or
  UI are added.
- Narrative artifact media contexts remain schema-reserved but operationally
  blocked until narrative artifacts gain first-class `worldline_id`.
