# v1.0 Private Beta MVP Release Notes

## Summary

v1.0 turns the v0.9 self-use demo-world path into an invite-only private beta path for 1-3 selected testers. It adds least-privilege onboarding, server-owned player resume, enforced provider quota controls, private beta setup/readiness checks, memory/persona QA diagnostics, contextual beta feedback, reviewable content repair, and an admin-only private beta gate.

## Released Scope

- Phase 1 Private Beta Onboarding & Access Model: dedicated `private_beta` package/router, hashed invite tokens, invite lifecycle/audit, redemption, least-privilege membership bootstrap, worldline-scoped player profile setup, and minimal authenticated Web onboarding.
- Phase 2 Player Session Stability: dedicated `player_sessions` package/router, player-owned resume records, current conversation/scene/presentation pointers, safe recovery status, and player resume/restore UI.
- Phase 3 Cost & Quota Real Enforcement: provider-owned quota enforcement in `ProviderExecutionService`, world/provider/capability/player scopes in budget policy JSON, emergency stop behavior, safe quota status, and no hidden retries after quota blocks.
- Phase 4 World Setup Wizard: admin-only private beta setup readiness under existing observability/readiness, validating access, session, quota, provider/model, media, persona/memory, visual, voice, source traceability, self-use evidence, and no-leak markers.
- Phase 5 Memory & Persona QA: admin diagnostics in the existing narrative quality boundary for missing persona/memory, memory contamination, persona drift, style drift, relationship drift, source traceability gaps, and worldline contamination.
- Phase 6 Beta Feedback System: dedicated `beta_feedback` package/router, reporter-private feedback records, safe contextual evidence refs, admin triage, repair-proposal link refs, and minimal tester/admin Web feedback surface.
- Phase 7 Beta Content Iteration Loop: authoring-backed repair proposal bridge from beta feedback and QA findings, preserving review/apply, safe feedback traceability, worldline isolation, and no direct mutation.
- Phase 8 Private Beta Gate: admin-only `private_beta_gate` readiness report under observability/readiness that aggregates onboarding, setup, session, quota, QA, feedback, repair loop, provider/media/memory/visual/voice, no-leak checks, and manual 1-2 hour tester-session evidence.

## Safety And Security Boundaries

- Private beta remains invite-only; no public signup was added.
- Tester access is deny-by-default and least-privilege.
- Tester/player/member surfaces do not expose provider admin, media admin, invocation admin, setup diagnostics, resolved secrets, storage paths, object storage paths, bytes, base64, raw prompts, raw outputs, prompt snapshot internals, or invite tokens.
- Invite tokens are stored only as non-redeemable hashes/fingerprints.
- Provider spend is blocked before adapter execution when quota policy disallows the call.
- Provider output, feedback, and QA findings do not directly mutate persona, memory, visual bindings, voice bindings, provider profiles, or world state.
- Content repair reuses authoring preview/review/apply.
- Private beta readiness does not imply public launch or release-candidate readiness.
