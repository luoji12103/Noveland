# v0.9 Self-use MVP Demo World Cut Release Notes

## Summary

v0.9 turns the existing Noveland platform into a self-use playable demo-world path. It productizes provider setup, adds a controlled visual generation planning layer, creates a safe provider lab harness, accepts user-provided already-unpacked galgame sources, extracts dialogue, distills persona and memory proposals, maps imported visual and voice assets, assembles a reviewed demo conversation, and adds a 30-minute self-use MVP gate.

## Released Scope

- Phase 1 Provider Settings & Model Lab: static/code-owned provider templates, redacted server-side model discovery, manual model fallback, safe smoke checks, and OpenAI-compatible/Anthropic-compatible text execution through `ProviderExecutionService`.
- Phase 2 Visual Generation Control Plane: dedicated visual generation package/router, workflow templates and versions, visual model inventory, strict-worldline character visual generation profiles, provider-neutral plans, slot validation, and dry-run mapping for ComfyUI, Z-Image, GPT/OpenAI-compatible image, and generic image providers.
- Phase 3 Provider Worktree Integration Test Harness: provider lab documentation, strict `real_provider` pytest marker, `NOVELAND_RUN_REAL_PROVIDER_TESTS=1` opt-in convention, and fake/mock provider contract coverage.
- Phase 4 Galgame Source Intake: migration-free intake for user-provided already-unpacked directories, source batches/assets/fragments, media assets/objects, preview/apply, and generation-reference candidate metadata.
- Phase 5 Script Dialogue Extraction: deterministic dialogue extraction with line text, speaker/scene/route candidates, emotion and relationship hints, and manual-label fallback proposals.
- Phase 6 Character Memory Distillation Agent: provider-backed distillation through the provider kernel into reviewable persona, memory, and visual-generation-profile recommendation proposals; explicit apply writes `AgentPersona`, `Agent.character_profile`, and `AgentMemoryItem`.
- Phase 7 Visual Asset Mapping: reviewed sprite/background/CG mapping through authoring apply using existing visual records and safe media metadata.
- Phase 8 Voice Profile Mapping: reviewed voice reference and provider voice ID mapping through existing speech voice profiles, bindings, and style overrides.
- Phase 9 Demo World Assembly: backend/API-first `demo_world_assembly` proposal and reviewed apply path that creates a manual-chain conversation entry session, participants, seed turn, and initial presentation references.
- Phase 10 30-Minute Self-use MVP Gate: platform-admin read-only observability report for demo entry, conversation continuity, persona/memory, visual/speech readiness, provider setup, media jobs, invocation ledger, traceability, world-event leak checks, and manual 30-minute/resume/failure-note checklist items.

## Provider And Model Configuration

- Provider templates cover OpenAI-compatible LLM, Anthropic-compatible LLM, MiMo V2.5 TTS, MiMo V2.5 ASR, Z-Image, GPT Image, ComfyUI, OpenAI-compatible image, and generic/custom HTTP image providers.
- Provider configs keep `base_url`, `auth_ref`, `model_name`, model list/discovery strategy, provider kind, adapter kind, and capability flags configurable.
- Model discovery is best-effort, server-side, redacted, and has manual model-name fallback.
- Default tests do not run real providers or consume quota; real-provider tests require explicit opt-in.

## Galgame Intake Boundary

- v0.9 accepts only user-provided already-unpacked local sources.
- It does not implement cracking, unpacking, decryption, DRM bypass, scraping, or automated source acquisition.
- Source visibility remains admin-scoped unless later published through safe reader/player delivery.

## Persona And Memory Distillation

- Distillation reads reviewed source/dialogue evidence and produces reviewable proposals.
- Provider-backed calls use `ProviderExecutionService`, invocation ledger records, and prompt snapshots.
- Persona and memory writes happen only after explicit review/apply and preserve source traceability.
- Provider output does not directly mutate canon, memory, visual bindings, voice bindings, or world state.

## Visual Generation Safety Model

- Runtime agents cannot execute arbitrary raw ComfyUI workflow JSON.
- Image generation is planned through registered workflow templates, versioned template payloads, validated slots, visual model inventory, character visual profiles, provider capabilities, and provider-neutral generation plans.
- AI may propose profile, binding, prompt preset, or workflow variant changes only as reviewable proposals.
- ComfyUI remains optional; Z-Image, GPT/OpenAI-compatible image, and generic providers remain supported through provider-neutral mapping.

## Guardrails Preserved

- API keys and resolved secrets remain behind `auth_ref`/server-side secret resolution.
- Reader/player/member APIs do not expose storage URIs, filesystem paths, object paths, local model paths, bytes, base64, raw prompts, raw outputs, prompt snapshot internals, raw workflow JSON, or resolved secrets.
- `world_events.payload` is not used for storage paths, raw provider data, or secret-bearing payloads.
- Import, persona/memory migration, visual mapping, voice mapping, visual profile changes, and demo assembly use preview/review/apply boundaries.
- No real provider tests run by default.
- No Web UI was added after Phase 1; Phase 1 Web work used `impeccable`.
- v0.9 does not imply private beta, public launch, or normal-use release-candidate readiness.
