# v1.1 Normal Use / Release Candidate Release Notes

## Summary

v1.1 hardens Noveland after private beta for normal-use and release-candidate evaluation. It adds operational runbooks, a fresh local backup/restore drill, deterministic multi-world stress evidence, content safety and moderation hardening, safer import/export manifests, provider reliability controls, focused Web polish, and an admin-only release-candidate gate.

## Released Scope

- Phase 1 Operational Runbooks: normal-use runbooks for provider outage, quota exhaustion, stuck media jobs, migration failure, backup/restore, rollback, worldline restore, secret rotation, private beta invite/session/feedback incidents, import/export recovery, and provider fallback/degraded mode.
- Phase 2 Real Backup/Restore Drill: read-only fresh local/single-host restore verifier over database state, media objects, checksums, snapshots, provider config metadata without secrets, and OpenSpec/docs provenance, exposed through platform-admin observability readiness.
- Phase 3 Multi-world / Multi-user Stress Test: deterministic fake-provider stress reporting for 3 worlds, 2 worldlines per world, 2 player sessions per world, 2 fake providers, and 120-turn-equivalent normal-use coverage.
- Phase 4 Content Safety & Moderation Hardening: admin-only safety review reports, beta-feedback-to-moderation escalation, reporter privacy preservation, safe evidence refs, and existing takedown visibility enforcement.
- Phase 5 Import/Export Stability: extended world packaging manifests for provider, persona, memory, visual, voice, and source traceability metadata, public-sample exclusion for user-provided galgame assets, repeatable import preview warnings, and explicit apply discipline.
- Phase 6 Provider Reliability Layer: provider health trends, degraded-mode reports, manual-first fallback planning, explicit fallback execution metadata, and audited provider media-job requeue without hidden fallback or hidden spend.
- Phase 7 User-facing Polish: focused improvements to existing onboarding, feedback, player resume, playback/scene fallbacks, provider status, responsive behavior, focus states, and safe failure/degraded copy.
- Phase 8 Release Candidate Gate: platform-admin `release_candidate_gate` readiness report under observability/readiness that aggregates private beta, backup/restore, stress, moderation, packaging, provider reliability, UX/manual checklist, and no-leak evidence while keeping public launch separate.

## Safety And Security Boundaries

- Release-candidate readiness does not imply public launch or unauthenticated access.
- Readiness reports remain admin-only.
- No resolved secrets, provider credentials, auth refs, storage URIs, filesystem paths, object storage paths, local model paths, raw prompts, raw outputs, prompt snapshot internals, invite tokens, bytes, or base64 are exposed in reader/player/member surfaces.
- Default tests and stress runs use fake/mocked providers and do not consume real provider quota.
- Provider fallback is manual-first and opt-in only, with capability, quota, auth, and audit checks.
- Provider output does not directly mutate world state.
- Import/export and content repair preserve preview/review/apply discipline.
- Proprietary or user-provided galgame assets are not committed to repository fixtures or public sample exports.
- v1.1 did not duplicate observability/readiness, provider, media, packaging, moderation, or authoring frameworks.
