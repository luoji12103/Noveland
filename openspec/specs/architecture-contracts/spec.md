# Architecture Contracts Specification

## Purpose

This spec captures stable cross-cutting contracts that current Noveland code must preserve: worldline isolation, service ownership, secret handling, invocation auditability, media storage boundaries, event payload safety, and API exposure rules.

## Requirements

### Requirement: Worldline-scoped state validates world and worldline identity
The system SHALL treat `world_id` and `worldline_id` as first-class identifiers for worldline-scoped records and SHALL reject links that cross worlds or worldlines.

#### Scenario: Cross-worldline link rejection
- **GIVEN** a media asset, visual binding, conversation presentation, speech transcript, media job, asset generation record, or invocation belongs to one worldline
- **WHEN** another worldline-scoped record attempts to reference it from a different worldline
- **THEN** the service SHALL reject the operation.

### Requirement: Product modules use owning services instead of direct adapters
The system SHALL keep provider adapters, storage operations, memory backends, image composition, speech operations, and visual resolution behind their owning package services.

#### Scenario: Provider boundary
- **GIVEN** an image, speech, conversation presentation, or asset generation flow needs provider behavior
- **WHEN** it executes
- **THEN** it SHALL route through provider, image, speech, media, or visual services as appropriate
- **AND** it SHALL not call OpenAI, ComfyUI, MiMo, OmniVoice, GPT-SoVITS, or custom HTTP adapters directly from world, conversation, agent, or narrative modules.

### Requirement: Secrets are opaque references
The system SHALL treat provider `auth_ref` values as opaque references and SHALL resolve actual secrets only in memory at execution time.

#### Scenario: Admin reads provider config
- **GIVEN** a provider integration has `auth_ref` set to an environment reference
- **WHEN** an admin reads the provider through the API
- **THEN** the API MAY return the reference string
- **AND** it SHALL NOT return the resolved secret value.

### Requirement: World event payloads exclude sensitive and binary data
The system SHALL NOT write storage URIs, filesystem paths, bytes, base64, raw prompts, raw provider outputs, provider secrets, or authorization headers into `world_events.payload`.

#### Scenario: Event payload audit
- **GIVEN** world events are generated by conversation, media, provider, speech, visual, asset generation, or eval flows
- **WHEN** diagnostics scan event payloads
- **THEN** no forbidden storage, binary, prompt, output, or secret fields SHALL be present.

### Requirement: Reader and member APIs hide admin evidence
The system SHALL keep prompt snapshots, raw prompts, raw outputs, resolved provider secrets, hidden/developer-only records, storage URIs, filesystem paths, bytes, base64, provider health metadata, and admin diagnostics out of reader/member API responses.

#### Scenario: Non-admin reads world content
- **GIVEN** a non-admin has access to reader or member routes
- **WHEN** they request world content
- **THEN** the response SHALL omit admin evidence and internal storage/provider details.

### Requirement: Architecture decisions are documented
The system SHALL maintain ADRs for accepted architecture boundaries, including worldline-first multimodal state, provider secret references, invocation ledger audit source, media assets versus narrative artifacts, optional ComfyUI, strict visual bindings, API-only turn presentation, admin-apply asset generation, and eval framework reuse.

#### Scenario: ADR lookup
- **GIVEN** a developer questions an architecture boundary
- **WHEN** they inspect `docs/agent/architecture/adr`
- **THEN** they SHALL find an accepted ADR explaining the current decision, consequences, non-goals, and related files/tests.

## Non-goals

- This spec does not define encrypted DB secret storage or a vault.
- This spec does not define cross-worldline inheritance.
- This spec does not authorize public reader media delivery.
- This spec does not allow bypassing package owners for convenience.
