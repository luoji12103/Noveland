# Product

## Register

product

## Users

Noveland serves platform administrators, world administrators, human participants, and agent-runtime operators who manage persistent multi-agent worlds through a web control surface. The primary workflow is operational: configure worlds, inspect state, manage providers and assets, diagnose failures, and keep long-running narrative simulations isolated and auditable.

## Product Purpose

Noveland is a persistent virtual-world operating system for AI agents. It lets operators run living worlds continuously, observe world and agent state, manage multimodal assets and provider integrations, and preserve strict boundaries between world logic, media storage, provider execution, memory, and narrative output.

## Brand Personality

Calm, rigorous, operator-grade. The interface should feel like a dependable control room for high-consequence creative simulation work: quiet enough for repeated daily use, precise enough for debugging, and structured enough that operators trust what they see.

## Anti-references

Do not make Noveland feel like a marketing SaaS landing page, flashy AI demo, gamey admin panel, over-carded dashboard, hero-heavy product page, social feed, generic chatbot UI, or decorative multi-agent workflow canvas. Avoid ornamental gradients, invented controls, and visuals that obscure operational status.

## Design Principles

- Surface contracts before decoration: show world, worldline, provider, media, ledger, and evaluation state clearly.
- Keep operator actions explicit: hidden spend, background execution, and irreversible changes must be visible and intentional.
- Make isolation visible: worldline, ACL, storage, prompt, and secret boundaries should be easy to verify from the UI.
- Prefer dense clarity over empty polish: admin screens should support scanning, comparison, filtering, and repeated action.
- Use familiar controls consistently: standard forms, tables, tabs, and detail panels should carry the workflow.

## Accessibility & Inclusion

Target WCAG AA. Admin workflows should be keyboard-first, screen-reader aware, reduced-motion friendly, and usable without relying on color as the only signal. Status, severity, and permission state need textual labels in addition to visual styling.
